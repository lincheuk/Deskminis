# DeskMinis

Windows 桌面端的通用 Agent 应用。让模型在你自己的机器上读写文件、执行命令、完成任务——
会话、记忆、工作区都存在本机；多台设备之间的会话同步走局域网直连，**不经任何云端**。

用 Electron + TypeScript 实现，产品理念参考 [OpenMinis](https://github.com/openminis/openminis)
（只研读了它的架构，没有用它的代码）。少量实现改编自 [pi-mono](https://github.com/badlogic/pi-mono)（MIT）
与 [ZCode](https://github.com/zai-org/ZCode)（Apache-2.0）；界面令牌的槽位结构承自 Appica UI（MIT），
取值来自 [AionUi](https://github.com/iOfficeAI/AionUi)（Apache-2.0）。逐项登记在 [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md)。

| 持久记忆 + 上下文压缩 | ✅ Markdown 记忆库（按会话开关）、自动压缩与大结果卸载；单指令长任务也能压缩，陈旧的大工具结果自动修剪。0.3.0 的压缩是止血版：接着上一份摘要只压新增的部分，摘要为空或被截断就拒收，压缩失败会在对话流里提示、回合照常继续，不再静默。摘要按固定小节输出并在写入前校验（格式不对、与会话记录对不上的不写入），另附一段由程序根据会话记录生成的记录（用户指示原话、工具成功写入的文件、有副作用的调用结果）——摘要里没有工具记录佐证的「改了某文件」「测试通过」不会进入后续请求；被摘要盖住的最近用户消息按原话带上。摘要协议在真实模型上的遵从率还没有实测 |

### 权限网关怎么判

- **四档**：「每次确认」与「本会话沿用」在后端判定相同，差别只在权限卡默认高亮「允许」还是「本会话允许」；
  「本会话允许」只记原样重复的同一条命令、同一个文件路径、同一个网址或搜索词，MCP 按服务器记。
  「完全访问」不再询问任何操作，但危险命令与文件工具写核心数据照样拦下。
  「只读 / 计划」保留文件读取与只读命令（敏感路径写法照旧询问），联网搜索和抓网页仍会询问；文件与记忆写入、会改东西的命令、MCP 及通知 / 打开 / 朗读 / 写剪贴板直接拒绝、不弹卡。
  输入卡权限胶囊和设置页都能切换四档；从输入卡开启完全访问需行内确认。
- **危险命令**（Remove-Item / del、format C:、reg delete、shutdown、taskkill 这类）任何档位都直接拒绝，不弹卡。
  规则只按命令写法认：经 `cmd /c` 转一手，或 Format-Volume、Clear-Disk、`[IO.File]::Delete` 这类不在规则表里的破坏性写法，
  前两档照常弹卡，完全访问下直接执行。
- **shell 命令**：免询问的只剩只读的本地命令——dir、Get-Content、rg、`git log` 这类，含 `git log | select-object -first 20`
  这类受限只读管道。只读命令一旦点到远程共享路径（`\\主机\共享`、`//主机/共享`）、读 `env:` 或 `$env:` 环境变量、
  点到 DeskMinis 的数据目录（命令里写着 DeskMinis、`%APPDATA%`、`%LOCALAPPDATA%`），或含上级目录段 `..`、`$HOME` / `~\` / `%USERPROFILE%` / `AppData`、8.3 短名、目录段通配，或带着 `-ComputerName` 这类远程参数，
  就改按普通命令过卡。判断只看命令写法，认不出的写法列在 [CHANGELOG.md](CHANGELOG.md) 的「已知边界」。
- **联网**：`web_fetch` / `web_search` 单列一档，前两档下每次确认，完全访问下不问。shell 里会联网或访问别的机器的命令——
  `Invoke-WebRequest`、`curl`、`git clone`、`npm view` / `npm outdated`、点到远程共享路径的命令、带 `-ComputerName` 的查询——
  不单列，按普通命令过卡：前两档弹卡，完全访问下不问。
- **文件工具**（`file_*`、`office_*`）：工作区内（含绑定的项目目录）的文件在其它三档直接放行；只读 / 计划档只放行读取。DeskMinis 自己的数据目录另有一道闸，
  数据目录里的路径都按它判（工作区绑在数据目录里或它的上级目录时也一样）：当前会话自己的几个目录（`sessions\<id>\` 下的
  workspace / attachments / offloads / browser）与各会话共用的 `shared` 在其它三档读写都直接放行，只读 / 计划档只放行读取，技能与记忆文件读取直接放行；会话库、
  模型与搜索服务配置、配对记录、本机连接凭据这些核心数据，文件工具写不了（完全访问也不行）。除此之外的读写前两档下要过权限卡，
  写文件审批带 diff 预览，完全访问下不问；数据目录里要过卡的（改 MCP 配置、技能与记忆文件，读会话库，碰别的会话这类），卡上写明动的是什么。
- **shell 命令与 MCP 工具不走数据目录这道闸**，照常按档位过卡：完全访问下 agent 用 shell 改写上面这些核心数据也不会被拦、不会被问；
  只读命令的上述路径写法回落询问，末段通配（如 `dir *.ts`）照旧免询问；shell 超时限 1–3600 秒，默认 120 秒，调整参数时在结果开头说明。

每个版本改了什么见 [CHANGELOG.md](CHANGELOG.md)。

## 安装

到 [Releases](https://github.com/lincheuk/deskminis-releases/releases) 下载（这个公开仓库只放发布资产，源码仓目前不公开）：

- `DeskMinis-<版本>-Setup.exe` — 安装版（推荐）。启动后到上面这个发布仓库查一次新版，有就在后台下载，
  下载完提示你重启安装；不想自动检查就到 **设置 → 关于** 关掉。
- `DeskMinis-<版本>-win-x64-portable.exe` — 便携版，免安装，**不自动更新**，新版请回发布页下载。
  数据和安装版一样存在 `%APPDATA%\DeskMinis`：两者共用一份数据，不能同时运行。

**从 0.1.1 升级**：0.1.1 里写死的更新源是私有的源码仓，永远查不到新版——需要手动下载安装一次 0.3.0，之后才能自动更新。

安装包未做代码签名，Windows SmartScreen 会提示「未知发布者」，选择「更多信息 → 仍要运行」。
Windows 11 若开着「智能应用控制」，未签名的安装包会被直接拦下，没有「仍要运行」这一项。
安装时提示「DeskMinis 无法关闭」，而它其实并没有在运行：多半是安全软件拦下了安装包里的文件——先临时放行安装包，再点「重试」。

首次启动后到 **设置 → 模型** 添加一个 provider（起个名称、选类型，填 base URL / 模型 ID / API Key）即可开始。

OpenCode Go 端点按其文档自动带会话头。

对外请求跟随 Windows 系统代理（含自动配置与绕过列表），无需另设应用代理；本机与局域网地址、本地模型及配对同步直连。地区限制的 403 提示会引导检查系统代理。

### 模型元数据

模型规格以 [models.dev](https://models.dev/) 为主来源，使用公开的 `https://models.dev/api.json?type=all`，无需目录 API Key。
启动时读取磁盘缓存并按 24 小时有效期更新；**设置 → 模型 → 刷新元数据** 可立即重拉。
添加或编辑模型时显示的是**运行时实际采用**的规格：按「这个配置 + 它的接口地址 + 模型 ID」解析。官方端点与目录收录的服务商（按 base URL 匹配目录里的接口地址）用该服务商自己的条目；中转、本机端点与未收录的服务商按模型汇总，汇总只能说明「未确认」或「至少 3 家服务商一致标注不支持」，不会因为型号名相同就套用官方服务商的能力。
每项能力是目录声明、当前端点是否确认、DeskMinis 是否已实现三者的交集：模型能理解音视频、PDF，或能生成图片 / 音视频时，界面写明「模型支持，当前接入不可用」及原因；未确认的能力不显示为可用。
每个配置可以单独手动修正上下文窗口、最大输出、图片输入、工具调用与推理（**设置 → 模型 → 编辑 → 手动修正**），只作用于这个配置，清空即回到目录值；手动修正打不开应用尚未接入的传输。
发消息与模型组降级时，每个模型按自己的规格重新决定输出上限与推理参数（备用模型不沿用主模型的参数）；本条消息带图片而模型不收图片时不发送并说明原因，组内有收图片的成员则这一轮改用它；历史图片、工具记录在不支持的模型上改以文字发送，事件条会提示。非手动的输出上限不超过窗口的 3/4，目录值不可信时改用佐证值或 8192；手动把窗口填小、目录的输出上限因此放不下时，按手动窗口的 3/4 计（手动填的最大输出照填写的值）。推理参数只在当前端点确认支持或手动标为支持时发送。
目录不可用时保留最后成功缓存；首次无缓存时回退备用目录及内置数值。官方 Anthropic 端点上 200K 以上的窗口按 200K 计（未发送长上下文 beta 头），确认可用时可在该配置手动填写。

### 请求预算、用量与费用

每次请求发出前，DeskMinis 按**实际将发送的内容**估算输入：系统提示、工具定义、对话、回放的推理、图片分别计入（图片按尺寸换算，不按文件大小）。这些是估算值，不调用服务商的计数接口；收到服务商报告的真实用量后会校准下一次估算，任务面板写明是否已校准与上次的偏差。

- **单次输出额度**：`max_tokens` 取「偏好、模型输出上限、上下文剩余空间」三者的最小值。没有手动填最大输出时，默认每次申请 65,536（带推理预算时另加预算）；需要更长的单次输出可在该配置手动填写最大输出。输入已占掉大半窗口时会收紧（带推理预算时，预算不占满收紧后的额度，给正文与工具调用留出最小输出），被截断时任务面板会说明那次的 `max_tokens` 与原因；输出额度在正文之前就用完（多为推理占用）时不当作空响应处理：那次的额度是模型自己的输出上限或手动填写的最大输出、且模型组里还有接得住这一轮的成员时，本轮改用它并在对话里说明（不算故障，会话不因此改绑，下一条消息仍先给原来的模型；要先压缩对话才放得下的成员、修剪旧的工具结果之后仍放不下这段对话的成员不算。换用的那一刻不为它压缩；换过去之后对话继续增长，或接手的成员自己回了空响应、再降到后面的成员时，仍按当时接手成员的窗口压缩，会话同样不改绑）；其余情况（额度是按默认额度或任务指定的额度申请的、被上下文剩余空间收紧的，或没有可换的成员）照实报「输出被 max_tokens 截断」并给出出路。换过去的成员也没有接住这一轮时（故障、空响应、端点以上下文超窗拒绝、它自己也把输出用完），报的仍是最先被换下的那个模型的这条说明，后面附上最后的错误，不给「新建会话接力」。出路按那次请求实际的情况写——请求里真带了可调的推理参数才建议调低推理档位（思考由服务端自适应的 Claude 型号，档位进不了请求，不提），输出上限是目录没有记录时的兜底值就指向手动填写最大输出或换用模型，是按手动填写的上下文窗口的 3/4 封顶出来的就指向手动填写最大输出或调大手动窗口，服务商报了用量的附上报告的输出数。
- **共享窗口与独立上限**：输入与输出共用一个窗口的接入（Anthropic、多数 OpenAI 兼容端点），输出随输入收紧；目录另给了输入上限、且与输出上限互不占用的型号（如 gpt-5），以及 Gemini，输入与输出各按各的上限。
- **提前减压**：上下文水位与输出余量按上面的完整估算判断，系统提示与工具定义很大时会更早修剪旧的工具结果、必要时压缩。修剪是本地操作，每一轮都可以做；付费的压缩每次运行最多 3 次，因余量不足而压缩时还要这一次真能摘走足够多的内容才发。系统提示与工具定义自己就放不下模型的输入上限时，不发送请求并说明原因（压缩与新建会话解决不了，需要停用部分 MCP 服务器 / 技能、精简助手规则与记忆，或换用窗口更大的模型）；这种拒发只在上限是手动填写的或当前端点自己的目录记录时发生。
- **超窗后的同模型恢复**：估算再细也可能被端点拒绝（窗口资料偏高或没有、估算偏低）。端点以「上下文超出」拒绝时，先在当前模型上恢复，不直接换模型：记下端点拒绝给出的上限（报文带数字就按它换算，没有就按被拒输入下调 25%；只在本次运行里生效，不写回目录与配置，也不据此在本地拒发）→ 输出申请得很大时先把输出上限调到 16,384 → 修剪较早的大工具结果 → 压缩较早的对话 → 把最近仍然很大的工具结果裁成头尾 → 只保留最近 4 条消息的压缩；每一步之后重算预算，放得下才重发。全程不追加消息、不执行任何工具，已经执行过的工具不会重跑。熔断：同一次超窗最多重发 2 次，一次运行最多处理 6 次拒绝、发 5 个摘要请求（累计花费约 40 万 token 封顶）、成功压缩 3 次；能做的都做了仍放不下就不再重发，改换窗口更大的模型，或报「上下文已满」并给接力草稿。被拒绝过的模型在之后的轮次里按学到的上限提前裁剪，不再每轮先被拒一次。故障降级到窗口小得多的备用时，同样先按它的窗口减压再发。事件条与任务面板的「上下文恢复」卡写明被拒的那次请求、做了哪几步、重发的那次请求与结果。这几个上限数字没有对着真实端点调过。
- **用量**：任务面板的「上次请求」显示总输入、总输出，以及其中的缓存读取、缓存写入、推理（都是总数的一部分，不重复相加）。服务商没有报告的项写「服务商未报告」，不显示为 0。
- **费用**：只在当前端点自己的目录记录有价格、且计费规则确定时按 token 估算，并标明是估算。中转与本机端点、目录标价为 0（多为订阅或套餐计费）、按上下文长度分档计价、用量不完整等情况一律显示「费用未知」及原因，不显示 0 元。压缩摘要、自动命名与失败重试的请求不计入。

## 从源码构建

源码仓目前不公开，下面写给有源码的开发者：

Windows x64 上已完成锁文件安装与发布构建的组合是 **Node.js 24.19.0 + npm 10.9.4**；其它版本尚未完成同等验收。
Electron 自带的 Node 用于应用和原生测试，不能代替安装依赖所需的 Node/npm。原生模块需要从源码重建时，准备好
Python 3、Visual Studio 2022 / Build Tools 的「使用 C++ 的桌面开发」工作负载及 Windows SDK；`npm ci` 的
`postinstall` 会为 Electron 重建 `better-sqlite3`。完整准备与构建流程见 [发布检查单第 1 节](docs/RELEASE.md#1-构建)。
请在独立检出中按锁文件安装；`npm ci` 会先清空 `node_modules`，失败后依赖可能不完整，需成功完成安装后再构建或测试。

```bash
cd deskminis && npm ci
npm run dev              # 开发模式（自动起 minisd 与渲染进程）
npm test                 # Windows 上应全绿；Linux 上 PowerShell、终端、桥这类 Windows 专属用例会失败
npm run typecheck
npm run dist             # 出安装包到 deskminis/dist/
npm run verify:release   # 核对 dist/ 里要上传的四件（latest.yml、安装包、blockmap、便携版）与随包文件
```

发布一个新版本的完整流程（构建 → 验收 → 冒烟 → 上传 Release）见源码仓的 `docs/RELEASE.md`。
单独的 `e2e:*` 验收入口、数据与凭据前提、真实模型要求见 [脚本说明](deskminis/scripts/README.md)。

**测试分档**：默认 `npm test` 跳过两条写入真实剪贴板的用例；Windows 验收入口 `verify:windows` 显式启用。
设置 `DESKMINIS_F09_FULL=1` 可运行完整进程档；修改进程生命周期相关代码或发布验收前必须跑。
运行方法、环境要求和已知受负载影响的用例清单见 [测试说明](docs/TESTING.md)。

**开发态数据与正式版分开**：未打包运行（`npm run dev`）时，数据在 `%APPDATA%\DeskMinis-dev`，凭据在 Windows
凭据管理器的服务名 `DeskMinis-dev` 下，日志在 `%LOCALAPPDATA%\DeskMinis-dev\logs`，不碰装好的正式版。dev 首次启动是空库；
想把正式版的数据带进 dev：

1. 从托盘退出所有 DeskMinis，也停掉 `npm run dev`。
2. 把 `%APPDATA%\DeskMinis` 整个复制为 `%APPDATA%\DeskMinis-dev`（`minis.db` 连同 `-wal`、`-shm` 一起；原目录留给正式版，别移动）。
3. 在 dev 的设置里重填模型与搜索的 API key——key 存在凭据管理器里，复制目录带不过去。
4. dev 会生成新的配对身份，算另一台设备；要同步的设备在「设备」里重新配对。
5. 主题等界面偏好 dev 首次回到默认，重选一次即可。

如果正式版启动时提示「这份数据来自更新版本的 DeskMinis」，说明以前共用目录时 dev 已经把库升级了：把这个目录改名给 dev 用
（`DeskMinis-dev`），正式版装上最新版本再开。临时换一个数据目录：设 `DESKMINIS_DATA_DIR=<目录>`（日志随之写在 `<目录>\logs`）。

**不同开发分支也要隔离数据**：默认目录只按是否打包区分，不按仓库位置或 Git 分支区分。多个 `npm run dev` 检出默认共用
`%APPDATA%\DeskMinis-dev`；新分支追加迁移并启动后，迁移较少的旧分支会拒绝打开这份库。切分支前退出对应应用，
每个分支在自己的 PowerShell 窗口设不同目录，例如：

```powershell
$env:DESKMINIS_DATA_DIR = Join-Path $env:APPDATA 'DeskMinis-dev-data\quality-20261007'
npm run dev
```

这个变量隔离会话库、开发态 Electron 缓存与日志；未打包应用的凭据服务名仍是 `DeskMinis-dev`，不会随目录分开。
关闭这个 PowerShell 窗口后变量不再沿用；同一窗口要恢复默认目录，可运行 `Remove-Item Env:\DESKMINIS_DATA_DIR`。

## 数据存在哪

安装版与便携版都在 `%APPDATA%\DeskMinis`：

```
minis.db              会话、消息、压缩摘要、助手、定时任务、注释、审计、设置等（SQLite）
sessions\<id>\        每会话的沙箱：workspace / attachments / offloads / browser
memory\               持久记忆（纯 Markdown，可直接编辑）
skills\               已安装技能
mcp-servers\          MCP 服务器配置（servers.json；其中的 env / headers 是明文，可能含密钥）
shared\               各会话共用的目录
其余几个 .json         模型与搜索服务配置（不含密钥）、模型目录缓存、本机引擎的端口与连接令牌（明文）、配对记录
minisd.lock           数据目录锁（运行时存在）
```

Electron 自己的缓存与界面偏好（包括自动更新开关 `update-prefs.json`）也在这个目录里。
模型与搜索服务的 API key、本机的设备身份与配对密钥不在这个目录里，存在 Windows 凭据管理器（服务名 `DeskMinis`）。
**但这个目录里仍有明文的敏感内容**：MCP 服务器的 env / headers（包括在扩展市场确认卡里填的密钥）原样写在
`mcp-servers\servers.json`；本机引擎的连接令牌（每次启动换新）写在 `minisd-port.json`；会话库与各会话目录里是全部对话内容
（含 agent 读到的文件内容与命令输出）。把这个目录打包发给别人、放进网盘或同步盘、做备份之前，先想到这些。
日志与崩溃记录在 `%LOCALAPPDATA%\DeskMinis\logs`（按天日志 `minisd-<日期>.log` 保留 7 天；崩溃记录 `crashes.json` 只留 7 天内最近的 5 条）。

删除会话会清掉它在库里的记录，但不删磁盘上的 `sessions\<id>\` 目录。库里会留一条不含内容的删除记录（会话 id、版本号、发起删除的设备、当时的消息 id 清单；清单 90 天后压掉），用来把这次删除同步给已配对的设备，并挡住之后带着旧副本回来的设备。
卸载不会删除上面这些，也不删 `%LOCALAPPDATA%\deskminis-updater`（安装程序留的自身副本，以及自动更新下载的安装包）。
想彻底清干净：删掉 `%APPDATA%\DeskMinis`、`%LOCALAPPDATA%\DeskMinis` 与 `%LOCALAPPDATA%\deskminis-updater`，
再到 Windows 凭据管理器里删掉名字带 `DeskMinis` 的条目。

## 关于联网

除了你自己配置的模型服务，DeskMinis 会在这些时候出网：

| 什么时候 | 连哪里 | 怎么关 |
|---|---|---|
| 启动时（模型目录缓存超过 24 小时才拉） | models.dev（失败时回退 basellm.github.io），取各模型的上下文窗口与输出上限 | 没有开关 |
| 安装版启动 8 秒后检查更新；有新版就在后台下载 | GitHub 上的公开发布仓库 `lincheuk/deskminis-releases` | **设置 → 关于** 关掉自动检查；便携版从不检查 |
| 你打开「扩展市场」、搜索、安装或检查更新时 | clawhub.ai、registry.modelcontextprotocol.io、awesome-dsh-plugin.com；装 awesome-dsh 的条目时经 api.github.com 列出仓库目录，再从 raw.githubusercontent.com 下载文件 | 不打开市场就不连 |
| agent 调用 `web_fetch` / `web_search` 时 | 目标网址；搜索走你在 **设置 → 网络搜索** 配的服务（Tavily、Brave 或自建的 SearXNG） | 单列一档：前两档下每次过权限卡，拒绝就不连；完全访问下不问 |
| agent 跑会联网或访问别的机器的 shell 命令时（`Invoke-WebRequest`、`curl`、`git clone`、`npm view` / `npm outdated`、点到远程共享路径的命令、带 `-ComputerName` 的查询） | 命令里写的网址或主机（`npm view` / `npm outdated` 连配置里的 npm 源） | 不单列，按普通命令过卡：前两档弹卡，拒绝就不跑；完全访问下不问。免询问的只剩只读的本地命令（按命令写法判断，认不出的写法见 CHANGELOG「已知边界」） |
| 你配置的 MCP 服务器 | 取决于服务器本身（streamable-http 的直接连它的地址） | **设置 → MCP** 里停用 |
| 设备同步 | 只在局域网里直连已配对的设备，不经任何服务器；连接加密，但配对那一步不加密，请在可信的局域网里配对；设备页可打开实验性的认证配对（未经独立密码学审查，默认关闭），打开后配对码不经过网络 | 设备页暂停同步；不设 `MINISD_HOST` 时引擎只监听本机 |

## 架构

```
渲染进程 (Vue 3)  ──WebSocket JSON-RPC + per-run token──▶  minisd (utilityProcess)
      │                                                        │
      └─ preload 白名单 IPC ─▶ 主进程 (窗口/托盘/对话框/更新)     ├─ Agent 循环 + Provider
                                                               ├─ 工具 + 权限网关
                                                               ├─ SQLite（迁移追加式）
                                                               └─ 同步引擎（手填 host:port 配对 + 直连）
```

后端逻辑全在独立的 `minisd` 进程里，渲染层只通过 JSON-RPC 说话——
这让后端可被 CLI、e2e 脚本、将来的手机端复用。

设计与实施记录在源码仓的 `docs/`：`specs/` 是设计定稿，`plans/` 是逐里程碑的 TDD 计划，
