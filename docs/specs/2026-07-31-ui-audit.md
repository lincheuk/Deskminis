## 硬差距置顶（5 条）

### H1. 桌面端无 Markdown 渲染 —— 最严重的内容层缺陷
- **现状**：助手文本与流式文本均走纯文本插值 + `white-space: pre-wrap`，`**粗体**`、`` `代码` ``、`## 标题`、列表、代码围栏全部原样露出符号。截图 30/32：连**用户消息**里的 `**粗体**` 星号都直接铺出。
- **锚点**：[ChatView.vue](file:///c:/Users/24739/Downloads/openminis1/deskminis/src/renderer/src/components/ChatView.vue#L136)（`:136` 历史文本 `{{ p.value }}`、`:155` 流式 `{{ chat.streamingText }}`、`:231` `.atext { white-space: pre-wrap }`）
- **对照 OpenMinis**：`MarkdownRenderView` + `SelectableMarkdownView`（AST + append-only fast path 热更新）是全量 GFM 渲染，且 `TextFadeAnimator` 给流式文本做逐词 alpha 淡入（0.45s/词、0.10s 交错窗、easeOutCubic）。手机端两年前就解决的题，桌面端是零。
- **对照 Codex**：标题/列表/代码块/行内码全渲染，代码块带语言标签与复制键，mono 字体只落在代码与路径上——克制但完整。
- **差距定性**：同一产品的两端，助手产出物的可读性不在同一个时代。

### H2. 权限卡 30s 硬超时，且 UI 无任何倒计时提示
- **现状**：`askTimeoutMs = 30000`，超时按 **deny** 处理。权限卡组件没有任何倒计时、沙漏或「即将过期」提示——用户读一条长命令、起身倒杯水，回来发现操作已被静默拒绝，agent 回合就此打断。
- **锚点**：[permissions.ts](file:///c:/Users/24739/Downloads/openminis1/deskminis/src/minisd/tools/permissions.ts#L65)（`:65` 超时常量、`:80` 超时→deny）；[PermissionCard.vue](file:///c:/Users/24739/Downloads/openminis1/deskminis/src/renderer/src/components/PermissionCard.vue)（无超时呈现）
- **对照 WorkBuddy**：审批类交互常驻且语义亲和（「等待你的确认」），不存在静默过期打断任务流的设计。
- **对照 Codex**：批准提示无硬超时，用户决策权完整；危险操作靠分级文案而非倒计时施压。
- **差距定性**：对慢操作偏紧 + 过期不可见，双重反模式。30s 对「读命令做判断」的人类节奏是敌意的。

### H3. 桥命令双层弹卡：shell 卡 + 桥卡，一个动作两次打断
- **现状**：M2e 桥命令经 shell 工具发起时，shell 分类器先弹一张权限卡；命令经命名管道触达桥实现后，桥七类（`bridge-notify` / `bridge-clipboard-*` / `bridge-open` / `bridge-speak` / `bridge-screenshot`）各自 `askOnce` 再弹一张卡。用户视角：同一个「帮我截个屏」要批两次，且两张卡文案/类目不连续。
- **锚点**：[permissions.ts](file:///c:/Users/24739/Downloads/openminis1/deskminis/src/minisd/tools/permissions.ts#L41-L54)（`:41` 注释自证「后九类 kind 即类目，绝不经 shell 分类器」——但命令入口仍是 shell 工具，第一卡逃不掉）；[PermissionCard.vue](file:///c:/Users/24739/Downloads/openminis1/deskminis/src/renderer/src/components/PermissionCard.vue#L11-L19)（kind 文案映射仅 shell/file-write/file-read 三类，桥类目落到 default「请求权限」，语义丢失）
- **对照 WorkBuddy**：一次任务一次授权叙事，进度反馈连续，不打断心流。
- **对照 OpenMinis**：手机端权限是系统级一次性授权，对话内无重复打断先例。
- **差距定性**：安全模型正确（纵深防御），交互模型错误（成本转嫁给用户）。需要在 UI 层做「一卡告知两段授权」或入口归并。

### H4. 事件条 / 错误横幅视觉层级混乱，错误原文无治理
- **现状**：四类事件三种呈现位置——① retry 是助手块内一行橙色小字（`ChatView.vue:163`）；② fallback/compacted/offloaded 是对话流内联 `evnote` 小条（`:170-173`）；③ 致命错误是输入框上方红色 `errbar`（`:177-181`），且**错误原文（含 HTTP 状态、request id、JSON body）无截断、无格式化、无重试入口**直接铺满。截图 31/33：503 错误的 JSON dump 原文一行排开，普通用户完全读不懂，开发者也要横向滚动。
- **锚点**：[ChatView.vue](file:///c:/Users/24739/Downloads/openminis1/deskminis/src/renderer/src/components/ChatView.vue#L163-L181)（retry/evnote/errbar 三处）；TasksPanel 内 fallback/compacted/offloaded 又各有一张彩色状态卡（`:57-76`）——**同一事件，对话流一张条 + 任务面板一张卡，双份呈现**。
- **对照 Codex**：错误收敛为单行摘要 + 可展开详情，retry/fallback 是状态行而非内容。
- **对照 WorkBuddy**：状态反馈亲和（拟人化短句），技术细节折叠。
- **对照 OpenMinis**：`AssistantBlockView` 的 info 块有成熟先例：⚠️ 原因行 + ✅ 结果行分组，超 9 行中间截断（`⋯ N more`）。
- **差距定性**：层级（什么该多显眼）与治理（原文该不该直接铺）都缺设计。

### H5. 右栏三面板信息密度与组织失衡
- **现状**：300px 固定栏宽（App.vue:92-95）塞三个平等 tab：① 终端是完整 xterm，80 列在 300px 内折行严重（截图 20，提示符断成三行）；② 文件面板空态只有「工作区为空」一行小字（截图 21）；③ 任务面板三张卡（回合/Token/水位）字段稀疏、`—` 占位多、12-13px 小字大留白（截图 22）。gear 混在 tab 行里当第四个 tab 用（App.vue:70），语义是设置却共享 tab 视觉。
- **锚点**：[App.vue](file:///c:/Users/24739/Downloads/openminis1/deskminis/src/renderer/src/App.vue#L65-L78)；[TasksPanel.vue](file:///c:/Users/24739/Downloads/openminis1/deskminis/src/renderer/src/components/TasksPanel.vue)
- **对照 WorkBuddy**：右侧是「结果区」——按任务类型动态切换（参悟/全部文件/变更/预览），产物汇总有数量角标 + 文件类型图标 chips，多任务并行时左栏任务卡带 进行中/已完成/失败 状态徽标。我们的右栏是三个静态抽屉，与「任务」这个一等公民概念脱钩。
- **对照 Codex**：状态信息收敛为底部单行 status line（model/token/cwd），不抢横向空间。
- **差距定性**：有面板之形，无任务组织之神；300px 对终端过窄、对任务卡过宽。

## 一、信息架构（IA）

### IA-1. 「任务」不是一等公民，会话即一切
- 左栏只有会话列表（标题 + 时间），无运行状态、无产物数、无任务分组。WorkBuddy 左栏任务卡按工作空间分组且带 进行中/完成/失败 徽标——agent 产品的左栏本质是「任务管理器」，我们目前只是「聊天记录列表」。
- 锚点：[SessionList.vue](file:///c:/Users/24739/Downloads/openminis1/deskminis/src/renderer/src/components/SessionList.vue)

### IA-2. 设置入口寄生在右栏 tab 行
- 模型设置靠 tab 行末尾一个 gear 图标切换（App.vue:70），与终端/文件/任务三个内容 tab 共享同一视觉语义；ModelPicker 的「管理模型…」通过 provide/inject 撬开右栏（App.vue:49）。设置是应用级功能，不应是面板级 tab。
- 对照：Codex 设置是独立 modal/页面；WorkBuddy 设置在左栏底部固定入口。

### IA-3. 标题栏功能虚设，导航语义缺失
- 前进/后退按钮无任何 handler（TitleBar.vue:92-93，纯装饰）；菜单栏 文件/编辑/视图/帮助 中大量 `noop` 项（新建工作区/导入技能/文档/更新日志/诊断信息…）——展示了不存在的功能，稀释了真实功能的可信度。明暗切换只藏在「视图」菜单里，无直观入口。
- 锚点：[TitleBar.vue](file:///c:/Users/24739/Downloads/openminis1/deskminis/src/renderer/src/components/TitleBar.vue#L21-L53)

### IA-4. M3 后端能力在前端零呈现
- M3a 已落地配对码/X25519/PASETO/remote.* RPC，前端无配对管理、无设备列表、无同步状态任何入口。M3b/c 即将到来，IA 必须现在预留位置（设备与同步是一等导航项还是设置子页，需要决断）。
- 锚点：`src/minisd/remote/`（后端）；前端无任何对应组件。

### IA-5. 空状态无引导价值
- EmptyState 仅两行静态文案（截图 03：「开始新的对话 / 让 DeskMinis 帮你读写文件、执行命令、完成任务」），无示例指令、无快捷键提示、无最近任务恢复。
- 对照 WorkBuddy：首屏即任务模板入口（研究报告/官网生成/Skill 创建）。

## 二、视觉系统

### V-1. 字号体系是 iOS 直搬，桌面密度不足
- 正文 16.5px（ChatView :223/:230）、助手名 17px、会话标题 16px、新建按钮 15px——全套 iOS pt 映射。桌面端视距与像素密度下，对话流一屏信息量约为 Codex 的 60%。
- 对照 Codex：正文 13-14px、mono 12-12.5px，密度高但不挤——开发者产品的密度基线。
- 锚点：[ChatView.vue](file:///c:/Users/24739/Downloads/openminis1/deskminis/src/renderer/src/components/ChatView.vue#L215-L231)、[tokens.css](file:///c:/Users/24739/Downloads/openminis1/deskminis/src/renderer/src/styles/tokens.css)（令牌层**没有字号/间距尺度**，全写死在组件里——这本身是令牌体系的缺口）

### V-2. 双主色并存，视觉重心分散
- `--brand #B7AF96`（暖灰褐）管新建按钮/会话选中/头像底，`--accent #3686EE`（蓝）管链接/高亮，`--link #007AFF` 又是一种蓝。截图可见：新建按钮土褐色块是全窗口最跳的元素，而它只是个低频动作。
- 对照 OpenMinis：iOS 侧 accent 蓝是唯一主行动色，brand 暖色只做点缀。桌面端把 brand 提到了主按钮位，色权失衡。
- 锚点：[tokens.css](file:///c:/Users/24739/Downloads/openminis1/deskminis/src/renderer/src/styles/tokens.css#L35-L39)、[SessionList.vue](file:///c:/Users/24739/Downloads/openminis1/deskminis/src/renderer/src/components/SessionList.vue#L80-L84)

### V-3. 等宽字体使用无节制标准
- 目前 mono 仅出现在工具展开 pre（12px）、权限详情、键盘快捷键。对话流内代码符号与正文混排同字（因为根本没有 Markdown 渲染）。Codex 的标准是：mono 只给代码/路径/命令/数字读数，正文一律比例字体——我们缺内容层，这个标准无从谈起。

### V-4. 暗色三模式地基完好，但未经真实内容验证
- tokens.css 的 auto/light/dark 三件套（media query + 双 data-theme 覆盖）结构正确，`color-scheme` 也配了。但截图审计全在浅色；暗色下 evnote 的 color-mix 透明度、errbar 的 12% 红底、xterm 的 256 色主题都未验证。三模式是硬约束，需要进验收清单而非留在纸面。
- 锚点：[tokens.css](file:///c:/Users/24739/Downloads/openminis1/deskminis/src/renderer/src/styles/tokens.css#L73-L190)

### V-5. 低饱和度未达标：状态色过多过艳
- 工具类型色绿/青/蓝/橙/紫五色 + 状态色绿/红/黄 + 事件三色（橙/蓝/紫）+ brand + accent，同屏可能出现 8+ 种强调色。Codex 对话流常态只有灰阶 + 一种强调色，彩色只给状态（成功绿/失败红）。

## 三、交互质量

### X-1. 流式输出无渐进呈现，文本硬跳
- 流式文本整块 `{{ chat.streamingText }}` 替换，无逐词/逐段淡入。OpenMinis `TextFadeAnimator` 的逐词 alpha 调度（显示层专用、O(新词)、CADisplayLink 驱动）是已验证的参考答案。
- 锚点：[ChatView.vue](file:///c:/Users/24739/Downloads/openminis1/deskminis/src/renderer/src/components/ChatView.vue#L155)

### X-2. 滚动强贴底，用户失去阅读控制
- 任何新内容（textDelta/toolCard/retry/eventNote）都强制 `scrollTop = scrollHeight`（ChatView :79-82）。用户上翻读上文时来一条 delta 就被拽回底部。Codex 标准：用户上翻即解除跟随，回到底部（或点「回到底部」按钮）才恢复。
- 锚点：[ChatView.vue](file:///c:/Users/24739/Downloads/openminis1/deskminis/src/renderer/src/components/ChatView.vue#L79-L82)

### X-3. 消息零操作：无复制、无重生成、无编辑重发
- 用户气泡与助手块均无 hover 操作。复制只能靠原生选区（而 atext 还是 pre-wrap 纯文本）。Codex 每回合有 copy；WorkBuddy 产物一键导出。

### X-4. 工具结果呈现是裸 JSON，无 diff 视图
- ToolPill 展开区是 参数/输出 两段 `<pre>`（ToolPill :97-107），file_edit 的前后对比要用户在 JSON 里肉眼找。Codex 的 diff 式展示（红绿 +/- 行）是编辑类工具的标配；这也是用户钦定基准里明确要的「diff 式内容展示」。
- 锚点：[ToolPill.vue](file:///c:/Users/24739/Downloads/openminis1/deskminis/src/renderer/src/components/ToolPill.vue#L97-L107)

### X-5. 错误横幅无恢复路径
- errbar 只有 × 关闭，没有「重试」——而 retry/fallback 机制明明存在于 loop 层。用户看到 503 只能手动重发整段话。

### X-6. 输入区功能单薄
- textarea `rows=1` 无自适应长高（CSS 有 max-height 200px 但无 JS resize）；无附件能力（OpenMinis ChatInputBar 有完整 AttachmentGrid：64px 圆角缩略图、拖排、预览）；无语音/图片入口；`/` 斜杠菜单已有（M2c），但无 `@` 文件引用。
- 锚点：[ChatView.vue](file:///c:/Users/24739/Downloads/openminis1/deskminis/src/renderer/src/components/ChatView.vue#L195-L211)

### X-7. 权限卡决策信息不足
- 卡内只有命令/路径原文，无工作区相对位置、无风险分级文案（danger/gated 视觉无差异）、无超时倒计时（见 H2）。三按钮「仅此次/本会话允许/拒绝」齐全（好），但预选高亮逻辑（`:22-24` preselect）用 1px 边框表达，弱到几乎不可见。

## 审计结论（给任务二的输入）

1. **内容层是最大短板**：Markdown 渲染缺失（H1）让「全局皮肤 = OpenMinis」失去根基——手机端的核心体验资产必须移植，这是 MU1 之后第一个施工里程碑的头等项。
2. **三栏骨架可保留，腔内重做**：260 | 1fr | 300 的壳不用推翻，但左栏要长出「任务状态」、中栏要长出「回合结构与 Markdown」、右栏要从「三抽屉」进化为「任务结果区」。
3. **事件与错误需要一套统一的呈现语法**：收敛位置、分级显隐、治理原文，fallback/compacted/offloaded/retry/error 五类一套组件。
4. **tokens.css 需要向上长两层**：字号/间距/线宽尺度令牌 + 语义色槽位（surface/on-surface/state-*），组件不再写死 px。
5. **M3 的 IA 位置现在就要留白**：设备/配对/同步状态的导航归属，设计文档里先行决断。
