# S 波设计稿：字体与圆角系统返工（2026-08-21）

状态：**定稿即施工**（自己做模式）。
起因：用户 2026-08-20 目视实拍后指「UI 不对，字体 UI 都没有圆角这种感觉」——
I 波搬了 AionUi 的**颜色**与**结构**，没搬**质感层**（排版节奏 + 圆润度）。

## §0 当前缺陷实测（改之前先证明问题存在）

| # | 缺陷 | 实测证据 | 后果 |
|---|---|---|---|
| 1 | **全局无 line-height** | `tokens.css` body 段只有 font-family/background/color，无 line-height → 浏览器默认 `normal`≈1.2 | 中文正文行间挤压，「密不透风」的生硬感——质感差的头号成因 |
| 2 | **全局 tabular-nums** | body `font-variant-numeric: tabular-nums` | 正文里的数字被强制等宽，读起来机械；等宽只该用在读数（耗时/大小/token） |
| 3 | 字号阶梯过密且偏小 | 7 档挤在 11–17px：micro 11 / caption 12 / mono 12.5 / ui 13 / body 14 / title 15 / display 17 | 相邻档差 1px 形同没有层次；UI 主力 13px、胶囊 11px 显局促 |
| 4 | 圆角偏小 | 基准 `--radius: 14px`；控件 `--r-control` 8px、卡片 `--r-card` 12px | 小圆角 + 紧 padding = 紧绷，与「圆润」的目标相反 |
| 5 | 字重硬写 | 组件里散落 `font-weight: 600`，无语义 token | 中文在无可变字重时合成假粗，笔画糊；且强调层级不可统调 |
| 6 | 无字距体系 | 仅 App.vue 两处 letter-spacing | 中文标题需微正字距透气，拉丁小字同理 |
| 7 | 控件 padding 紧 | 胶囊 `4px 8px` | 触感局促（S1 已把「靠挤压塞一行」的错解换成换行，padding 本身仍紧） |

## §1 目标

不改配色、不改布局结构（那两层用户已认可），只动**排版节奏**与**圆润度**两层，
让界面从「信息密集的工具」变成「呼吸顺畅的现代应用」。

## §2 方案（数值取自 AionUi 源码实测，见 docs/research/2026-08-21-aionui-typography-radius.md）

| 项 | 落值 | 依据 |
|---|---|---|
| 行高 | `--lh-tight/snug/normal/relaxed = 1.3/1.45/1.55/1.7`，body 取 normal | AionUi 实测配对 12→18、13→20、14→20、16→24、24→32，markdown 1.7 |
| 字号 | display 19 / title 16 / **chat 16(新)** / body 15 / ui 14 / caption 12.5 / mono 13 / micro 12 | 控件基准 14、桌面聊天正文 16、mono 13 均为实测值 |
| 字重 | `--fw-normal/medium/strong = 400/500/600`；600 只留 19 处标题，52 处降 500 | 实测分布 500(151) ≫ 600(66) ≫ 700(17) |
| 圆角 | **不动 A 区基准**，只调别名：`--r-md` 10→12、`--r-card` 12→16 | 实测档位 8(主力)/12/16(大卡与弹窗)/20/24；我们 raw 阶梯本就覆盖 |
| 边框 | `.5px` → `1px`（103 处） | AionUi 全站 1px，无 .5px；.5px 在 100% DPI 下发虚 |
| 阴影 | 输入卡静止 `none`，聚焦 `0 2px 20px` 淡晕 | 实测 `useInputFocusRing`：静止 none + 大扩散低透明晕 |
| hero | 26 → 28px + `--lh-tight` + .012em | 实测 24px 是在 800px 宽布局里，我们内容区 1000+ 等比放大 |

**首轮走错一次并回滚（记录在案）**：先试图抬 `--radius` 基准 14→18px 让六档等比放大，
被 `tokens-mu3-appica` 例 2「A 区与参考文件逐行一致」拦下——A 区是外部参考的忠实副本，
不可为我们的设计意图篡改。正解是只改 B 区语义别名的映射档。**守卫又一次拦对了。**

## §3 红线

- 26+1 对比度守卫必须保持全绿（改的是尺寸不是颜色，理应不受影响，但要跑）。
- 零新 npm 依赖：**不引 webfont**（Inter 等），继续走系统字体栈——
  打包体积与离线可用性优先（章程：Windows 桌面应用，不联网取字体）。
- 每一档数值改动都要能在实拍截图上验证，不做「参数改了但看不出」的空转。
