# V 波设计稿：新壳能力面补齐（2026-08-21）

状态：**已实施**（V1-V9 全部落 main）。本稿是**事后成文**——它起源于一次可达性盘点，
不是先有设计再施工。如实记：这是流程上的一处偏离，原因与后果见 §0。

## §0 为什么会有这一波：一次可达性盘点

T5 收尾时对新组件树做了一次从 `main.ts` 出发的可达性遍历（脚本见交接文档），
结果是 **25 个旧组件 + 18 个 lib 模块 + App.vue 无人引用**。
逐个看这 25 个的名字才发现问题：它们里面有一半不是「被新组件取代了」，
而是**功能整个没接过来**。

其中最严重的一条：

> `StageChat` 只在 watch 依赖里数了一下 `chat.pendingPerms.length`，从没渲染过它。
> 默认权限档位就是「每次确认」——agent 一请求权限，界面上什么都不会出现，
> 回合无声卡死到 90 秒超时后被判 deny。**应用看起来在跑，其实永远没有下文。**

这是发布级阻断，而且它躲过了：全量测试（1890 例全绿）、typecheck、
之前所有的 xvfb 实拍（那些剧本用的都是不触发权限门的路径）。

**教训**：换壳是「把功能搬到新房子」，不是「在新房子里重写主要房间」。
搬家清单必须是**从旧实现出发的逐项核对**，不能是从新设计出发的补全——
后者只会补上你想得起来的那些。

## §1 补齐清单（按发现时的严重度排）

| 步 | 能力 | 没有它会怎样 |
|---|---|---|
| **V1** | 权限卡 + 差分预览 | agent 请求权限即无声卡死（**发布级阻断**） |
| **V2** | 事件条（降级/压缩/卸载/修剪/重试/出错/同步） | 出错没有重试入口；降级不告知，用户拿次一档模型的输出当主模型的 |
| **V3** | 思考块 | 每轮烧的 reasoning token 白花；出错无从判断它怎么想歪的 |
| **V4** | 终端 | 一整条能力不可达 |
| **V5** | 任务面板（上下文水位 + 四类回合状态） | 「今天它变笨了」没有任何线索可查 |
| **V6** | 附件（粘贴/拖拽/＋钮 + 历史 mediaRef chip） | 带图的消息在历史里退化成空气泡 |
| **V7** | 扩展市场 | 只能按路径导入本地技能 |
| **V8** | 产物清单收归 collectArtifacts | 同一份数据两处各写一遍，且拿不到正在跑的这一轮 |
| **V9** | 文本选区注释 / 引用 | 最后一块 |

## §2 不许动的东西（逐条有来由，全部照搬旧实现）

- **权限卡**：路径/命令逐字完整不截断（看不全就没法判断该不该批准）；
  倒计时纯显示（超时判定权在 minisd，组件自判会与广播打架）；
  shell 卡的桥命令双段告知（一次批准放行两类权限，不说清楚就是静默扩权）。
- **终端**：先订阅 `terminal.output` 并缓冲 → attach 拿滚动缓冲 → 再冲刷。
  颠倒顺序则 attach 往返途中的输出掉进缝里，表现为「命令跑了但没输出」。
- **市场**：malicious 不开确认卡 / warn 必须勾 / manualOnly 禁用 / 必填 env 未齐禁用 /
  isSecret 走 password / install 显式 confirm。渲染层的闸是「不给可点态」，
  服务端仍复核——两道都留着。
- **注释**：高亮走 CSS Custom Highlight API 零 DOM 改写；`::highlight` 必须非 scoped。

## §3 实拍逮到的真缺陷（测试全绿也没拦住的那些）

| # | 缺陷 | 性质 |
|---|---|---|
| 1 | 默认 provider 是猜的（`providers[0]`），设置页把它显示成「当前默认」 | **界面撒谎**：用户看到 A，后端在用 B。补 `provider.getDefault` RPC |
| 2 | 更新状态映射照 electron-updater 的**事件名**写，主进程存的是 status 值 | 原始状态串直接上屏 |
| 3 | 任务面板把 `StopReason` 内部枚举原样上屏（`endTurn`） | 同上 |
| 4 | 右栏三 tab 挤在 244px 里，「文件」被折成两行 | 排版 |
| 5 | 市场空结果劝人「换个词试试」，真实原因是两个源都连不上 | **文案不诚实** |
| 6 | zip 读失败漏出 yauzl 英文原文到预览卡 | 同上 |

前三条的共同点：**内部标识符漏给用户看**。每条都补了守卫钉住两边一致。

## §4 守卫红两次，两次都是守卫对

- `tokens-mu3-appica` 例 9「组件零硬编码颜色」——我在 StageMarket 写了 `rgba(0,0,0,.38)`
  做遮罩。tokens.css 早有 `--scrim` 的收编先例，新令牌系统漏了这一档：补 `--c-scrim`。
- `renderer-titlebar-stacking`「主体内所有 z-index 低于标题栏」——遮罩放在 40 落进主体档。
  层级序不变量是 主体 < 标题栏 50 < 模态 100。改到 100，并照 MarketPanel 的先例做
  **值级**豁免（只放行 100，面板内其余元素仍受守卫），不是文件级豁免。

「守卫红先想它对不对」至此第四、第五次兑现。

## §5 留给 T6

25 个旧组件 + App.vue 现在真的无人引用，但 **43 个测试文件指向它们**。
清场时每条守卫都要**逐条判断**：
- 不变量仍成立 → 重新指向新树（如层级序、零硬编码颜色）；
- 不变量随实现退场 → 连同实现一起删，并在提交里说明为什么它不再适用。

一删了之会留下守卫真空——那比留着死代码更危险。
