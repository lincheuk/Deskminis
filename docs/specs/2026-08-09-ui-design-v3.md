## 1. 决议反转记录（自 MU3 起生效）

MU1 拍板「变体 A + Codex/WorkBuddy/OpenMinis 三合一视觉基准」，其中 Apple HIG 语义色（iOS 系统灰、label 四级、material/backdrop-filter 材质语言）随变体 A 落地并经 MU2a 令牌化。MU3 用户拍板**反转**该基准的取值层：

1. **换掉而非融合** —— 全盘采用 Appica（@appica/ui-react v1.0.0，MIT）的视觉语言与取值；Apple HIG 色值体系（含 material 材质）整体退场。
2. **label 扩到 7 级** —— 4 级文字层次扩展为 Appica 的 7 级 foreground 体系（§3）。

不受反转影响、继续有效的 v2 决策：

- 信息架构与三栏布局（左任务列表 / 中对话流 / 右任务区）、回合式对话流、内联权限卡、工具行折叠呈现等结构与交互决策。
- MU2a「发送键 --label 黑底退场 → --action 实底」属交互语义决策而非 Apple 色值，**不反转**（Appica monochrome 主按钮语言不移植）。
- 四段三模式机制（跟随系统 / 强制深色 / 强制浅色）与 6 个切片标记结构。

## 2. 令牌双层架构（乙案）

tokens.css = **A 区 Appica raw 层**（token 名与值逐字照抄参考文件）+ **B 区 DeskMinis 语义别名层**（现有 token 名全部改为指向 raw 层的别名）。组件 `var(--token)` 引用零改动；这正是 Appica 官方两层架构（raw value tokens + aliased theme tokens）的同构。

新红线（替换 MU2a「tokens.css 只追加不改既有值」红线）：**raw 层取值唯一来源是参考文件，禁止凭印象写值；别名层映射关系禁止漂移**；组件禁写死颜色与 color-mix。

## 3. 文字层次：7 级 label 使用规范

按强度轴对齐（Appica 亮/暗两段强度序一致：intense > emphasis > strong > base > muted > subtle）：

| 级别 | 别名 | raw 目标 | 用途 | 消费场景（实测落地） |
|---|---|---|---|---|
| 1 基色 | --label | --foreground-strong | 正文 | 全组件正文（48 处引用）；收尾上移一档 |
| 2 | --label-secondary | --foreground-muted | 次要文字 | 说明、副标题、mono 辅助 |
| 3 | --label-tertiary | --foreground-subtle | 弱化文字 | 时间戳、占位符、提示 |
| 4 | --label-quaternary | --foreground-subtle | 最弱（与 3 级视觉合并） | 禁用态、spinner 轨 |
| 5 | --label-strong | --foreground-emphasis | 标题强化 | 会话/卡片/工具/字段标题（14 组件：ArtifactsPanel、ChatView .aname/.sname、DevicesModal 分组标题、DiffView 文件路径、EmptyState 要点标题、FilesPanel、ModelPicker 已选模型名、PermissionCard 标题、PermissionPicker 选项标题、ProgressPanel、ProviderSettings 字段标题、SessionList 会话标题、TitleBar .tb-title、ToolLine 工具名） |
| 6 | --label-emphasis | --foreground-emphasis | 大标题 | EmptyState 主标题、SettingsModal 分组标题 |
| 7 | --label-intense | --foreground-intense | 最强（近纯黑/白） | DevicesModal 配对码读数、PermissionCard 命令 mono、SettingsModal 页标题（--fs-display 位） |

**--label-inverse 不设别名**：反色能力由 raw 层 --foreground-inverse 承载；当前 UI 无反色表面（无 tooltip/无 monochrome 主按钮），首个反色表面出现时再启用别名。

## 5. 焦点环规范（无障碍）

raw 层：Appica `--focus-ring` 族 9 个照抄入库（亮段 alpha 30%、暗段 50%）。别名：`--ring` / `--ring-input` / `--ring-danger`（= --focus-ring / --focus-ring-input / --focus-ring-error）。

应用规范：

- 按钮/列表项/菜单项：`:focus-visible { outline: 2px solid var(--ring); outline-offset: 1px; }`
- 输入类：`:focus-visible { outline: 2px solid var(--ring-input); outline-offset: 1px; }`
- 危险/拒绝钮：`:focus-visible { outline: 2px solid var(--ring-danger); outline-offset: 1px; }`（PermissionCard 拒绝钮）
- 既有 `outline: none` 灭绝写法禁止新引入；存量 3 处（ChatView .field / DevicesModal .codeinput / ProviderSettings .inp）已退场，改为 :focus-visible 环。

应用清单（10 组件，已落地）：ChatView（.field/.send/.back-bottom/.uops/.slashitem）、TitleBar（.tb-ico/.mi/.it）、SessionList（.scard/.newbtn/.lfbtn）、SettingsModal（.sitem/.opt/.devbtn）、ProviderSettings（.inp/.act/.addbtn/.cancelbtn，:focus 边框保留 + 叠加环）、PermissionCard（.btn / .btn.deny 走 --ring-danger）、PermissionPicker（.mrow）、ModelPicker（.mrow）、DevicesModal（.codeinput/.pbtn/.rbtn/.xbtn）、ToolLine（.tline）。

### 5-1. 实际键盘可达性（交付复验实测，**必读**）

26 个 `:focus-visible` 选择器中，**17 个落在原生可聚焦元素上（环真实生效）**，**9 个落在无 `tabindex` 的 `<div>` 上（Tab 走不到，环为空转）**：

| 组件 | 环生效（button/input/textarea） | 环空转（div，无 tabindex） |
|---|---|---|
| ChatView | .field(textarea) .send .back-bottom .uops .slashitem | — |
| ProviderSettings | .inp(input) .act .addbtn .cancelbtn | — |
| PermissionCard | .btn / .btn.deny | — |
| DevicesModal | .codeinput(input) .pbtn .rbtn .xbtn | — |
| ToolLine | .tline | — |
| SessionList | .lfbtn | **.scard .newbtn** |
| SettingsModal | .devbtn | **.sitem .opt** |
| TitleBar | — | **.tb-ico .mi .it** |
| PermissionPicker | — | **.mrow** |
| ModelPicker | — | **.mrow** |

**成因（计划内在矛盾，MU3 范围内无解）**：§2-5 承诺补齐键盘可达性，而 MU3 计划 §1.2 非目标硬性禁止「动组件 DOM/交互逻辑」；让 div 型控件可聚焦必须加 `tabindex="0"` + Enter/Space 键盘处理，属 DOM 改动，超出授权。

**净效果仍为正**：改造前全应用**零焦点样式**，且 3 处输入框被 `outline: none` 主动灭环；改造后 17 个真正可聚焦控件有了符合规范的环，灭环写法退场。

**遗留（backlog）**：9 个 div 型控件的键盘可达性。补齐需要 DOM 层改造（tabindex + 键盘事件 + `role`），是独立的无障碍里程碑，不属令牌/样式层。**Tab 走查验收时这 9 处走不到属预期，不是实现缺陷。**

## 6. 材质退场声明

Apple material/backdrop-filter 语言全退场：`--material-tint`（4 段）/ `--material-thin` / `--material-regular` token 本体删除；组件 5 处消费全部改实底（TitleBar .titlebar → var(--bg)；ChatView .back-bottom/.composer/.slashmenu/.adel → var(--surface-1)）；组件侧 backdrop-filter 4 处全摘除（守卫：tokens-mu3-appica 例 6/8 双断言）。

TitleBar 的 `position: relative; z-index: 50` 保留为「防御性层级槽位」（论证见 renderer-titlebar-stacking.test.ts 头注）：滤镜曾创建层叠上下文困住下拉菜单，诱因虽消失，保留槽位固化「主体所有 z-index < 50 < 模态 100/110」不变量，成本为零。

视觉差异：毛玻璃 → 实底，正是 Appica 语言；composer/slashmenu 失去透视感，由 border + shadow 承担浮层表达。

## 7. 三模式结构（不变）

四段结构原样保留：`:root` = 浅；`@media (prefers-color-scheme: dark)` = 暗；`[data-theme="dark"]` = 暗重申；`[data-theme="light"]` = 浅重申。段内改「A 区 raw + B 区别名」两段式；主题无关 raw（--font-*/--radius-*/--border-width/--opacity-disabled）只在 :root 写一次。守卫：tokens-mu3-appica 例 2 断言各段 A 区与参考文件对应块逐行一致。

## 8. 对比度实测（WCAG，交付复验实算）

换算链：oklch → OKLab → linear sRGB（Ottosson 矩阵）→ WCAG 相对亮度 → 对比度。旧值按 alpha 混合到底色后计算。

| 层级 | 旧（Apple HIG） | 新（Appica） | 结论 |
|---|---|---|---|
| 浅 正文 `--label` | `#000000` 21.00 ✓ | `#364153` **10.31** ✓ AAA | 收尾上移一档后（原 base `#4a5565` 7.56，目视偏淡） |
| 浅 次级 `--label-secondary` | `rgba(60,60,67,.6)` **3.44 ✗** | `#6a7282` **4.84 ✓ AA** | **转正**：旧版不过 AA，新版过 |
| 浅 三级 `--label-tertiary` | `rgba(60,60,67,.3)` 1.73 ✗ | `#99a1af` **2.60 ✗** | 改善 +50%，仍不过 AA |
| 浅 四级 `--label-quaternary` | `rgba(60,60,67,.18)` 1.37 ✗ | 并入三级 2.60 ✗ | **改善 +90%**（合并是净收益，非损失） |
| 浅 强调 `--label-strong` | —（无此级） | `#1e2939` **14.68 ✓ AAA** | 新增；随正文连带上移一档 |
| 暗 正文 `--label` | `#FFFFFF` 21.00 ✓ | `#e5e7eb` **16.28 ✓ AAA** | 收尾上移一档后（原 base `#d1d5dc` 13.67） |
| 暗 三级 | `rgba(235,235,245,.3)` 2.25 ✗ | `#6a7282` **4.16 ✗** | 改善 +85%，逼近 AA |
| 暗 四级 | `rgba(235,235,245,.16)` 1.38 ✗ | 并入三级 4.16 ✗ | **改善 3 倍** |

**结论：MU3 未引入无障碍回归，是全面改善。** 旧调色板的次级/三级/四级**全部不过 AA**（1.37–3.44）；新调色板次级转正过 AA，三级与四级大幅提升。

**遗留缺口（继承自旧版，非 MU3 引入）：** 三级文字浅 2.60 / 暗 4.16 仍不过 AA 4.5。三级当前用于时间戳、占位符、禁用态等辅助信息（34 处引用）。若要补齐，需把三级从 `--foreground-subtle` 上提到 `--foreground-muted`（浅 4.84 / 暗需另核），但那会与次级同色、压掉一层层次——属独立的无障碍决策，不在 MU3 范围，记入 backlog。

> 计划 §2-1 初稿曾写「正文对比度浅 ≈4.9:1」，系估算未实算；交付复验实测为 7.56:1。
>
> **MU3 收尾调档（用户目视后提出「正文有点淡、hairline 也太浅」）**：`--label` 由 `--foreground` 上移至
> `--foreground-strong`（浅 7.56→**10.31**、暗 13.67→**16.28**），`--label-strong` 随之上移至
> `--foreground-emphasis`（浅 **14.68**、暗 **18.29**）以保住「正文 vs 标题」色差；
> `--separator` 由 `--border` 上移至 `--border-strong`（浅 `#e5e7eb`→`#d1d5dc`、暗 `#1e2939`→`#364153`）。
> **撞档代价**：`--separator-opaque` 本就零消费，无代价；`--label-strong` 与 `--label-emphasis` 同档，
> 唯一同时消费两级的组件是 EmptyState（主标题 22px/700 vs 要点标题 13px/600，字号差足以承担层次）。
> Appica 强级到 `--foreground-intense` 即到顶，再往上无档可提。
