# DeskMinis UI 设计 v4（工作台形态）

日期：2026-08-10 · 取代：[v3](2026-08-09-ui-design-v3.md) 的**布局与组件层**（v3 的令牌双层架构与对比度实测继续有效，见 §7）

---

## 1. 用户决议（2026-08-10）

起因：用户在 MU3 完成后目视真机，反馈「UI 太单薄」，随后明确是**能力面与信息面**单薄，而非视觉。四项拍板：

| 项 | 决议 |
|---|---|
| **布局** | **B —— 工作台为主**（图标轨 + 对话列 + 大工作台） |
| **默认配色** | **白色**；暗色保留为夜间与终端场景（三模式能力不变） |
| **中文字体** | **思源黑体 Noto Sans SC**（本机已装，打包成本零） |
| **组件设计** | 必须有真实产品依据，不得凭空发挥 |

## 2. 诊断：单薄的两个根

**根一 · 右栏装的是结果，不是过程。** 现状四标签「进度 / 产物 / 文件 / 终端」全是操作完的产物；成熟 agent desktop 的对应区域装的是**正在发生的现场**——它在浏览什么、点了哪里、改了哪几行、下一步打算做什么。agent 干活的过程全程不可见。

**根二 · 已建成的能力有 45% 没有入口。** `src/minisd/index.ts` 字面注册 33 个 RPC，其中 **15 个渲染端零引用**（全文搜确认）：M6 的 `control.pause/resume/status` 与 `audit.list`、M2b 的 `modelgroup.*` 全 5 个、M2c 的 `skills.setEnabled/delete/importStatus`、会话级 `delete/setMemoryEnabled/setModelBinding`。其中同步暂停做了完整后端 + 审计 + 13 笔 commit，界面上没有任何开关。

**结论：能力面不薄，薄的是「接出来」。** 因此本轮与下一轮**都是纯 renderer 工作**，`src/minisd` 零改动。

## 3. 布局规格（B）

```
┌──────────────────────────────────────────────────────────────┐
│ 任务条：状态点 · 名称 · 当前动作/步数/耗时/水位 · 待批准 · 暂停   │  38px
├──────┬───────────────────┬───────────────────────────────────┤
│ 图标 │ 对话              │ 工作台                             │
│ 轨   │                   │  标签条（可关闭 / 可多开）           │
│ 52px │ 336px             │  模式段控 + 地址 + 动作行           │
│      │                   │  视图                              │
│      │ ┌───────────────┐ │                                    │
│      │ │ 输入卡片       │ │                                    │
│      │ └───────────────┘ │                                    │
└──────┴───────────────────┴───────────────────────────────────┘
```

- **图标轨 52px**：`＋` 新建 / 会话图标（带待批准徽标）/ 弹性空隙 / 后端选择器 / 设置。工作态只留图标；侧栏可展开为 212px 完整列表（含状态点、标题、右对齐相对时间）。
- **对话列 336px**：不用气泡，助手输出按文档排版；权限卡内联（沿用 M2d 已验收设计）；底部输入卡片。
- **工作台（剩余全部）**：标签 = 浏览器 / 屏幕 / 打开的文件 / 终端；每个标签可关闭，同类可多开。

## 4. 组件规格与来源

每条都注明依据，取证方式为**下载真实产品截图逐帧读图**，不是凭 README 想象。

| 组件 | 规格 | 来源 |
|---|---|---|
| 图标轨 | 工作态会话列表压成纯图标，激活项左侧 2px 竖条 + 边框高亮 | AionUi 工作视图 |
| 会话身份 | 每个会话图标即所属 agent/模型的标识，不是通用圆点 | AionUi 侧栏 |
| 会话行（展开态） | `状态点 + 标题 + 右对齐相对时间`（`1s` `6h` `1d`）；运行中绿点，闲置灰点 | Agent Canvas 侧栏 |
| 对话排版 | **无气泡**：标题 / 列表 / 正文直接落在背景上，行高 1.72 | AionUi 会话视图 |
| 输入区 | 带阴影的卡片，底部仅 `＋` + 工作区 chip + 权限档 chip + 圆形发送 | AionUi 输入区 |
| 工作台标签 | 可关闭（`✕`）、可多开；实时标签带绿点 | AionUi 预览区 |
| 模式段控 | 同一内容多视图：`页面 / 源码 / 分屏` | AionUi `Source / Preview / 分屏` |
| 动作行 | 右对齐、图标+文字、低对比：`快照 / 历史 / 系统打开 / 下载` | AionUi 预览区头部 |
| 后端选择器 | 钉在侧栏底部：`● 本机 · MINIS-PC ⌄` + 齿轮 | Agent Canvas `● Local ⌄` |
| 列表分组 | **按状态分组 + 计数徽标**（`运行中 2` / `已停用 1`），不按时间 | Agent Canvas `Active 3 / Inactive 2` |
| 卡片动作 | 卡上直接 `▷ 立即运行` 与 `⋮`，不必进详情 | Agent Canvas 自动化卡 |
| 元数据 chip | 卡片底部一行 chip 说清配置（工作区 / 计划 / 能力），超出显示 `+1` | Agent Canvas 卡片 |
| 前置条件提示 | 模板卡直接标「需先启用 N 项能力」，不让人点进去才发现跑不了 | Agent Canvas `1 MCPs to connect before launch` |
| 色彩纪律 | **界面本体近乎无彩**，颜色只来自内容图标与状态点 | AionUi + Agent Canvas 一致 |

### 4-1. 明确不照抄的

- **待批准**：两家都做成侧栏徽标；DeskMinis 的**内联权限卡**是 M2d 已验收的设计，沿用内联，侧栏徽标只做计数补充。
- **顶部任务条**：两家都没有；但「过程可见」是本轮核心命题，保留。

## 5. 字体规格

| 层 | 字体 | 成本 |
|---|---|---|
| 拉丁 | `Segoe UI Variable Text` | Windows 11 自带 |
| 中文 | **`Noto Sans SC`** | **本机 `C:\Windows\Fonts\NotoSansSC-VF.ttf` 已装，可变字体，零打包** |
| 等宽 | `Cascadia Mono` | Windows Terminal 自带 |

栈序 `"Segoe UI Variable Text","Noto Sans SC",…` —— 拉丁走 Segoe，中文逐字符回落 Noto。

**不做子集化**：agent 输出的文本字符集不可预知，子集会掉生僻字且难复现。若日后要 MiSans 那种更紧的几何感，再评估 5–9MB 的打包代价。

## 6. 明暗策略

**默认白色**，暗色保留。理由：工作台主内容是网页与屏幕截图，绝大多数白底；白壳与内容连续，暗壳里那块白是刺眼的洞。这与「暗色护眼」的直觉相反，前提差异在于**内容本身是否暗**。

终端、diff、日志三个标签内部仍走暗色呈现，不受外壳影响。三模式（跟随系统 / 强制暗 / 强制浅）能力不变，MU2b 的 e2e 断言继续有效。

## 7. 令牌层（继承 v3，已结论）

MU3 的**双层令牌架构保留**：A 区 Appica raw 值层 + B 区 DeskMinis 语义别名层，组件只消费别名。v3 §8 的对比度实测与调档结论（`--label → --foreground-strong`、`--separator → --border-strong`）继续有效。

> **结论：不换板。** 原稿硬编码了 13 个 hex（正文 `#18202c` 等），与产品实际令牌（`--label` → 调档后 `#364153`）对不上，一度是未决项。处置方式不是空谈而是实测——把入库原型 [`docs/prototypes/mu5/layout-b.html`](../prototypes/mu5/layout-b.html) 的 13 个硬编码色**全部换成 `var()` 引用真实 tokens.css**，明暗两态逐屏看过：层次、强调、状态色、对比度均成立。**换完依然好看，即证明不必换板。**
>
> 映射关系（原型 `:root` 块即活文档）：`--pg→--bg-secondary`、`--card→--surface-1`、`--line→--border`、`--line2→--separator`、`--tx→--label`、`--tx2→--label-secondary`、`--tx3→--label-tertiary`、`--ac→--action`、`--ok/--warn/--err→--state-*`、饱和底色上的文字→`--on-action`（明暗两态均解析为纯白）。
>
> **例外且刻意**：`.wview` 内部（模拟被浏览的外部网页）保持字面色值，不随主题变化——它模拟的是真实网站。暗色截图里那块白正是 §6「默认白壳」的论据实证。
