逐条借鉴来源

设计细节来源原来画错的地方
52px 图标轨AionUi 工作视图：进入工作态后会话列表压成纯图标画了 250px 带标题的会话列，白占宽度
会话图标 = 身份AionUi 每个会话行带所属 agent 的标识只用了通用圆点
无气泡对话AionUi 助手输出按文档排版，标题/列表/正文直落背景用了气泡与卡片块，把内容框死
模式切换段控AionUi 预览区 Source / Preview / 分屏只有标签条，没有同一内容的多视图
右对齐动作行AionUi Snapshot / History / Open in system app / Download完全没有这一层
工作台标签可关闭AionUi 文件标签带 ✕，多标签并存标签是固定五个，不能开多份
输入框是带阴影的卡片AionUi 输入区浮起，底部只留 ＋ 与模型 chip摊了一排 pill，视觉噪音大
色彩只来自内容AionUi 界面本体近乎无彩，颜色全在 agent/助手图标上给壳子上了色（青/琥珀满屏）
后端选择器钉底部Agent Canvas 侧栏底部 ● Local ⌄ + 齿轮DeskMinis 有设备与同步，却没有「当前在哪台机器跑」的常驻入口
会话行 = 点 + 标题 + 相对时间Agent Canvas 会话列表：绿点表示运行中，时间右对齐写的是「刚刚 / 12 分钟前」长句，占宽且不对齐
按状态分组 + 计数徽标Agent Canvas Active 3 / Inactive 2按时间分组（今天），看不出哪些在跑
卡上直接「立即运行」Agent Canvas 每张卡带 ▶ Run now 与 ⋮把动作都藏进详情
元数据 chip 行Agent Canvas 卡片底部：仓库 / 计划 / 配置各一枚 chip，超出显示 +1卡片只有标题和描述，配置看不见
模板带前置条件Agent Canvas 1 MCPs to connect before launchDeskMinis 的技能要连桥才能跑，界面从不提前说

没照抄的地方，以及为什么：AionUi 把待批准做成侧栏徽标，DeskMinis 的权限卡是内联在对话里的（M2d 已验收的设计），沿用内联；它的顶栏没有任务条，但 DeskMinis 的「过程可见」是本轮核心命题，任务条保留。

Agent Canvas（原 OpenHands）取证的边界：它已改名，定位从「AI 编码 agent」变成「自托管的编码 agent 控制中心」，前端连多个 Agent Server（本机 / 虚拟机 / 云）。公开截图只拿到 Automations 这一屏——browser / changes / planner 三个工作台标签的视觉设计没拿到，属于没查到而不是不存在。而工作台恰恰是布局 B 的主角，这一块的参考实际只有 AionUi 一家。

CoPaw 与 OpenWorker 未能核实（全域名不通 / GoDaddy 待售停放域名），不作任何设计依据。
