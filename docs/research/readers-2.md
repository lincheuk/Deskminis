## Data formats
- SKILL.md: YAML frontmatter delimited by --- fences + markdown body. Parsed fields are exactly `name` (required), `description` (required), `version` (optional, default "1.0.0"); ALL other keys are silently ignored (this is the Claude/Codex compat mechanism). Both parsers accept YAML block scalars `|` and `>` including chomping/indent variants (`|-`, `|+`, `>-`, `>+`, `>2`). iOS additionally accepts 'headless' frontmatter (missing opening ---, gated on at least one recognized key); Android requires the opening --- and a non-blank name (returns null otherwise).
- skills.db SQLite schema (iOS Library/MinisChat/skills.db, mirrored on Android): skills(id TEXT PK, name, description, version, import_source, is_enabled INTEGER, installed_at REAL, updated_at REAL, use_count REAL) + session_skill_overrides(session_id, skill_id, is_enabled, PK(session_id,skill_id)). import_source encoded as 'url:<u>' | 'file' | 'bundled' | 'session'. skill id = slugify(name) (lowercase, non-alnum → '-').
- System-prompt skill disclosure fragment: 'Skills:' preamble + <available_skills><skill><name>…</name><description>…</description><path>/var/minis/skills/<id>/SKILL.md</path></skill>…</available_skills> + optional overflow line 'N more skills not shown above: … List /var/minis/skills/ or grep to search all.' Descriptions capped at 200 chars, max 20 skills disclosed.
- Canonical tool definition (provider-agnostic): AgentToolDefinition{name, description, parameters: map<name, AgentToolParam{type: string|integer|boolean, description, enumValues?}>, required: [names], propertyOrdering: [names]?}. Every tool includes a required `tool_title` string param (5-10 word user-facing summary in the user's language).
- Anthropic wire format: {name, description, input_schema:{type:"object", properties, required}} with cache_control ephemeral breakpoints on tools[last]/system[last]/last-2-user-messages.
- OpenAI Chat Completions wire format: {type:"function", function:{name, description, parameters:{type:"object", properties, required}}}; OpenAI Responses API: flat {type:"function", name, description, parameters:{…}}.
- Gemini wire format: {name, description, parameters:{type:"OBJECT", properties (types uppercased), required, propertyOrdering}}; iOS folds enums into the description text ('(values: a, b)'), Android emits enum arrays.
- Native offload CLI JSON envelope: success {ok:true, tool, action, data, timestamp}; error {ok:false, tool, action, error:{code, message}, timestamp}. Flags --compact (minify) and -q (data-only). Exit codes: 0 success, 1 error, 2 invalid args, 3 auth denied, 4 not available. Error codes like AUTHORIZATION_DENIED, INVALID_ARGS, NO_DATA.
- Android offload socket protocol: abstract unix socket 'native-offload', binary frames with magic 0x46464F4E ('NOFF') request / 0x52464F4E ('NOFR') response, version 1, carrying pid/argv/env/cwd; reply is (exit_code, guest_tmpfile_path); proot rewrites the execve to `/bin/cat <tmpfile>`. Chat session id forwarded via MINIS_CHAT_SESSION_ID env var.
- Context-offload stub text format: '[CONTEXT OFFLOADED] Content (~N tokens, M bytes) saved to: /var/minis/offloads/tools/<tool>_<shortToolId>.txt\nUse file_read tool to retrieve if needed.' Image placeholders: '[image omitted to save context — WxH, size — original: <path>; snapshot: <path>, use read_image…]'.

## Reusable for desktop
- Two-layer skill runtime: keep SKILL.md files verbatim on disk (never rewrite them) with metadata extracted into a small SQLite DB (skills + session_skill_overrides + use_count) — gives Claude/Codex skill compatibility for free since only name/description/version are parsed and unknown frontmatter keys are ignored.
- Progressive disclosure pattern: inject only <available_skills> XML (name, ≤200-char description, absolute SKILL.md path) into the system prompt, capped at ~20 with priority tiers (bundled > recently-updated-7d > most-used) and an overflow line telling the model to ls/grep the skills dir; the body loads only when the model file_reads the path. Trigger detection = intercepting file_read on <skillsRoot>/<id>/SKILL.md to bump use_count (normalize to 0-100 when any count >1000).
- Canonical provider-agnostic tool registry (AgentToolDefinition with flat typed params, required list, propertyOrdering) with three tiny serializers per provider dialect (Anthropic input_schema / OpenAI nested function + Responses flat / Gemini OBJECT+propertyOrdering with enum-in-description fallback). Android's toAnthropicJson/toGeminiJson/toOpenAIJson-on-the-data-class shape is the cleanest to port to TypeScript.
- The `tool_title` convention: every tool schema requires a 5-10 word human-readable summary param in the user's language — the UI renders it instead of raw args. Trivial to adopt and greatly improves an Electron chat UI.
- Keep the function-calling tool surface tiny (shell_execute, file_read/write/edit, browser_use, memory, read_image) and push everything else into namespaced CLI commands (apple-*/android-* → e.g. windows-*) reachable via shell_execute, documented in one system-prompt paragraph with --help for full usage. On desktop, offload handlers can be real shim executables (or named-pipe RPC into the Electron main process, mirroring Android's socket approach which is more portable than iOS's in-kernel hook) emitting the {ok, tool, action, data, timestamp} JSON envelope with --compact/-q flags and standard exit codes.
- Conditional tool registration: drop tools from the schema entirely when gated off (memory toggle, model image capability) and append an authoritative status override paragraph to the prompt rather than rewriting earlier prompt text.
- Context offloading: replace large old tool results/inputs/images in history with '[CONTEXT OFFLOADED] … saved to <path>, use file_read to retrieve' stubs written under a session offloads dir; subtraction-based token accounting from API-reported usage; protect the last 4 messages; separate image-trim pass with re-fetchable placeholders that skip snapshot copies for already-persistent paths.
- Tolerant SKILL.md frontmatter parser details worth copying verbatim: headless-frontmatter recovery (opening --- lost in copy/paste), block scalar |/> with chomping indicators, parse-failure guard on rescan (keep old metadata when a mid-edit save temporarily breaks frontmatter), name-fallback from source URL, slugify for stable ids.
- Skill import pipeline: GitHub raw-URL import with Contents-API sibling-file download (detached so UI navigation doesn't cancel it, partial-success reporting), ZIP import tolerating a one-level wrapper dir, and orphan reconcile for skills the agent itself writes into the skills dir mid-session.
- Session-scoped skill overrides (per-conversation enable/disable layered over the global flag) and slash-menu skill rows as a pure typing aid ('/<name>' in the composer, model does the actual loading) — both cheap, high-value UX patterns for a desktop agent.
- Anthropic prompt-cache breakpoint strategy (tools[last], system[last], penultimate + last user message) documented at AnthropicAgentProvider.swift:814-825 — directly applicable to any desktop agent loop hitting the Anthropic API.
