# OpenMinis (iOS/Android AI-agent app): sandbox execution layer (iSH/PRoot), debug JSON-RPC server, and sync/backup (iCloud + LAN skeleton)

## Key findings
- SANDBOX/iOS: customized iSH fork (OpenMinis/ish-arm64, branch feature-arm64, Asbestos ARM64 JIT, Alpine aarch64 guest) linked as static libs (libish.a, libish_emu.a, libfakefs.a); full summary at C:/Users/24739/Downloads/openminis1/OpenMinis/docs/specs/ios-sandbox-ish-summary.md, integration guide (Chinese) at deps/ISH_INTEGRATION.md, build script deps/build_ish.sh
- SANDBOX/iOS exec API layers: ISHKernel.m (boot, executeCommand w/ PTY, executeCommandAndWait(timeout:), sendInput, setTerminalSize, bindMountPath) at src/ios/iSH/; ISHShellExecutor.m (line callbacks, exit code, timeout, SIGKILL, env injection); ISHExecutionCoordinator.swift at src/ios/Agent/ — FIFO one-command-at-a-time across ALL sessions, regex prompt detection ($ , # , user@host:path$), 100KB output cap, 10-minute preemption, per-session /var/minis mount remount
- SANDBOX/Android: PRoot is process-per-command, so architecture differs: PRootKernel.kt (config holder + proot command builder, global bind-mount map, env: PATH/HOME/BROWSER=/usr/local/bin/minis-open/ENV=/etc/profile/CHARSET/NO_COLOR/PYTHONDONTWRITEBYTECODE/GOMAXPROCS=2/UV_LINK_MODE=symlink/POSIX TZ/system proxy) at src/android/app/src/main/java/com/openminis/app/sandbox/PRootKernel.kt; ExecutionCoordinator.kt — one PersistentShell per sessionId with per-session Mutex (concurrent across sessions, serialized within, unlike iOS global FIFO), sentinel-marker exit-code capture, dead-shell auto-recreate, env snapshot diff w/ unset, timezone/proxy broadcast to live shells; result = {output, exitCode, durationMs} after TerminalSanitizer.sanitize + truncate
- SANDBOX mount contract (identical guest paths both platforms): per-session /var/minis/{attachments,offloads,workspace,browser} -> host per-session dirs; global /var/minis/{memory,skills,shared,mcp-servers} -> shared dirs; user external mounts /var/minis/mounts/<name>; iOS host base Library/MinisChat/minis/, Android filesDir/minis-sessions/<id> and filesDir/minis-global. Android gotcha documented in ExecutionCoordinator.buildSessionBindMounts: PersistentShell's -b argv is built from ITS map, PRootKernel.bindMounts only feeds resolveHostPath — two maps must be kept in sync
- SANDBOX native offloads: guest execve on /usr/local/bin/apple-* (22 handlers: calendar, contacts, maps, photos, health, home, location, device, clipboard, weather, notification, alarm, vision, nlp, speak, speech, media, player, ffmpeg, open...) intercepted; iOS in-process via native_offload.c -> ObjC handler; Android via proot extension -> abstract unix socket 'native-offload' served by NativeOffloadServer (src/android/.../sandbox/NativeOffload.kt) with binary LE frame protocol; chat session id forwarded via MINIS_CHAT_SESSION_ID env var for per-session permission scoping
- DEBUG SERVER: JSON-RPC 2.0 over HTTP POST; iOS DEBUG builds only, port 8321, binds 0.0.0.0 (src/ios/Debug/DebugServer.swift, DebugJSONRPC.swift, DebugMethodRegistry.swift); Android port 5321 (src/android/.../debug/DebugServer.kt) — loopback (adb forward) is token-free, LAN clients must present per-install token (files/debug_server_token, constant-time compare). Full spec: docs/specs/debug-server-api.md
- DEBUG SERVER method surface (docs/specs/debug-server-api.md): UI inspection (debug.viewTree/search/inspect/highlight/screenshot), filesystem (debug.ls/readFile/appInfo — path prefixes Library/, Documents/, else rootfs data path), logs (debug.logs.list/read/setEnabled), LLM tracing (debug.llmRequests w/ full request/response + token usage, auth headers stripped, SSE body capped 64KB; debug.agentTrace), in-app browser control (debug.browser.listTabs/pageInfo/executeJS/getReadable/getText/screenshot), provider management (provider.types schema-discovery; provider.instances.list/create/update/delete/test; provider.models.list/add/update/delete/refresh/setAgentLoop; provider.groups.* incl. setDefault) and chat automation (chat.sessions.list/get, chat.messages.list, chat.sessions.usage, chat.models.list, chat.prompt, chat.retry, chat.session.status/cancel/delete) — chat.prompt takes prompt, sessionId?, base64 attachments, thinkingLevel, modelEntryId XOR modelGroupId, wait/waitTimeout(600s default, clamp 1-1800); destructive methods require confirm:true; credentials are write-only
- DEBUG SERVER LAN auth (iOS, src/ios/Debug/DebugAuth.swift): protocol v1 — /pair grants 32-byte token K after on-device user approval (Mode B plain only from 127.0.0.1; Mode A wraps K via ephemeral X25519 for LAN); /rpc uses encrypted envelope HMAC-SHA256-CTR stream cipher, encrypt-then-MAC, per-request random nonce, ±120s timestamp window, 1024-entry nonce replay LRU, separate direction key for responses, 30-day idle token expiry. This is a proven phone-side LAN remote-control auth scheme
- SYNC V2 (src/ios/Agent/Sync/V2/): SyncCore.swift — transport-agnostic dispatcher: dirty queue (ChatStore.markDirty), 3s send debounce, broadcast to multiple parallel transports, inbound merge to SQLite, dynamic throttling (background x4, cellular x2); SyncTransport.swift — protocol {name, capabilities OptionSet [pushObserve, deltaFetch, assets, persistence, conflictDetect], retryAfter, start/stop/send/observe/fullFetch/fetchChanges/delete}; conflict policy lastWriteWinsByField(updatedAt); TombstoneManager for deletes; MigrationEngine for v1->v2
- SYNC V2 LAN: LANTransport.swift is an explicit SKELETON (isImplemented=false, preconditionFailure on all methods) with the intended design written in comments: advertise _minis-sync._tcp via NWListener (Bonjour), discover peers via NWBrowser, WebSocket push of JSON-encoded PortableRecord batches, assets multiplexed as length-prefixed binary frames on the same connection, capabilities=[.pushObserve, .conflictDetect] (no persistence, no deltaFetch — fullFetch returns empty, history relies on iCloud), deletes broadcast as tombstone records
- SYNC V2 record types (src/ios/Agent/Sync/V2/SyncedTypes.swift, 748 lines): SessionV2, MessageV2 (partsJson = JSON-encoded ContentPart array; sortOrder is a hint only — receivers re-derive from created_at+id), CompactMarkerV2, SessionFileV2, SkillV2, ProviderConfigV2, MCPServersV2, MCPServerItem, ProviderInstanceV3, ProviderModelEntryV3, ProviderModelGroupV3, EnvVarV2, EnvVarItem, SyncDeviceV2, SoulV2, MemoryGlobalV2, MemoryDailyV2; per-type schemaVersion + minimumCompatibleVersion gate + unknownFields carry-through for cross-version safety
- SYNC v1 (still present): CloudSyncEngine.swift (src/ios/Agent/Sync/, 2992 lines, CloudKit CKRecord-based) with SyncLogStore persisting sync-log.json; ICloudSharedZoneTransport.swift (1817 lines) is the CloudKit implementation of the V2 SyncTransport protocol; SyncDirtyScanner.swift scans SQLite for dirty rows
- BACKUP: ICloudBackupManager.swift (src/ios/Agent/Sync/, DEBUG-gated) — three categories (sessions = minis.db+media/+minis/; skillsAndMemories = skills.db+skills/+memory/; full) zipped from Library/MinisChat via NSFileCoordinator, uploaded to iCloud Drive container iCloud.com.openminis.app/Documents/backups/<deviceName>/<prefix>_<timestamp>.zip, restore via built-in minimal ZIP extractor; UI at src/ios/Views/Backup/ICloudBackupView.swift and src/ios/Views/Sync/{CloudSyncSettingsV2View,SyncMigrationDetailView}.swift
- Android debug parity files: src/android/app/src/main/java/com/openminis/app/debug/{DebugRPCHandler,DebugMethodRegistry,ChatDebugMethods,ChatMutationMethods,ProviderDebugMethods,ProviderMutationMethods,BrowserDebugMethods,DebugInspectorMethods,HeadlessChatRunner,LLMRequestLog}.kt — Android mirrors the iOS RPC surface including headless chat runs

## Data formats
- PortableRecord JSON (C:/Users/24739/Downloads/openminis1/OpenMinis/src/ios/Agent/Sync/V2/PortableRecord.swift): Codable record {id: {type, id} serialized as 'Type:id', fields: {name: {t: tag, v: value}} tagged-enum values (null/string/int/double/bool/date/data/json), assets: {key, fileURL, size, mimeType}, schemaVersion, minimumCompatibleVersion, unknownFields (carried through round-trips), updatedAt (LWW timestamp)}; batches are SyncOutboundBatch {records, deletes} / SyncInboundBatch {records, deletes, sourceDeviceId}
- JSON-RPC 2.0 over raw HTTP POST (debug server): {jsonrpc: '2.0', id, method, params}; standard error codes -32700/-32600/-32601/-32602/-32000; attachments as {name, data: base64, mime?}; screenshots as {base64, size, encoding: 'png'}
- Native-offload binary frame (src/android/.../sandbox/NativeOffload.kt): little-endian ints, request = MAGIC 0x46464F4E ('NOFF') + version(1) + pid + argc + argv[] (u32-length-prefixed UTF-8 strings) + envc + 'K=V' strings + cwd; response = MAGIC 0x52464F4E ('NOFR') + exitCode + guest tmpfile path; guest then reads output via rewritten execve to /bin/cat <tmpfile>
- Shell sentinel protocol (src/android/.../sandbox/PersistentShell.kt): command wrapped as `{command}\necho "__MINIS_DONE_{marker}_EXIT_$?__"` on a long-lived /bin/sh stdin; exit code parsed with regex __MINIS_DONE_{marker}_EXIT_(\d+)__
- SQLite databases: minis.db (chat sessions/messages), skills.db, fakefs meta.db (iSH virtual-FS metadata), all under Library/MinisChat/ on iOS
- ZIP backup archives (ICloudBackupManager.swift): <prefix>_<timestamp>.zip created via NSFileCoordinator zip, stored in iCloud container iCloud.com.openminis.app under Documents/backups/<deviceName>/; restore via a custom minimal ZIP parser (EOCD scan)
- config.json (ProviderConfigStore) — provider instances/models/groups persisted as JSON, credentials in Keychain only (write-only over RPC)
- Daily-rotated text logs: Library/Logs/minis-YYYY-MM-dd.log; sync event log sync-log.json (max 1000 entries)

## Reusable for desktop
- Exec layer: adopt the Android ExecutionCoordinator pattern over the iOS one — per-session persistent shell + per-session mutex (concurrency across sessions) with the sentinel protocol `{command}; echo "__MINIS_DONE_{marker}_EXIT_$?__"` for exit-code capture on a long-lived shell; this maps 1:1 to spawning persistent pwsh/cmd/WSL-bash processes from Electron's main process, including dead-shell auto-recreate, env-snapshot diff with unset, and timezone/proxy broadcast to live shells
- Keep the /var/minis/* guest path contract (attachments, offloads, workspace, browser per-session; memory, skills, shared, mcp-servers global; mounts/<name> for user folders) so skills, profile scripts, and agent prompts written for mobile work unchanged on desktop — on Windows these become plain directory junctions or WSL mounts instead of PRoot -b flags
- Native-offload envelope as the host-API bridge: guest/child-process calls a stub name, host receives {pid, argv, env, cwd, sessionId from MINIS_CHAT_SESSION_ID} and returns {exitCode, output} — on Windows implement over a named pipe or localhost socket reusing the simple LE frame protocol (magic+version+len-prefixed strings); this cleanly exposes desktop APIs (notifications, clipboard, TTS, file dialogs) to sandboxed commands
- Debug-server JSON-RPC namespace as the remote-control protocol to borrow for LAN sync/companion features: chat.prompt/retry/status/cancel with wait+waitTimeout semantics, chat.sessions.list/messages.list pagination shapes, provider.* CRUD with schema discovery via provider.types (automation stays working when new provider types are added), confirm:true guards on destructive methods, write-only credential convention — a desktop app exposing this same surface is immediately drivable by the existing mobile tooling and vice versa
- LAN sync protocol: implement the LANTransport design outline exactly as commented — mDNS/Bonjour service _minis-sync._tcp for discovery, WebSocket connections per peer, JSON-encoded PortableRecord batches, length-prefixed binary frames for assets, tombstone records for deletes, no-persistence/no-deltaFetch capability declaration; PortableRecord (tagged field values, schemaVersion + minimumCompatibleVersion + unknownFields carry-through, updatedAt LWW) is a fully specified, Codable/JSON wire format ready to reimplement in TypeScript
- SyncTransport protocol + capability OptionSet as the desktop sync architecture: SyncCore stays transport-agnostic (dirty queue, debounce, multi-transport broadcast, LWW merge), letting desktop ship LAN-only first and add a cloud transport later without touching merge logic
- Pairing/auth for LAN: reuse the DebugAuth v1 flow — one-time /pair with on-device user approval granting a 32-byte token (X25519-wrapped over LAN), then HMAC-SHA256-CTR encrypt-then-MAC envelopes with nonce replay protection and idle expiry; or the cheaper Android token-gate (loopback free, LAN requires per-install token, constant-time compare) for a first cut
- Backup/export: the three-category ZIP backup model (sessions / skills+memories / full) with <category>_<timestamp>.zip naming and per-device subfolders translates directly to a desktop export-to-folder/import feature and doubles as the cross-device migration path before LAN sync exists
- Record-type catalog to sync between phone and desktop is already enumerated (SessionV2, MessageV2, SkillV2, ProviderInstanceV3, EnvVarV2, MemoryGlobalV2/DailyV2, SoulV2, MCPServerItem, ...) including which fields each carries — a desktop port can hydrate its own store from these shapes and interop with existing iCloud data via the same PortableRecord identities ('Type:id')

## Open questions
- LANTransport is only a skeleton (isImplemented=false) — no working LAN sync ships yet; the asset-frame wire format beyond 'length-prefixed binary over the same WebSocket' and the peer handshake/pairing story are undefined, so a desktop implementation would be defining the protocol, not porting one
- The exact byte layout and cross-language test vectors for the iOS encrypted debug envelope are said to live in .claude/skills/debug-server/SKILL.md, but no .claude/skills directory exists in this checkout — full envelope framing would need to be reverse-read from DebugAuth.swift (~remaining 500+ lines not read)
- Android debug server method-by-method parity with the iOS surface (esp. provider.groups.* and chat.retry) was inferred from file names, not verified per method
- How SyncCore decides which types route to which transport (SyncTypeMetadata per-record 'transports' allowlist is mentioned in SyncTransport.swift comments) — not read in detail
- Whether the debug-server-api.md provider/chat sections are fully implemented on iOS or partially aspirational (the doc itself flags the ProviderMutations facade as 'tentative')
