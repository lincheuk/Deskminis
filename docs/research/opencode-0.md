# 桌面端与 UI 架构 (packages/desktop, packages/app, packages/ui, packages/session-ui)

## Key findings
- **It is Electron, not Tauri** (Tauri is legacy — see 'formats' for residue). `C:/Users/24739/Downloads/opencode-ref/packages/desktop/package.json` declares `electron@42.3.3`, `electron-vite@^5`, `electron-builder@26.15.2`, `electron-store@11.0.2`, `electron-updater@6.8.9`, `electron-window-state@^5.0.3`, `electron-log@^5`, `electron-context-menu@4.1.2`. Version 1.18.5, `main: ./out/main/index.js`. Scripts: `dev` = `electron-vite dev`, `build` = `electron-vite build`, `package` = `electron-builder --config electron-builder.config.ts` (+ `package:mac|win|linux`).
- **Three-process split with an explicit rule.** `packages/desktop/AGENTS.md` says exactly two things: renderer may only call `window.api` from `src/preload`; main must register IPC handlers in `src/main/ipc.ts`. Source layout: `src/main/*` (39 files), `src/preload/{index.ts,types.ts}`, `src/renderer/*`. Total desktop TS is only ~4,559 lines — the shell is thin because all UI lives in `packages/app`.
- **The core service runs as an Electron `utilityProcess` sidecar, and the renderer talks to it over plain HTTP + SSE — not IPC.** `packages/desktop/src/main/server.ts` `spawnLocalServer()` does `utilityProcess.fork(join(dirname(...), 'sidecar.js'), [], { serviceName: 'opencode server', stdio: 'pipe' })`, then `child.postMessage({type:'start', hostname, port, password, userDataPath})` and waits for a `{type:'ready'}` message (60s stall timeout) followed by an HTTP health poll every 100ms. `src/main/sidecar.ts` imports the bundled server via a Vite virtual module `virtual:opencode-server` and calls `Server.listen({ port, hostname, username: 'opencode', password, cors: ['oc://renderer'] })`.
- **Auth is HTTP Basic with a per-launch random password on an ephemeral loopback port.** `src/main/index.ts` picks a free port by `createServer().listen(0, '127.0.0.1')` then closing it (overridable via `OPENCODE_PORT`), sets `hostname='127.0.0.1'`, `password = randomUUID()`, and resolves a `serverReady` Deferred with `{url, username:'opencode', password}`. The renderer fetches this via `window.api.awaitInitialization()` and builds `Authorization: Basic base64('opencode:'+password)` in `packages/app/src/utils/server.ts` (`authTokenFromCredentials`, `createSdkForServer`, `createApiForServer`).
- **Renderer is served from a custom privileged scheme `oc://renderer` in production.** `src/main/windows.ts` registers scheme `oc` with `{secure:true, standard:true, supportFetchAPI:true, stream:true}` and `protocol.handle` resolves paths under `out/renderer` with path-traversal rejection (`rel.startsWith('..')`). Dev uses `process.env.ELECTRON_RENDERER_URL`. `webPreferences: { preload, contextIsolation: true, nodeIntegration: false, sandbox: true }`.
- **Windows: multi-window with per-window UUID identity.** `restoreMainWindows()` restores persisted window IDs from electron-store; each window gets `window-state-<id>.json` (electron-window-state, default 1280x800) and its own renderer data file `opencode.window.<id>.dat`. Custom titlebar: macOS `titleBarStyle:'hidden'` + `trafficLightPosition:{x:14,y:14}`; Windows `frame:false` + `titleBarOverlay` with `color:'#00000000'`, `symbolColor` white/black by mode, `height: max(40, round(40*zoom))` (`titlebarHeight = 40`).
- **Renderer entry is SolidJS, and it is 100% a client of `@opencode-ai/app`.** `src/renderer/index.tsx` (464 lines) imports `AppBaseProviders`, `AppInterface`, `PlatformProvider`, `ServerConnection` from `@opencode-ai/app`, renders with `solid-js/web` `render()`, and uses `MemoryRouter` (`DesktopMemoryRouter`) persisting last route to `localStorage` key `opencode.desktop.window.<id>.last-active-url`. Its whole job is to construct a `Platform` object (file pickers, openLink/openPath, clipboard image, notifications, storage, updater, zoom, WSL) that delegates to `window.api`.
- **`packages/app` is a shared SPA used by both Electron and the browser.** It has its own `index.html`, `vite dev/build`, Playwright e2e, and exports a Vite plugin at `packages/app/vite.js` (`@opencode-ai/app/vite`) that the desktop's `electron.vite.config.ts` plugs into its `renderer` config. The renderer's `publicDir` is `../../../app/public`. Stack: SolidJS 1.9.10, `@solidjs/router`, `@tanstack/solid-query`, `@tanstack/solid-virtual`, `@kobalte/core` (headless primitives), Tailwind 4, `effect`, `motion`, `shiki`, `@pierre/diffs`, `ghostty-web` for terminals.

## Formats
- **Sidecar control protocol** (main ↔ utilityProcess, `src/main/server.ts` + `src/main/sidecar.ts`): parent→child `{type:'start', hostname:string, port:number, password:string, userDataPath:string}` or `{type:'stop'}`; child→parent `{type:'ready'} | {type:'stopped'} | {type:'error', error:{message, stack?}}`. Child validates every field before acting (`parseCommand`). Stop path: postMessage 'stop', race against `SIDECAR_STOP_TIMEOUT=6000` then `child.kill()`.
- **Server auth**: `Authorization: Basic ` + `btoa('opencode:' + password)`, password = `randomUUID()` per app launch. Health check tries both `/api/health` (v2, returns `{pid:number}`) and `/global/health` (v1, returns `{healthy:true}`) with `AbortSignal.timeout(3000)`.
- **Event stream is SSE, not WebSocket.** `packages/server/src/handlers/event.ts` returns `content-type: text/event-stream` with `Cache-Control: no-cache, no-transform`, `X-Accel-Buffering: no`, `X-Content-Type-Options: nosniff`; first frame is `{id, type:'server.connected', data:{}}`, then a bounded subscriber stream (`subscriberCapacity = 256`), merged with a `: heartbeat\n\n` comment every 15 seconds. Each SSE `data:` is one JSON-encoded `OpenCodeEvent`.
- **Event envelope + v1→v2 adapter** (`packages/app/src/context/server-sdk.tsx` `adaptServerEvent`): current shape `{id, type, data, location:{directory}}`; legacy shape `{directory, payload:{type, properties}}`. Renames observed: `permission.v2.asked → permission.asked` with `{data.action→properties.permission, data.resources→properties.patterns, data.save→properties.always, data.source:{type:'tool',messageID,callID}→properties.tool}`; also `permission.v2.replied`, `question.v2.asked/replied/rejected`. Delta event types that get merged: `session.text.delta`, `session.reasoning.delta`, `session.tool.input.delta` (keyed by sessionID+assistantMessageID+callID), `session.compaction.delta` (uses `.text` instead of `.delta`), plus legacy `message.part.delta {messageID, partID, field, delta}`.
- **PTY is the only WebSocket.** `packages/app/src/utils/terminal-websocket-url.ts` builds `ws(s)://host/api/pty/<id>/connect?location[directory]=…&cursor=N` (v2) or `/pty/<id>/connect?directory=…&cursor=N` (v1), with either a `ticket` param or `auth_token=base64(user:pass)` for v1.
- **Permission reply**: `api.permission.reply({ sessionID, requestID, reply: 'once'|'always'|'reject', location?: {directory} })`. `PermissionRequest` carries `{id, sessionID, permission, patterns:string[], always, metadata, tool?}`.
- **Theme JSON schema** (`packages/ui/src/theme/desktop-theme.schema.json`, published as `https://opencode.ai/desktop-theme.json`): `{ $schema, name, id, light: Variant, dark: Variant }` where `Variant = ({seeds}|{palette}) & {overrides?: Record<token, '#hex'|'var(--x)'>, v2Overrides?: Record<string, string>}`. Palette keys: `neutral, ink, primary, success, warning, error, info, accent?, interactive?, diffAdd?, diffDelete?`. Example from `themes/oc-2.json` light palette: `neutral:#f7f7f7, ink:#171311, primary:#dcde8d, success:#12c905, warning:#ffdc17, error:#fc533a, info:#a753ae, interactive:#034cff, diffAdd:#9ff29a, diffDelete:#fc533a`.
- **Component styling contract**: every component is `[data-component="name"]` with `[data-slot="…"]` children and `[data-variant]/[data-size]/[data-state]` attributes, styled by a co-located plain `.css` file imported into `packages/ui/src/styles/index.css` under `@layer components`. Layer order is declared once: `@layer theme, base, components, utilities`. Example literals from `button-v2.css`: `border-radius:6px; gap:6px; font-size:13px; font-weight:530; line-height:20px; letter-spacing:-0.04px`; sizes `small: 24px tall / 0 9px / radius 4px`, `normal: 28px / 0 11px`, `large: 32px / 0 15px`; focus ring `outline: 2px solid var(--v2-border-border-focus); outline-offset: 2.5px`.
- **Icons**: `packages/ui/src/components/icon.tsx` embeds ~100 SVG path strings in a plain `const icons = {...}` object keyed by kebab name (`glasses`, `console`, `code-lines`, `checklist`, `brain`, `mcp`, `task`, `chevron-grabber-vertical`, …), all `stroke="currentColor"` on a 20×20 grid. Separate sprite sheets (`app-icons/sprite.svg`, `file-icons/sprite.svg`, `provider-icons/sprite.svg`) are generated by `vite-plugin-icons-spritesheet` (see `packages/ui/vite.config.ts`).

Proof the app was ported from Tauri to Electron and kept a compatibility shim rather than renaming the attribute.

## Lessons for DeskMinis
- **Adopt: run minisd as an Electron `utilityProcess`, not a detached child process.** OpenCode's `spawnLocalServer` (`packages/desktop/src/main/server.ts`) gets structured `postMessage` handshake, `app.on('child-process-gone')` diagnostics, automatic teardown with the app, and piped stdout/stderr into the app log — all things a raw `spawn()` makes you build. DeskMinis already has a separate minisd binary; wrapping it as a utilityProcess entry (or at minimum copying the ready/stopped/error message protocol and the 60s stall + 6s stop-then-kill timeouts) is a cheap, high-value upgrade over 'spawn and hope'.
- **Adopt the two-phase readiness signal.** OpenCode does NOT trust the 'ready' IPC message alone: after `{type:'ready'}` it polls an HTTP health endpoint every 100 ms while racing the child's exit promise, so a process that starts and immediately dies fails fast with a clear error instead of hanging the splash screen. DeskMinis' WebSocket handshake should do the same: 'socket accepted' ≠ 'core healthy'.
- **Adopt: credentials resolved in main, handed to the renderer via one IPC call.** `awaitInitialization()` returns `{url, username, password}` after the server is up; the renderer never guesses a port or reads a token file. DeskMinis' per-run bearer token should flow the same way — `ipcRenderer.invoke('await-initialization')` returning `{wsUrl, token}` — never an env var or a file the renderer reads itself.
- **Adopt: ephemeral port + per-launch random secret + loopback-only + explicit CORS allowlist.** OpenCode binds `127.0.0.1:0`, generates `randomUUID()` per launch, and the sidecar passes `cors: ['oc://renderer']` so only the app's own scheme can talk to it. It also force-injects loopback hosts into `NO_PROXY`/`no_proxy` in *both* main and sidecar (`ensureLoopbackNoProxy`) — a real-world bug class on corporate Windows machines with a system proxy, which DeskMinis on Windows will hit.
- **Adopt the renderer security posture verbatim**: `contextIsolation:true, nodeIntegration:false, sandbox:true`, a preload that exposes exactly one frozen `window.api` object, and a hard rule (their `AGENTS.md`) that the renderer may call nothing else. DeskMinis' Vue renderer should be a pure JSON-RPC client + `window.api`; if the Vue side ever needs `fs` or `child_process`, that's a design smell.
- **Adopt the custom privileged scheme for production loading.** `oc://renderer` (registered via `registerSchemesAsPrivileged` with `secure/standard/supportFetchAPI/stream`) plus a `protocol.handle` that rejects `..` traversal is strictly better than `file://` for a Vue SPA: it gives you a real origin (so localStorage/service workers/CSP behave), and it's the origin you then allowlist in the core's CORS.
- **Adopt: renderer persistence via IPC into `electron-store`, not localStorage.** OpenCode's `storeGet/Set/Delete/Clear/Keys/Length(name, key)` + lazily-constructed named stores under `userData` gives per-window data files, survivable backup/migration, and — critically — lets the *main* process clean up state when a window is closed for good (`store-cleanup.ts`, `removeStoreFile`). Note their explicit warning: don't instantiate `electron-store` at module load, because import hoisting beats `app.setPath('userData')` and silently writes to the wrong directory.
- **Adapt: multi-window with UUID identity is what makes M3 (peer sync) tractable.** Each window has a UUID, its own `window-state-<id>.json` and its own `opencode.window.<id>.dat`. If DeskMinis wants LAN peer sync of sessions later, giving every window (and every desktop) a stable ID *now* is far cheaper than retrofitting it.
- **Adapt the `ServerConnection.Any` abstraction for M3.** OpenCode's UI is written against a discriminated union `{type:'sidecar'|'http'|'ssh', http:{url,username,password}}` with a derived `key` (`sidecar`, `wsl:<distro>`, `ssh:<host>`), and a `detectServerProtocol()` + `createCompatibleApi()` shim that hides version differences. DeskMinis should define an equivalent `PeerConnection` union (`local | lan:<peerId>`) on day one so that 'my minisd' and 'a peer's minisd' are the same type to the Vue layer, and mDNS-discovered peers just append to a list. Their WSL subsystem (~1,450 lines) is the concrete proof this pattern scales to real remote backends.
- **Adopt: SSE (or your WebSocket) events must be coalesced before touching UI state.** `coalesceServerEvents` merges consecutive text/reasoning/tool-input deltas into one, `enqueueServerEvent` collapses repeat `message.part.updated` for the same part, and everything flushes inside a Solid `batch()` on a 16 ms frame with an 8 ms yield back to the event loop. DeskMinis streams token deltas over JSON-RPC notifications; applying each notification straight into a Vue `ref` will pin a CPU core on long outputs. Copy the 16 ms flush + delta-concat design (in Vue, the equivalent is buffering into a plain array and committing inside one `nextTick`/reactive write).
- **Adopt the reconnect + lifecycle handling.** Their stream loop is `while(!aborted && started)` with a 250 ms reconnect delay, a `generation` counter to kill superseded loops, `AbortController` per attempt, `streamErrorLogged` to avoid log spam, and `pagehide`/`pageshow` stop/restart. A WebSocket transport needs exactly this shape, plus their 15-second server-side heartbeat comment to keep intermediaries from closing an idle connection.
- **Adopt: pace the rendering of streamed text.** `createPacedValue` (24 ms tick, 2→256 char step curve, snap to whitespace/punctuation, instant-dump if >512 chars behind) is why their stream looks smooth instead of jittery, and it decouples render cost from token arrival rate. This is ~40 lines and is directly portable to Vue as a composable.
- **Adopt: virtualize the chat timeline from the start, with a row model.** Flattening a session into typed rows (`UserMessage | AssistantPart | Thinking | DiffSummary | TurnDivider | Error | …`) before virtualizing is what lets `@tanstack/*-virtual` measure correctly. `@tanstack/vue-virtual` is the same library. Also copy the per-session measurement snapshot cache so switching tabs doesn't re-measure the whole history, and `content-visibility: auto` on message/tool containers.
- **Adopt the two-registry extension model for M2 (MCP + skills).** `PART_MAPPING[partType]` + `ToolRegistry.register({name, render})` with alias fallback and a generic `mcp`-icon default means an unknown MCP tool still renders sensibly instead of crashing. DeskMinis will get arbitrary MCP tools in M2 — design the tool-call component as a registry lookup with a *good* default now, not a `v-if` chain over known tool names.
- **Adopt the deferred-mount trick for heavy tool bodies.** `BasicTool`'s global rAF queue mounts default-open tool contents bottom-first (nearest the viewport, since chat starts scrolled to the latest turn). Without this, opening a session with 50 expanded diffs blocks the first paint.
- **Adopt: approval prompts as an inline dock above the composer, not a modal dialog.** `session-permission-dock.tsx` keeps the user in context, shows the concrete `patterns` being requested as monospace code, and offers exactly three actions in a fixed order (Deny / Allow always / Allow once) with a `responding` disabled state. DeskMinis' permission gateway should present the same three-way choice — a binary allow/deny forces users into either fatigue or over-permissioning.
- **Adopt the permission-reply de-dup and TTL.** Their `responded` Map (cap 1000, 1-hour TTL) prevents double-replying to the same request id when events replay after a reconnect — an inevitable bug once you add reconnection. Also copy the idea that auto-accept is *persisted separately per server scope* (`permission.v3`) and keyed by session+directory, and that auto-accept for a child session must resolve session lineage first.
- **Adopt a real design-token layer before writing Vue components.** Two files bought them 37 themes: a primitive ramp file (grey 50→1200, alpha-dark/light 0→100, 8 hue ramps 100→1200) and a semantic alias file (`bg-base/bg-layer-01..04`, `text-base/muted/faint`, `border-muted/base/strong/focus`, `state-{bg,fg,border}-{success,warning,danger,info}`, `elevation-raised/floating/overlay`). Components reference *only* semantic names. DeskMinis' pending 'UI 重设计' task should start here — the literal values in this report are directly usable as a starting palette.
- **Adopt named typography classes over ad-hoc utilities.** `.text-12-regular / .text-14-medium / .text-16-medium / .text-20-medium` (13/14/16/20 px, weights 400/500, line-heights 150%/180%) bundle family+size+weight+leading+tracking into one token. This is the single highest-leverage consistency rule for a Vue app, and it needs no framework.
- **Adopt the `data-component` / `data-slot` / `data-variant` styling contract.** Plain co-located CSS files keyed off data attributes (not utility-class soup, not CSS-in-JS) means the markup stays readable, themes can restyle anything from outside, and Vue SFC `<style>` blocks map onto it 1:1. Their `@layer theme, base, components, utilities` declaration is worth copying verbatim to make override precedence predictable.
- **Adopt the FOUC-prevention pattern for theming.** Cache the resolved theme CSS in localStorage, inline a tiny sync script into `index.html` at build time that re-applies it plus `data-theme`/`data-color-scheme` before first paint, and separately have the renderer push the computed `--background-base` to main via IPC so the native `BrowserWindow` background matches. Without the last step, every window resize and every cold start flashes white on a dark theme.
- **Adapt: compute the initial native background color in the main process.** `windows.ts` imports the default theme JSON and runs `resolveThemeVariant()` in main so the very first `new BrowserWindow({backgroundColor})` is already correct. That requires the theme resolver to be plain, dependency-free TS — a good constraint to keep for DeskMinis' token layer.
- **Adopt the crash/hang recovery dialog.** Hooking `unresponsive`, `render-process-gone`, `did-fail-load`, and `preload-error` to a native message box offering Relaunch / Export Logs / Keep Waiting turns 'the app froze' into an actionable bug report. `exportDebugLogs()` + a per-window unresponsive sampler is maybe 300 lines and pays for itself the first week of real users.
- **Adopt for Windows packaging**: electron-builder with `target:['nsis']`, `oneClick:true`, `perMachine:false` (no admin prompt, per-user install), `verifyUpdateCodeSignature:false`, signing shelled out to a PowerShell script and only enabled in CI. Channel-per-appId (`ai.opencode.desktop.dev|.beta|prod`) lets dev/beta/prod coexist on one machine with separate `userData` — invaluable while DeskMinis is pre-1.0.
- **Adapt: keep the UI layer in a separate package from the Electron shell.** OpenCode's desktop package is only ~4,500 lines because 100% of the interface lives in `packages/app`, which also builds as a plain browser SPA. That forced discipline — everything native goes through an injected `Platform` object — is exactly what would let a future DeskMinis web/mobile client reuse the Vue app. If DeskMinis' Vue UI currently lives inside the Electron package, splitting it out and injecting a `Platform` abstraction is the structural change with the longest payoff.
- **Adopt Storybook with stories co-located next to components.** ~35 `*.stories.tsx` sit beside their components with `@storybook/addon-a11y` enabled. For the planned DeskMinis UI redesign this is how you iterate on tool-call rows, diff views and permission docks without booting minisd and driving a real agent turn.
- **Avoid: don't ship two parallel token systems.** OpenCode is mid-migration and now carries both a legacy semantic layer (`--surface-raised-stronger`, `--text-on-critical-weak`, ~26 KB of `theme.css`) and the newer `--v2-*` layer, with bridge hacks like `"text-diff-add-base": "var(--v2-state-fg-success)"` in `oc-2.json` and duplicate `--gray-dark-1` definitions inside a single `:root` block in `colors.css`. Pick one naming system for DeskMinis and commit.
- **Avoid: don't leave dead framework abstractions in place.** `[data-tauri-drag-region]` and `window.__TAURI__` checks still drive drag regions and window controls months after the Electron port. If DeskMinis renames or re-platforms anything, rename the attributes too — future contributors will otherwise assume Tauri support exists.
- **Avoid: don't put a 2,662-line `message-part.tsx` or a 1,865-line `message-timeline.tsx` at the center of the app.** These are the highest-churn, highest-risk files in the repo. DeskMinis should split per-part-type components into separate files behind the registry from the start — the registry pattern makes that free.
- **Note the deliberate transport split**: HTTP request/response + SSE for everything except PTY, which uses WebSocket. DeskMinis chose JSON-RPC over one WebSocket for everything, which is a defensible simplification (one connection, one auth, bidirectional by default) — but it means you own backpressure, ordering, and reconnect-replay semantics yourself. Their SSE `subscriberCapacity = 256` bounded buffer and 15 s heartbeat are the two concrete details worth porting to your WS server.

## Open questions
- `@opencode-ai/client` is a vendored tarball (`packages/app/vendor/opencode-ai-client-1.17.13-v2.tgz`), so I could not read the generated SSE client / `event.subscribe` implementation or confirm whether it does Last-Event-ID replay on reconnect. The app-side reconnect loop just restarts the stream with no cursor, which suggests missed events are recovered by a full session re-sync (`sync().session.sync(id, {force:true})`) rather than by event replay — I could not verify this end-to-end.
- `packages/desktop/native/` (referenced by `extraResources` as `mac_window.node` + `swift-build/**` and by the `native:build` script) is not present in the clone, so the macOS-only native window customizations are unverified.
- `packages/ui/src/theme/v2/mapping.ts` (9.7 KB) and `v2/resolve.ts` define how arbitrary theme seeds are projected onto the `--v2-*` semantic names; I read the outputs and the primitives but did not trace the full mapping algorithm, so I can't state exactly which v2 tokens are derived vs. always fixed.
- There is a `newLayoutDesigns()` settings flag gating a `layout-new.tsx` / `pages/session/v2/` / `settings-v2/` code path alongside the legacy layout. Both exist in the tree; I did not determine which is the shipping default in v1.18.5, so some component paths cited (v2 vs non-v2) may not be what users actually see.
- The desktop `README.md` and `electron.vite.config.ts` reference `../opencode/dist/node` (built by `packages/opencode/script/build-node.ts`) as the sidecar bundle; I did not inspect that build script, so how the Bun-authored core is bundled to run under Electron's Node (and how the `.wasm` assets are handled beyond the copy plugin) is unverified.
- No evidence was found in the desktop package of mDNS/LAN peer discovery or a PortableRecord-style sync format — remote servers are added manually by URL, by WSL distro, or by SSH host. If DeskMinis M3 needs a discovery reference, OpenCode is not it.
