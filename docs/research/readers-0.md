# OpenMinis chat-session persistence, agent context management, and iCloud sync (iOS Swift + Android Kotlin)

## Key findings
- iOS persistence is a hand-rolled SQLite layer (raw sqlite3 C API inside a Swift actor): C:/Users/24739/Downloads/openminis1/OpenMinis/src/ios/Agent/Chat/ChatStore.swift (6211 lines). DB file Library/MinisChat/minis.db; per-session media/workspace files under Library/MinisChat/minis/<sessionId>/. Core tables created at lines 442-755: sessions(id TEXT PK, title, model_id, created_at REAL, updated_at REAL + migrated columns category, model_binding, source, memory_enabled, last_synced_at, remote_origin_device_id, pinned_at, remote_tombstoned_at), messages(id TEXT PK, session_id FK, role TEXT, parts_json TEXT, created_at REAL, token_usage TEXT, sort_order INTEGER + migrated reasoning_content, stream_interrupt_count, updated_at, error_info, part_flags), compact_markers, plus sync tables (sync_dirty_records, sync_pushed_records, deleted_session_tombstones, deleted_record_tombstones, sync_devices, remote_sessions/remote_messages/remote_media/remote_skills/remote_memories/remote_provider_configs/remote_env_vars).
- One DB row = one turn: RawMessage {id(UUID string), sessionId, role user|assistant, parts:[ContentPart], createdAt, tokenUsage, reasoningContent, streamInterruptCount, sortOrder, errorInfo} — ChatStore.swift lines 286-350. Tool calls and results are NOT separate tables; they are ContentPart entries inside the turn's parts_json.
- ContentPart is a tagged-union JSON: {"type":"text|mediaRef|toolUse|toolResult","value":...} (ChatStore.swift lines 179-231). ToolUse={toolUseId,name,input(JSON-string args),description,thoughtSignature(Gemini)}. ToolResult={toolUseId,output,success,mediaRef,snapshot{type:text|image,text,mediaRef,duration},pageURL(truncated<=512),status:'success|failed|cancelled'}. MediaRef={id,relativePath (under Library/MinisChat/minis/<sid>/),mimeType,originalFileName,linuxPath (/var/minis/... mirror)}.
- Android mirrors the exact same schema via Room (version 10): C:/Users/24739/Downloads/openminis1/OpenMinis/src/android/app/src/main/java/com/openminis/app/data/db/AppDatabase.kt, MessageEntity.kt, ChatSessionEntity.kt, CompactMarkerEntity.kt. Same column names (parts_json, sort_order, reasoning_content, stream_interrupt_count, error_info) but timestamps are epoch-milliseconds Long vs iOS epoch-seconds REAL. partsJson wire format is byte-compatible with iOS via kotlinx.serialization ContentPartSerializer in data/model/ContentPart.kt ({type, value} discriminator, ignoreUnknownKeys).
- UI messages are ephemeral: ChatMessage/AssistantBlock in src/ios/Agent/Chat/ChatModels.swift are view-models rebuilt from RawMessage rows on load (consecutive assistant + tool-result turns folded into one bubble; sourceSortOrder/lastSourceSortOrder track the raw-row range). Nothing UI-level is persisted. In-flight agent history uses AgentMessage (src/ios/Providers/AgentProvider.swift:101) carrying dbMessageId back-links to persisted rows, plus in-memory-only ReasoningEcho for OpenAI Responses encrypted reasoning items (deliberately never persisted).
- Context-window management is tiered by model window (identical on both platforms): src/ios/Agent/Chat/ContextPolicy.swift and src/android/.../data/ContextPolicy.kt — <32K: nothing (prompt 'start new'); 32-64K: auto-offload when remaining<=10K; 64-128K: offload@-20K + auto-compact@-10K; >=128K: offload@-40K + compact@-20K.
- Compaction (summarization): src/ios/Agent/Chat/AIChatViewModel+Compaction.swift — an LLM-generated summary is stored as a compact_markers row; v2 marker model anchors ONLY on last_compacted_message_id (message id, not sort_order, because synced sessions can duplicate sort_order); everything before the anchor is replaced by the summary in the agent history; last 3 user turns kept verbatim (compactKeepRecentUserTurns=3). Markers self-heal by createdAt if the anchor id is orphaned by sync. Markers sync cross-device (CompactMarkerV2, conflictPolicy alwaysAccept).
- Truncation/offload of big tool outputs: content is written to per-session files (Android: filesDir/minis-sessions/<sid>/offloads/tools/<toolName>_<last12-of-toolUseId>.<ext>, iOS mirror), exposed in the Linux sandbox at /var/minis/offloads/tools/..., and the in-history part is replaced with the stub '[CONTEXT OFFLOADED] Content (~N tokens, N bytes) saved to: <linux-path>\nUse file_read tool to retrieve if needed.' — format deliberately identical across platforms so sessions round-trip via sync (src/android/.../data/ContextOffload.kt, src/ios/Agent/Chat/AIChatViewModel+RequestBudget.swift). A separate per-request 25MB image budget elides oldest images into text placeholders pointing at spillover files attachments/spillover/<sha1>.<ext>.
- iCloud sync v2 (iOS only) is layered: transport-neutral PortableRecord {SyncRecordID(type:id), fields:[String:PortableFieldValue(null/string/int/double/bool/date/data/json)], assets:[PortableAsset], schemaVersion, minimumCompatibleVersion, unknownFields (unrecognized wire fields round-tripped so old clients don't destroy new-client data), updatedAt} — src/ios/Agent/Sync/V2/PortableRecord.swift. SyncCore.swift is the transport-agnostic dispatcher (dirty queue in sync_dirty_records with priority 0=user/1=migration-backlog, 3s debounce, fg/bg/cellular throttling); transports: ICloudSharedZoneTransport.swift (CKSyncEngine) and LANTransport.swift.
- What syncs for sessions (src/ios/Agent/Sync/V2/SyncedTypes.swift): SessionV2 (title/category/modelId/timestamps/memoryEnabled/modelBinding/pinnedAt), MessageV2 (partsJson as a string field, tokenUsageJson, reasoningContent, streamInterruptCount, sortOrder-as-hint, createdAt/updatedAt), CompactMarkerV2, SessionFileV2 (per-session workspace files as assets; changes detected by SessionFileChangeTracker.swift fed from iSH fakefs kernel events), SkillV2, SoulV2 (SOUL.md), MemoryGlobalV2 (GLOBAL.md), MemoryDailyV2 (per-day JSON entry arrays, set-union merged by timestamp), SyncDeviceV2 heartbeats; provider configs/env vars/MCP servers as separate per-record types in a secrets zone. Device-local columns error_info and part_flags are intentionally NOT synced.
- CloudKit topology: container iCloud.com.openminis.app with three FIXED shared zones (not per-device — that was v1): minis-shared (sessions/messages/markers/files/skills/memory), minis-devices (heartbeats), minis-secrets (provider configs, env vars, MCP servers) — ICloudSharedZoneTransport.swift lines 30-75. Payloads >750KB become CKAsset, else inline CKRecord string. Conflict resolution is per-record last-write-wins by updatedAt for almost all types.
- Inbound merge rules (ChatStore.mergeRemoteMessage, ChatStore.swift:5410): LWW by updated_at (falls back to created_at); merging is DEFERRED while the session is actively streaming locally; sender's sortOrder is only a hint — the receiver always re-derives sort_order from (created_at ASC, id ASC) rank; deleted_session_tombstones / deleted_record_tombstones (30-day TTL) block resurrection of just-deleted records that CloudKit's query-based fetch would otherwise re-deliver.
- Backup (distinct from sync): src/ios/Agent/Sync/ICloudBackupManager.swift zips WAL-checkpointed minis.db + media/ + per-session minis/ workspace (and skills.db + skills/ + memory/) into iCloud Drive Documents/backups/<deviceName>/<category>_<timestamp>.zip.
- Session forking: src/ios/Agent/Session/SessionForkManager.swift deep-copies a remote device's session (new message ids, remaps compact-marker message-id references through the old-id→new-id copy map, skips markers with dangling references). Android has SessionForkManager.kt in data/.
- Android has NO cloud sync engine — no CloudKit analogue, no dirty queue; the Room schema and JSON formats are kept in ('iOS parity') lockstep so session data is portable, but cross-device sync is currently an iOS-only feature. Grep for sync in Android hits only UI/terminal code.
- A debug seeding fixture shows a simpler portable session-dump shape: src/ios/Debug/TestData/travel-planning-session.json — array of {created: ISO8601, role, parts:[{type:'text',text:...}], usage:{input_tokens,output_tokens,cache_creation_tokens,cache_read_tokens}}.

## Data formats
- SQLite (iOS: raw sqlite3, DB at Library/MinisChat/minis.db, timestamps REAL epoch-seconds; Android: Room v10, timestamps INTEGER epoch-milliseconds). Key table: messages(id, session_id, role, parts_json, created_at, token_usage, sort_order, reasoning_content, stream_interrupt_count, updated_at, error_info, part_flags)
- parts_json — JSON array of tagged-union content parts, e.g. [{"type":"text","value":"hi"},{"type":"toolUse","value":{"toolUseId":"toolu_01...","name":"shell","input":"{\"cmd\":\"ls\"}","description":null,"thoughtSignature":null}},{"type":"toolResult","value":{"toolUseId":"toolu_01...","output":"...","success":true,"mediaRef":null,"snapshot":{"type":"text","text":"last lines","duration":1.2},"pageURL":null,"status":"success"}},{"type":"mediaRef","value":{"id":"...","relativePath":"<sid>/browser/x.png","mimeType":"image/png","linuxPath":"/var/minis/browser/..."}}] — identical bytes on iOS (Codable) and Android (kotlinx.serialization)
- token_usage column — JSON {inputTokens, outputTokens, cacheCreationTokens, cacheReadTokens, latestContextTokens?} (StoredTokenUsage)
- PortableRecord (sync wire model) — {id:{type:'MessageV2',id:uuid}, fields:{name:{t:'string|int|double|bool|date|data|json', v:...}}, assets, schemaVersion, minimumCompatibleVersion, unknownFields, updatedAt}; mapped to CKRecord fields; >750KB payloads become CKAsset files
- Offload stub text protocol — '[CONTEXT OFFLOADED] Content (~N tokens, N bytes) saved to: /var/minis/offloads/tools/<name>_<toolId12>.<ext>' with real bytes on disk at minis-sessions/<sid>/offloads/tools/; image spillover at attachments/spillover/<sha1-hex>.<ext>
- Markdown memory files synced whole-file: SOUL.md (SoulV2), GLOBAL.md (MemoryGlobalV2); MemoryDailyV2 = per-day record id 'YYYY-MM-DD' with entriesJson = JSON [MemoryEntry{timestamp,content}], set-union merge
- Zip backups — Documents/backups/<deviceName>/<sessions|skills-memories|full>_<timestamp>.zip containing minis.db (WAL-checkpointed) + media/ + minis/ workspace trees
- Debug session fixture JSON — [{created: ISO8601, role, parts:[{type,text}], usage:{input_tokens,...}}] (src/ios/Debug/TestData/travel-planning-session.json)

## Reusable for desktop
- Adopt parts_json as the canonical cross-platform message format: one row per turn, role user|assistant only, tool calls (toolUse) and tool results (toolResult) as tagged content parts inside the turn — already proven to round-trip identically between Swift Codable and kotlinx.serialization; an Electron port can implement the same tagged union in TypeScript with zero migration for synced sessions
- Sync-friendly ordering rule: sort_order is device-local and derived from (created_at ASC, id ASC) rank; the wire value is only a hint. This avoids cross-device ordering corruption and is directly reusable for any sync backend (the desktop app should re-rank on insert exactly like ChatStore.mergeRemoteMessage)
- PortableRecord abstraction: transport-neutral records with typed fields, unknownFields round-trip (old client preserves new client's fields), per-type schemaVersion + minimumCompatibleVersion escape hatch, and per-record LWW by updatedAt. A desktop port could implement a new SyncTransport (e.g. WebDAV/S3/custom server) against this exact model; LANTransport.swift already demonstrates a non-CloudKit transport
- Separate what syncs from what doesn't: device-local columns (error_info, part_flags, cache-ish data) excluded from the wire; secrets in a separate zone/category so users can disable secret sync without losing chat sync
- Delete-resurrection tombstones (deleted_session_tombstones / deleted_record_tombstones with 30-day TTL) — needed by any query-based sync backend where deletes propagate asynchronously
- Compact-marker design: keep ALL raw messages, never destructively truncate; store an LLM summary row anchored to a message id (v2 id-only model), rebuild effective agent history at request time (summary + anchor tail + last 3 verbatim user turns). Markers sync as ordinary records, and forking remaps anchor ids through the copy map
- Context offload pattern: replace large tool outputs/images in history with a stable stub pointing to a workspace-relative file path the model can re-read via file_read/read_image; keep the path layout platform-agnostic (offloads/tools/<name>_<toolId12>.<ext>, attachments/spillover/<sha1>.<ext>) so sessions stay executable after sync to another device — a Windows port only needs to reproduce the /var/minis/* virtual mount mapping
- Tiered ContextPolicy by model window size (offload threshold, compact threshold, exhausted-only for tiny windows) — a small pure function, trivially portable
- Dirty-queue architecture: mark-dirty rows in the same DB transaction as the write, debounced push (3s), priority lanes so migration backlogs never starve fresh user messages, throttling by app state/network — all backend-agnostic
- Per-session workspace as first-class synced data: session files tracked by filesystem change events and synced as assets (SessionFileV2), so the agent's working directory travels with the conversation — highly relevant for a desktop agent with a real filesystem
- Zip-based full backup (WAL-checkpointed DB + workspace trees) as a separate, simpler recovery path orthogonal to record-level sync

## Open questions
- Android has no sync engine in the repo despite comments referencing 'cloud sync' cross-platform round-trips — is Android sync planned via a port of SyncCore/PortableRecord (transport TBD, since CloudKit is unavailable), or is portability limited to manual backup/restore today?
- Legacy v1 CloudSyncEngine.swift (per-device zones, remote_* mirror tables) still ships alongside v2 — how long must a desktop port support inbound v1 records, or can it target v2-only (SessionV2/MessageV2/...)?
- CompactMarkerV2 uses conflictPolicy .alwaysAccept (not LWW) — concurrent compaction on two devices could produce multiple overlapping markers; the resolution behavior for that case wasn't traced
- iOS ContentPart.toolUse includes thoughtSignature and ToolResult includes snapshot/pageURL/status, but Android's ContentPart.kt omits thoughtSignature and snapshot/pageURL/status (ignoreUnknownKeys tolerates them) — a desktop port should implement the iOS superset
- Exact CKRecord field-name mapping and asset naming (partsAsset etc.) beyond the 750KB threshold was not exhaustively extracted from ICloudSharedZoneTransport.swift (1817 lines)
