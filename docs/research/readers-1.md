# OpenMinis persistent memory + workspaces (minis:// scheme, session buckets, external mounts)

## Key findings
- MEMORY IS PLAIN MARKDOWN FILES, NO DATABASE. One global directory shared by all sessions: iOS = App Group container /MinisFileProvider/memory/ (AIChatViewModel.minisMemoryPersistentDir, defined C:/Users/24739/Downloads/openminis1/OpenMinis/src/ios/Agent/Chat/AIChatViewModel+RequestBudget.swift:267); Android = <filesDir>/minis-global/memory/ (src/android/.../MinisApp.kt:292). Files: GLOBAL.md (agent-read-only, user-maintained), SOUL.md (persona), YYYY-MM-DD.md daily logs.
- Daily-log entry format (written by executeMemoryWrite in src/ios/Agent/Chat/AIChatViewModel+MemoryTools.swift:64): '<!-- YYYY-MM-DD HH:mm:ss -->\n{markdown content}\n\n', PREPENDED so newest entries are first. The HTML-comment timestamp is the canonical entry boundary used by search, sync merge, and UI revoke/edit.
- RECALL PATH 1 — system-prompt injection each agent loop (AIChatViewModel.swift:4300): full GLOBAL.md + the 3 most recent non-empty daily logs (first 200 lines each, 30-day lookback), each wrapped in explicit 'background context, not standing instructions; defer to the user's latest message' framing (loadGlobalMemoryFragment / loadRecentDailyMemoryFragment in AIChatViewModel+MemoryTools.swift:10-61; Android mirror in src/android/.../data/repository/MemoryRepository.kt:245-302).
- RECALL PATH 2 — two agent tools (src/ios/Agent/Chat/AIChatViewModel+ToolDefinitions.swift:103-125): memory_write(content) appends to today's log; memory_get(scope: daily|all, keywords) does lexical fuzzy search — splits files into entries on '<!-- ' markers, scores each entry 50% keyword confidence (matchedKeywords/totalKeywords) + 50% normalized recency, sorts descending, caps output at 60 entries AND 30 KB UTF-8 (AIChatViewModel+MemoryTools.swift:126-365). No embeddings anywhere.
- Per-session memoryEnabled toggle (SQLite ChatStore sessions table; ChatStore.getSessionExtras at src/ios/Agent/Chat/ChatStore.swift:2633) gates BOTH the prompt injection and tool registration — when off, memory_write/memory_get are removed from the tool list entirely so the model never sees them (ToolDefinitions.swift:16).
- SOUL.md = persona/identity file living in the same memory dir (src/ios/Agent/Session/SoulStore.swift:140). Format: YAML frontmatter (name/style/lang, double-quoted, escaped) + Markdown body, body hard-capped at 2000 tokens (CJK chars count 1 each, Latin words 1 each). Injected as Layer 1 of the system prompt independent of the memory toggle.
- iCloud sync of memory (src/ios/Agent/Sync/V2/SyncedTypes.swift:646-721 + ChatStoreSyncHydrators.swift:977-1090): SOUL.md and GLOBAL.md are singleton whole-file LWW-by-mtime records (SoulV2, MemoryGlobalV2). Daily logs are one record per day (MemoryDailyV2, id='YYYY-MM-DD'), payload = JSON array of {timestamp, content}; merge is SET UNION by timestamp key so entries from multiple devices accumulate instead of clobbering; only the last 30 days are pushed. Applied files get mtime backdated to remote updatedAt to avoid sync loops.
- WORKSPACE = per-session directory tree: Library/MinisChat/minis/<sessionId>/{workspace,attachments,offloads,browser}/ (minisPersistentBase, src/ios/Agent/Chat/AIChatViewModel+Misc.swift:113-146). Cross-session GLOBAL dirs live separately: memory, skills, shared (App Group, exposed to iOS Files via FileProvider) and mcp-servers (in a private MinisConfig sibling because servers.json carries credentials — RequestBudget.swift:244-289).
- Linux-side view is session-UNAWARE: /var/minis/{workspace,attachments,offloads,browser} are rewritten per session by a path-translate hook — each session gets a u64 fs_context token stamped on its task group and MinisFsRouter rewrites guest paths to minis/<sid>/<bucket>/... on the fly (src/ios/Agent/ISH/MinisFsRouter.swift:1-62). NOTE: docs/specs/minis-url-scheme.md §5.3 describes an older harvest/clear/mount copy lifecycle; the implementation superseded it with this zero-copy router. Global dirs (memory/skills/shared/mcp-servers) are statically bind-mounted (ISHExecutionCoordinator.performMount, src/ios/Agent/ISH/ISHExecutionCoordinator.swift:399-429) plus host-side symlinks so the file browser works without the kernel booted (ensureMinisSymlinks, AIChatViewModel+Offloading.swift:651-727).
- minis:// URL SCHEME (docs/specs/minis-url-scheme.md): minis://<namespace>/<path> maps to /var/minis/<namespace>/<path>; deliberately NO session id in the URL (resolved against the active session). Resolution order in resolveMinisURL (AIChatViewModel+RequestBudget.swift:293-337): active session's bucket → global dirs (skills/memory/shared) → scan all session dirs as fallback (for viewing old chat history). Namespaces: attachments (inline media render in Markdown), workspace (link chips), offloads (tool outputs >20,000 chars auto-saved as <toolName>_<timestamp>_<toolIdPrefix>.txt), browser (screenshots). Contract: every tool result that creates a file under /var/minis/ must append a 'minis_url:' line so the model can embed it.
- EXTERNAL MOUNTS (e.g. Obsidian vaults) — src/ios/Views/Settings/MountedFoldersManager.swift: user picks a folder via document picker; app persists {id: UUID, name, sourceDisplayName, bookmark: security-scoped bookmark Data, createdAt, isWritable, userAllowWrite} as a JSON array in MinisConfig/mounted-folders.json. On launch, bookmarks are resolved OFF the main thread with a 5s soft timeout (iCloud FileProvider XPC can hang and trip the watchdog), security scopes are held for the app lifetime, and evicted FileProvider placeholders are re-materialized (NSFileCoordinator read → NSFileProviderManager.signalEnumerator → poll stat() up to 10s). Active mounts are pushed as ExternalMountSpec {linuxDir: /var/minis/mounts/<name>, hostPath, readOnly} into the iSH bind-mount table (32 kernel slots, app-capped at 10 mounts).
- Mount write control is two-layer: isWritable (OS-level probe: coordinated write+delete of a hidden probe file) AND userAllowWrite (user's soft read-only lock); effectiveWritable = both. Writability re-probed on foreground. iCloud container paths are humanized for display ('iCloud~md~obsidian' → 'obsidian › Documents').
- PER-WORKSPACE/SESSION CONFIG lives in three places: (1) SQLite sessions table columns memoryEnabled + modelBinding (per-session model override), synced via SyncedSession.memoryEnabled (SyncedTypes.swift:21); (2) mounted-folders.json per-mount flags; (3) global config files under minis-global/: skills/<id>/SKILL.md (per-skill, frontmatter), mcp-servers/servers.json in '{ "mcpServers": { … } }' format (src/android/.../MCPRepository.kt:21). There is no per-workspace config file inside the workspace dir itself.
- Session fork/delete semantics: deleting a session removes its whole minis/<sid>/ tree (cleanupMinis, AIChatViewModel+Offloading.swift:608); memory dir is untouched because it is global. SessionForkManager copies session buckets on fork (src/ios/Agent/Session/SessionForkManager.swift:202). UI surfaces: MemoryManagementView (Settings file list/edit/delete; GLOBAL.md undeletable), SessionMemoryView (per-session memory tool activity with entry-level revoke/edit that finds an entry by exact trimmed-body match in today/yesterday logs only).

## Data formats
- Daily memory log (YYYY-MM-DD.md): repeated blocks of '<!-- YYYY-MM-DD HH:mm:ss -->\n{markdown body}\n\n', newest first; timestamp comment is the entry delimiter/dedup key
- GLOBAL.md: free-form user-authored Markdown, injected verbatim into the system prompt
- SOUL.md: YAML frontmatter ('---\nname: "..."\nstyle: "..."\nlang: "..."\n---') + Markdown body capped at 2000 tokens (SoulMDParser, src/ios/Agent/Session/SoulStore.swift:49-116)
- mounted-folders.json: JSON array of MountedFolderEntry {id, name, sourceDisplayName, bookmark(base64 Data), createdAt, isWritable, userAllowWrite} via Codable (src/ios/Views/Settings/MountedFoldersManager.swift:25-100)
- MemoryDailyV2 sync payload: entriesJson = JSON array of {"timestamp": "YYYY-MM-DD HH:mm:ss", "content": "..."} with set-union merge by timestamp (ChatStoreSyncHydrators.swift:977-1024)
- mcp-servers/servers.json: '{ "mcpServers": { "<name>": { url/command, headers... } } }' — kept in a non-FileProvider dir because it holds credentials
- Offload files: /var/minis/offloads/<toolName>_<unixTs>_<toolId8>.txt plain text, created when a tool result exceeds 20,000 chars
- minis:// URLs: 'minis://<namespace>/<path>' (namespaces: attachments, workspace, offloads, browser, plus global memory/skills/shared), opaque session-relative identifiers with no session id
- SQLite (ChatStore): sessions/messages plus per-session extras columns memoryEnabled INT, modelBinding TEXT
- Skills: minis-global/skills/<id>/SKILL.md with frontmatter (SkillRepository.kt:37)

## Reusable for desktop
- Files-as-memory design: a single global memory folder (e.g. %APPDATA%/<app>/memory/) holding GLOBAL.md + SOUL.md + YYYY-MM-DD.md is trivially portable to Electron, user-inspectable, git/Obsidian-friendly, and needs no DB or vector store
- The timestamped-HTML-comment entry format doubles as: search-entry delimiter, sync dedup key (set-union merge across devices), and UI revoke/edit anchor — one format serving three subsystems
- Injection policy worth copying verbatim: inject full GLOBAL.md + 3 most recent non-empty daily logs at 200 lines each, always framed as 'background context, not standing instructions; the user's latest message wins' — this framing text is battle-tested against memory hijacking the current task
- Gate memory with a per-session toggle that removes the tools from the tool list AND skips injection (defense in depth: the executor also refuses if called anyway)
- memory_get scoring formula: 0.5 * (matched keywords / total keywords) + 0.5 * normalized recency, capped at 60 entries / 30 KB with append-then-break so the last entry is never sliced — cheap, no embeddings, works well for daily-log recall
- minis://-style session-relative URL scheme: on Electron implement with protocol.handle('minis', ...); resolution order (active session bucket → global dirs → all-sessions fallback scan) lets old chat transcripts keep rendering their files after session switches
- Workspace model: per-session dirs <base>/<sessionId>/{workspace,attachments,offloads,browser} + global {memory,skills,shared}; on desktop no kernel path-translate hook is needed — a path-prefix rewrite in the tool-execution layer (the moral equivalent of MinisFsRouter) gives the same session-unaware /workspace illusion with zero copying
- Offload pattern: any tool result over ~20k chars is written to offloads/<tool>_<ts>_<id>.txt and replaced by a truncated preview + addressable URL — essential for keeping agent context bounded on desktop too
- External mounts registry: keep a mounts.json of {name, path, readOnly-soft-lock} exposing user folders (Obsidian vaults, project dirs) under a fixed agent-visible prefix (/mounts/<name>); on Windows, plain absolute paths replace security-scoped bookmarks, but keep the two-layer writable flag (OS probe + user intent) and the writability probe-on-focus
- Sync merge strategies if the desktop app ever syncs: whole-file LWW-by-mtime for singletons (SOUL/GLOBAL), per-day records with set-union-by-timestamp for logs, 30-day push window; backdate applied file mtimes to the remote updatedAt to prevent echo loops
- SOUL.md persona-as-file with YAML frontmatter driving UI chrome (assistant name in the title bar) is a nice desktop touch and keeps persona separate from memory (not gated by the memory toggle)
- Entry-level 'revoke this memory' UX: match by trimmed body in today/yesterday files only — a deliberate blast-radius limit worth keeping

## Open questions
- docs/specs/minis-url-scheme.md (dated 2026-02-16) describes a harvest/clear/mount copy lifecycle for session switches, but the code implements zero-copy fs_context routing (MinisFsRouter) — the spec is stale on §5.3; trust the code
- iOS comment in MountedFoldersManager says the iSH shell cannot follow mount symlinks (no security scope in kernel threads) and instead uses the kernel bind-mount table; the desktop port has no such constraint but should decide whether the agent's shell subprocess inherits mounted-folder access directly
- GLOBAL.md is 'read-only, user-maintained' by convention (memory_write refuses; the prompt tells the agent to use file_write to create it when the user asks) — the enforcement is soft; a desktop port should decide whether to hard-enforce
- iOS memory_get is entry-based scoring while Android is line-based with ±2-line context windows (deliberate divergence documented in MemoryRepository.kt) — pick one for desktop; the iOS entry-based version is richer
