## Reusable for desktop
- Single-method provider interface: the entire provider contract is one streaming call (messages, systemPrompt, tools, maxTokens, thinkingLevel) → AsyncIterable of a unified event enum; retry, fallback, tool execution, persistence all live above it. Direct TS analog: `interface AgentProvider { streamAgentMessage(req): AsyncIterable<AgentStreamEvent> }` — this kept 8+ vendors behind one seam
- Unified AgentStreamEvent vocabulary including toolInputDelta(accumulated) for live tool-arg preview, thinkingDelta vs reasoningContent (display vs echo-back) separation, and a distinct `refusal` stop reason so deterministic declines never enter retry loops
- Three-layer error handling with a typed taxonomy: transparent connect-phase retries confined to pre-first-byte (never mid-stream, avoids duplicated content), visible countdown auto-retry [3,5,10,15,30]s on the same model, then model-group fallback with a user-visible reason trail and binding rewrite. The isRetryable vs isFallbackable split on the error enum is the load-bearing design
- Model groups + ModelGroupRouter: user-defined ordered fallback chains across heterogeneous vendors, with 'limited' vs 'always' fallback strategies and empty-response cycling — a strong resilience pattern for a desktop agent app
- History self-healing at two altitudes: loop-entry orphan sweep plus provider-boundary heal (inject missing tool_results, strip orphan results, merge consecutive same-role, reorder blocks) — makes strict APIs (Anthropic pairing rules) survivable across crashes/cancels/fallbacks
- Counted agent loop with defer-incremented turn counter + hitTurnLimit flag pattern, compaction iterations not consuming turn budget, and ToolLoopDetector (unknown-tool streak, no-progress circuit breaker, poll thresholds) as a second backstop
- Anthropic cache-breakpoint strategy (tools/system/last-2-user rolling breakpoints so each loop iteration cache-hits the prior prefix) plus the max_tokens:1 keep-alive warmup to hold the cache TTL across idle gaps — directly portable and a large cost lever
- ReasoningEcho design: encrypted/native reasoning payloads kept in-memory only, tagged (providerKind, modelId), replayed only on exact match — clean solution for multi-provider thinking continuity without persisting un-portable blobs
- Tool preflight driven off the same schema published to the model + 3-strategy JSON repair (truncation closures, type coercion, fuzzy field rename) — cheap robustness against small-model tool-call malformations
- Permission model: per-capability bypass/askOnce/notAllowed with continuation-based approval sheet, 30s timeout-to-deny, per-session grants, and denial messages fed back to the model as tool_result errors containing a settings deep link — maps directly to an Electron approval dialog + IPC
- tool_title required-parameter convention: model self-describes every tool call in the user's language for UI pills/status — trivially portable UX win
- Stall watchdog as a race between stream.next() and a 120s sleep; tiered flush throttling by content length; committedBlockCount boundary so retries/fallbacks clear only the uncommitted UI tail; queued user prompts interrupting after the current tool closes and landing as standalone turns
- Request-level image budget (25MB cap, newest-first keep, elided images replaced by placeholders pointing at content-addressed spillover files the model can re-read) and inference-time compact-summary synthesis (effectiveAgentHistory) for context control
- models.dev as the model-capability registry (context window, reasoning support, max output) with bundled fallback + background refresh, plus a small pattern-matching ThinkingLevelCatalog for per-family effort clamps
