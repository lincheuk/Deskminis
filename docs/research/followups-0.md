# OpenMinis MCP integration (guest CLI + native stores + OAuth/PKCE)

## Key findings
- DEFINITIVE: MCP tools are prompt-described + CLI-invoked, never native function-calling tools. iOS makeAgentTools() in src/ios/Agent/Chat/AIChatViewModel+ToolDefinitions.swift registers ONLY shell_execute, file_read, file_write, file_edit, browser_use, plus conditional memory_write/memory_get/read_image — zero MCP tool definitions. The model reaches MCP exclusively by running `minis-mcp-cli ...` through the generic shell_execute tool inside the Linux guest (iSH on iOS, PRoot/Alpine on Android).
- System-prompt disclosure: MCPStore.systemPromptSnippet(for:) at src/ios/Agent/Session/MCPStore.swift:608 discloses ONLY server name + note (note truncated to 200 chars) for the Top-20 enabled-and-not-session-disabled servers, sorted createdAt DESC (most-recently-added first, name asc tiebreak; cap maxMetadataCount=20). Tool names/schemas are NOT in the prompt — the snippet instructs: run `minis-mcp-cli tools <server>` to discover, then `minis-mcp-cli call <server> <tool> [args]` to invoke, plus $$VARNAME env-placeholder guidance. Injected fresh on every request at src/ios/Agent/Chat/AIChatViewModel.swift:4286 and :4652 (no caching — refresh cadence is per-turn). Android mirror: MCPRepository.mcpPromptFragment (src/android/.../data/repository/MCPRepository.kt:442, MAX_MCPS_IN_PROMPT=20, MAX_NOTE_LENGTH=200), injected at ChatViewModel.kt:8095; wording matches iOS verbatim.
- CLI command surface (src/ios/default_mount/usr/local/lib/minis-mcp-cli/main.py, 642 lines; sh wrapper src/ios/default_mount/usr/local/bin/minis-mcp-cli auto-installs python3+httpx via apk/pip then execs main.py): list [--all], tools <server> [--refresh], refresh <server> (alias), info <server>, ping <server>, call <server> <tool> [--input '{}'] [k=v ...], add (--url|--command + --header/--args/--env/--note/--startup-timeout/--oauth-* flags), remove, enable, disable, shutdown, global --pretty. All structured output is single-line JSON on stdout; errors use unified envelope {"error","code","server"} with exit!=0; codes: PARSE_ERROR, NOT_FOUND, DISABLED, TOOL_NOT_FOUND, CONNECTION_ERROR, TIMEOUT, STDIO_CRASH, MCP_ERROR, AUTH_REQUIRED, NO_DAEMON. Diagnostics go only to /var/minis/mcp-servers/mcp-cli.log.
- CLI architecture: list/tools/ping/call go through a self-forked background daemon (src/.../minis-mcp-cli/daemon.py, 490 lines) that keeps MCP sessions warm: per-server 10-min idle TTL (TTL_SECONDS=600), 60s empty-pool exit grace, IPC = newline-delimited JSON over 127.0.0.1 loopback TCP with ephemeral port published in /tmp/minis-mcp-daemon.port (AF_UNIX impossible under iSH fakefs), pid file /tmp/minis-mcp-daemon.pid, cold-start fork lock /tmp/minis-mcp-daemon.lock. info/add/remove/enable/disable are pure-local servers.json edits. STDIO_CRASH/TIMEOUT get one evict+respawn retry (MCPPool.call_with_retry).
- Transports: transport/stdio.py spawns command+args with env (parent env merged with $VAR-expanded server env), newline-delimited JSON-RPC 2.0 over stdin/stdout, protocolVersion 2025-06-18, clientInfo minis-mcp-cli/1.0.0, 300s RPC timeout, per-server startupTimeoutSeconds (default 60, max 900, aliases startup_timeout_sec/startupTimeout/handshakeTimeout/initializeTimeout read in priority order — utils/config.py). transport/http.py is MCP Streamable HTTP: single POST per RPC to server url; parses either application/json or text/event-stream body (takes last data: line that parses); forces Accept: application/json, text/event-stream and Content-Type: application/json (dropping any user case-variant); echoes Mcp-Session-Id response header back on subsequent requests; initialize -> notifications/initialized -> tools/list | tools/call per connection. There is NO long-lived GET SSE stream — SSE is only a response-body encoding.
- Header/credential injection: $VAR, ${VAR}, $$VAR, $${VAR} in url/headers/env values expand from the guest process environment (regex in transport/http.py:29, expand_env); UI emits $$VAR form. For OAuth servers, the Authorization header is overridden with 'Bearer <access_token>' read from the token bridge file /var/minis/mcp-servers/oauth/<server>.json — the bridge always wins over static headers (http.py:_post).
- servers.json exact field set (path guest:/var/minis/mcp-servers/servers.json; iOS host: MinisConfig persistent dir via MCPStore.syncFileURL; Android host: files/minis-global/mcp-servers/servers.json). Shape: {"mcpServers": {"<name>": entry}}. Entry fields (MCPStore.ServerEntry, src/ios/Agent/Session/MCPStore.swift:254): note (string?), enabled (bool, optional, default true; import also accepts Cursor-style disabled:true), createdAt (double epoch, optional — native assigns stable value on first sight; drives Top-20 sort), updatedAt (double epoch, optional — per-server iCloud LWW clock, iOS only; CLI never writes either clock), url (string, HTTP transport), headers ({string:string}), oauth (non-secret object: mode='static', clientId, authorizationEndpoint, tokenEndpoint, scopes (space-separated string, optional), redirectURI (optional)), command (string, STDIO transport), args ([string]), env ({string:string}), startupTimeoutSeconds (int, optional). Atomic write (temp+rename) on all three writers (Swift, Kotlin, Python) so co-readers never see torn files.
- Per-session enable: global default is entry.enabled; per-session overrides live OUTSIDE servers.json in SQLite — iOS table mcp_session_overrides(session_id, server_id, is_enabled) inside Library/MinisChat/skills.db (MCPStore.createTables, MCPStore.swift:201); Android table mcp_session_overrides(session_id, mcp_id, is_enabled) in mcp.db (MCPRepository.McpDbHelper). Sparse storage: an override equal to the global default is DELETED, not pinned (setSessionOverride both platforms), so later global flips propagate. Read precedence: session override -> global enabled -> false. UI: src/ios/Views/MCP/SessionMCPsView.swift (draft sessions materialize lazily on first toggle), src/android/.../ui/chat/SessionMcpsSheet.kt (override map re-derived keyed on server list). Note: the CLI daemon only checks the GLOBAL enabled flag (daemon.py:274 DISABLED error) — per-session gating is purely prompt-level (undisclosed servers are still callable if the model guesses the name).
- OAuth token lifecycle (iOS complete, src/ios/Agent/Session/MCPOAuthController.swift): Static mode only (user-supplied client id + optional secret; 'dynamic' discovery/DCR reserved). Authorize: PKCE S256 (64-char verifier, 24-char state) + RFC 8252 loopback redirect http://localhost:54546/callback (fixed port 54546; local OAuthCallbackServer + SFSafariViewController) or ASWebAuthenticationSession fallback for custom schemes; auth URL adds access_type=offline&prompt=consent and RFC 8707 resource=<canonical server url> (fragment stripped, trailing slashes removed) on BOTH authorization and token requests. Token exchange: authorization_code grant, form-urlencoded, client_secret included only if present. Storage: tokens {accessToken, refreshToken?, expiresAt epoch} JSON in local non-synchronizable Keychain (service com.openminis.app.mcp-oauth, accounts <server>#tokens and <server>#secret); then materializeBridge writes guest bridge file oauth/<server>.json (chmod 600) with access_token, expires_at, refresh_token?, token_endpoint, client_id, client_secret?, resource?. Runtime refresh is GUEST-AUTONOMOUS: transport/http.py refreshes 60s before expires_at or on HTTP 401 (one retry) via refresh_token grant against token_endpoint (rotating refresh tokens handled) and atomically rewrites the bridge file; on failure raises AUTH_REQUIRED whose message embeds a tappable deep link [Authorize](minis://settings/mcp-servers/<name>). signOut deletes tokens+bridge but keeps secret; purge (on server delete, called from MCPStore.delete) removes all three. CLI can seed a secret via add --oauth-client-secret -> writes oauth/<name>.secret (chmod 600); native imports it into Keychain and deletes the file (importPendingSecretIfAny).
- Android OAuth status (src/android/.../mcp/oauth/): MCPOAuthController.kt runs the same PKCE flow (Custom Tab + OAuthCallbackServer, port 54546, McpPkce.kt for verifier/challenge/state/resource/URL build) and stores tokens in EncryptedSharedPreferences (MCPOAuthStore.kt, file mcp_oauth_secrets, keys secret::<server> / tokens::<server>, expiresAtMs). Phase 2 scope explicitly EXCLUDES the guest bridge materialization and autonomous refresh (header comment MCPOAuthController.kt:27-30) — so on Android the guest transport currently has no token bridge. Tests: McpOAuthPhase1Test.kt (PKCE S256, resource canonicalization, auth-URL params, config round-trip), McpOAuthTokenExchangeTest.kt (token form body incl. conditional client_secret/resource).
- Cross-platform servers.json oauth key MISMATCH: iOS (Codable) and the CLI's `add` write camelCase keys (clientId, authorizationEndpoint, tokenEndpoint, redirectURI) — see main.py:448 and MCPOAuthConfig.swift — but Android MCPOAuthConfig.kt toJson()/fromJson() uses snake_case (client_id, authorization_endpoint, token_endpoint, redirect_uri). An oauth block written by iOS/CLI parses as empty-and-discarded on Android and vice versa. Everything else in the entry schema matches.
- iOS extra plumbing: refreshTools(server:) (MCPStore.swift:670) shells `minis-mcp-cli refresh '<name>'` through ISHExecutionCoordinator with 120s timeout and parses the first JSON line — native Settings UI reuses the same CLI instead of a native MCP client. iCloud sync (iOS only): one CloudKit record per server (recordType MCPServerItem, recordName = server name), per-entry updatedAt LWW with 2s skew slack, semantic fingerprints in UserDefaults (key cloudSync.mcp.syncFingerprints) detect CLI-authored edits via file-mtime scan (scanExternalChanges, MCPStore.swift:868); token/bridge/secret files are deliberately outside sync. Android has NO sync layer for MCP (local-only).
- CLI runtime deps auto-resolution (utils/deps.py): missing STDIO commands are best-effort installed — npx/node/npm -> apk add nodejs npm; python3/pip -> apk add python3 py3-pip; uvx/uv -> pip install uv (with --break-system-packages fallback). iOS and Android bundled CLI trees are byte-identical (verified by diff: src/ios/default_mount/usr/local/{bin,lib}/minis-mcp-cli == src/android/app/src/main/assets/default_mount/usr/local/{bin,lib}/minis-mcp-cli).

## Data formats
- servers.json (Claude-Desktop-compatible): {"mcpServers": {"notion": {"url": "https://mcp.notion.so/mcp", "headers": {"Authorization": "Bearer $$NOTION_TOKEN"}, "oauth": {"mode": "static", "clientId": "...", "authorizationEndpoint": "https://...", "tokenEndpoint": "https://...", "scopes": "openid email", "redirectURI": "http://localhost:54546/callback"}, "note": "...", "enabled": true, "createdAt": 1753500000.0, "updatedAt": 1753500000.0}, "github": {"command": "npx", "args": ["-y", "@modelcontextprotocol/server-github"], "env": {"GITHUB_TOKEN": "$$GITHUB_TOKEN"}, "startupTimeoutSeconds": 120, "enabled": true}}}
- CLI stdout success envelopes (one JSON line, --pretty optional): list -> {"servers": [{"name","enabled","transport":"http|stdio|unknown","target","note","alive"}], "count"}; tools -> {"server", "tools": [<raw MCP tool objects with name/description/inputSchema>], "count"}; call -> {"server", "tool", "result": <raw MCP tools/call result>}; ping -> {"server", "ok": true, "elapsed_ms"}; add -> {"added", "config", "oauth_note"?}; error -> {"error": "msg", "code": "AUTH_REQUIRED|TIMEOUT|...", "server": "name|null"} with non-zero exit
- OAuth token bridge file /var/minis/mcp-servers/oauth/<server>.json (chmod 600, never synced): {"access_token": "...", "expires_at": 1789999999, "refresh_token": "...", "token_endpoint": "https://oauth2.googleapis.com/token", "client_id": "...", "client_secret": "...", "resource": "https://mcp.example.com"} — co-written by native (authorize) and guest (refresh)
- CLI-seeded secret handoff: /var/minis/mcp-servers/oauth/<server>.secret (plain text, chmod 600; imported into Keychain then deleted by native)
- Daemon IPC (127.0.0.1 TCP, newline-delimited JSON): request {"cmd": "list|tools|call|ping|shutdown", "server"?, "tool"?, "args"?, "refresh"?, "all"?} -> reply {"ok": bool, "result"?|"error","code","server"}; port file /tmp/minis-mcp-daemon.port, pid file /tmp/minis-mcp-daemon.pid
- MCP wire: JSON-RPC 2.0, protocolVersion "2025-06-18", initialize -> notifications/initialized -> tools/list / tools/call; stdio = newline-delimited JSON on child stdin/stdout; HTTP = POST per RPC, response either application/json or text/event-stream (last data: line), session continuity via Mcp-Session-Id header
- Keychain token blob (iOS, account <server>#tokens): {"accessToken", "refreshToken"?, "expiresAt": epochSeconds(0=unknown)}; Android EncryptedSharedPreferences tokens::<server>: {"access_token", "refresh_token"?, "expires_at_ms"}
- System-prompt fragment format: 'Available MCP Servers (use minis-mcp-cli to discover and call):\n- <name>: <note<=200ch>\n...' + usage lines + $$VAR guidance (identical wording iOS/Android)
- SQLite session overrides: mcp_session_overrides(session_id TEXT, server_id/mcp_id TEXT, is_enabled INTEGER, PK(session_id, server_id)) — rows exist only when diverging from global default

## Reusable for desktop
- The core shape decision transfers directly: prompt-described servers (name+note only, Top-N cap) + a CLI the model calls through the existing shell tool. For DeskMinis/Electron you can keep this exact contract — bundle minis-mcp-cli (it is platform-neutral POSIX Python; on Windows the fork()-based daemon in main.py would need a spawn-based or Node rewrite, or run under WSL/git-bash) — OR register native tools; the OpenMinis design deliberately avoids native registration to keep the model's tool list small and let tool discovery happen lazily at runtime.
- The daemon pattern is worth porting even if reimplemented in the Electron main process: warm per-server sessions with 10-min idle TTL, single-retry evict+respawn on crash/timeout, self-exit after 60s empty grace, and a stable localhost JSON-line IPC. In Electron this collapses naturally into a main-process MCP pool with the CLI (or IPC bridge) as a thin client.
- Adopt servers.json verbatim ({mcpServers:{name:{url/headers | command/args/env, note, enabled, startupTimeoutSeconds, oauth, createdAt, updatedAt}}}): Claude-Desktop compatibility gives free import from existing configs; keep the 3-variant lenient importer (mcpServers-wrapped, name-keyed, single bare entry, disabled:true mapping) and per-entry decode tolerance (skip malformed entries, never blank the list).
- Secret hygiene split: non-secret oauth config in the synced/visible servers.json; client secret + tokens in OS credential store (Electron: safeStorage/keytar, mirroring iOS Keychain non-synchronizable); a chmod-600 token bridge file only if a separate process (bundled CLI) must authenticate autonomously. The $$VAR env-placeholder convention keeps secrets out of config files and the model's context, with a matching redaction pass on shell tool output (EnvVarRedact in AIChatViewModel+ConcurrentTools.swift).
- OAuth blueprint is fully reusable on desktop: PKCE S256 + RFC 8252 loopback server on a fixed dedicated port (pick one clear of other integrations; OpenMinis uses 54546) + system browser, RFC 8707 resource=canonical-server-URI on both requests, access_type=offline&prompt=consent for refresh tokens, refresh 60s-early or on 401 with one retry, AUTH_REQUIRED error text carrying a clickable deep link back to the settings page (Electron: app://-style protocol handler).
- Per-session server toggles as sparse SQLite overrides (delete row when equal to global default) with lazy draft-session materialization — cheap, propagates global changes correctly, and the same table shape works in any embedded DB.
- Two cautionary findings to NOT copy: (1) the iOS/CLI camelCase vs Android snake_case oauth key mismatch — pick one casing and write a tolerant reader; (2) per-session disable is prompt-only (the CLI still honors globally-enabled servers), so if DeskMinis needs hard per-session isolation, enforce it in the invocation layer, not just the prompt.
- The `tools --refresh` / `refresh` alias pattern (evict live session -> fresh initialize + tools/list) and the native Settings UI reusing the same CLI for its tool-list preview (MCPStore.refreshTools) keep a single MCP code path for both agent and UI — same trick works in Electron with a child-process call.

## Open questions
- Is the oauth JSON key-casing divergence (iOS/CLI camelCase vs Android snake_case in MCPOAuthConfig.kt toJson/fromJson) a known open bug or intentional (Android oauth entries perhaps never expected to cross devices, since Android has no sync)? Either way DeskMinis should read both casings.
- Android phase gap: without the token bridge (Phase 2 exclusion), how do OAuth HTTP servers work from the Android guest at all — does `call` simply fail AUTH_REQUIRED until the bridge phase ships?
- The daemon relies on os.fork(), POSIX file locks, and /tmp — a Windows Electron port needs a redesign (spawned detached child + named-pipe or localhost TCP), not a straight reuse of daemon.py.
- servers.json carries plaintext static Authorization headers when users configure them literally (only $$VAR indirection avoids it); iOS syncs this file via iCloud (MCPServerItem records include headers). Whether DeskMinis wants to sync headers at all is a policy question.
- Prompt discloses at most 20 servers but all globally-enabled servers remain callable via the CLI; also `minis-mcp-cli add` lets the model modify config — DeskMinis should decide whether to keep that self-service capability.
