# OpenCode V2 研读、界面裁剪与底层功能设计基准（2026-09-25）

> 用户原话：「参考 Opencode V2 做了比较大的革新，我想把我们之前 UI 有部分和 Opencode 相关的看看能不能裁掉，
> 让 Zcode 和 Opencode V2 和 aionUI 做底层功能设计基准」。
> 状态：**调研与建议，等用户拍板**；不改代码。0.3.0 止血期间界面结构不动。
> 对象：sst/opencode 1.18.32（2026-09-24 浅克隆，MIT）；对照上次研究（2026-07-27，1.18.5，`docs/research/opencode-*.md`）。
> 附录目录 `docs/research/2026-09-25-opencode-v2/`：`arch.md` 底层架构原稿、`ui.md` 界面原稿、`provenance.md` DeskMinis 界面溯源原稿、
> `verify.md` 对抗式核验、`baseline-and-cuts.md` 基准表与裁剪清单全文。

## §0 结论

**可以裁，但 DeskMinis 界面里字面上出自 OpenCode 的东西几乎没有。**
- 逐件溯源下来，只有标题栏窗控形制（无边框 + 系统绘制窗控）来自 OpenCode 的思路。ZCode 也是这么做的，所以保留，只修两处当初抄漏的细节。
- 渲染层里没有 OpenCode 的代码或事件名（`src/` 与 `tests/` 里 grep 不到 opencode），裁剪不涉及许可问题。
- 看着像 OpenCode 的几件——终端抽屉、任务面板、右栏第三个 tab——其实出自 OpenMinis 与 Codex 方向。

**按「去掉 coding 味、向 AionUi 收拢」的意图，建议 0.3.0 之后做一次界面减法**：
- 砍掉底部终端抽屉与标题栏的 ☰ 钮；
- 任务面板换成输入卡上的上下文占用环，与对话流里已有的事件条分工；
- 右栏从「文件 / 改动 / 任务」收成「文件 / 改动」两个 tab；
- 其余保留。

**OpenCode 的「V2 大革新」要分两层看**：
- **内核**：事件溯源、准入与投递分离、System Context 这些，上次研究已经读过；1.18.32 发行版默认跑的仍是 V1，V2 内核还是没发布的半成品。可以借它的数据模型和边界法则，不借「它已经这么跑」的信心。
- **界面**：这次真正变的是界面——新布局强制上线，旧侧栏 2026-09-14 下线，文件树、终端、状态等专业件默认隐藏。这是一次做减法，和我们要做的方向一致。

**底层功能设计基准分工**：
- **OpenCode V2**：会话事件表、准入与投递分离、System Context 与指令文件、工具注册表、压缩边界。
- **ZCode**：引擎与渲染端协议快照、工具副作用调度、压缩熔断、交互登记、改动回退、模型规则数据。
- **AionUi**：界面、等待态、计划条、助手与定时。
- **保持 DeskMinis 现状、不向 V2 看齐**：provider 降级、重试梯、60 秒看门狗。V2 runner 在这些方面比 DeskMinis 弱。

## §1 OpenCode V2 这段时间变了什么

| 变化 | 状态 |
|---|---|
| 界面换骨架：Home 页 + 标题栏标签页的新布局强制默认，旧侧栏界面 2026-09-14 下线，路由改为服务器作用域 | 已落地，默认路径 |
| 界面去 IDE 化：文件树、搜索、终端、推理摘要、工具展开等默认隐藏，收进「高级」；但内核仍面向 coding（项目即代码目录、改动审阅依赖 git） | 已落地，默认路径 |
| 事件溯源内核：单写者事件表，投影与追加同一事务；持久事件与只在线的增量分两路；按 seq 续传、有限 history 分页 | 已落地，仅 V2 路径；上次研究已覆盖 |
| 准入与投递分离：收件箱 + steer / queue + 幂等回执 | 已落地，仅 V2 路径 |
| System Context：带 key 的源冻结成基线，变化作为追加消息；AGENTS.md 向上发现 | 已落地，仅 V2 路径；上次未覆盖 |
| 压缩、工具协议、PermissionV2（拒绝级联、「总是允许」后重评） | 已落地，仅 V2 路径；仍是半成品 |
| 协议与 SDK：18 个接口组 codegen 出两套客户端；但 app 依赖的客户端事件名与内核发出的不一致 | 已落地，但仓内没有界面消费者 |
| 重试、tool.progress、压缩增量等事件只有定义没有发出方；成本固定写 0；V2 runner 只接 3 条 provider 路由、不降级 | 只有定义 |
| config / mcp / workspace 等路由、插件 hook、超时看门狗、崩溃续跑、工具并发上限 | 只有规格或明确延期 |

**要警惕的**：
- PermissionV2 仍把模型写的原始命令存成通配规则，默认 `* * allow`；
- 用户拒绝时的附言被工具吞掉，模型收不到；
- todo 用的是非持久事件、整表替换，没有读取路由；
- 收尾回合的提示以 assistant 结尾，新一代 Claude 会当成预填而拒绝。

## §2 DeskMinis 界面溯源与裁剪清单

| 部件 | 出处 | 建议 | 时机 |
|---|---|---|---|
| 标题栏窗控形制（无边框 + 系统绘制窗控 + 右侧 146px 让位） | OpenCode 思路，ZCode 同款 | 保留；补上随主题同步窗控颜色、缩放后重算让位宽度 | 0.3.0 只订正两处注释；实现排 W9c |
| 标题栏 ☰ 钮（实际只切换明暗、不保存） | 自创遗留件 | 裁掉；主题只留「设置 → 外观」，并让保存的主题启动即生效 | 0.3.0 之后的界面减法子波 |
| 底部终端抽屉 + 标题栏终端钮 + 引擎 terminal 接口 | OpenMinis 方向 | 裁掉：面向 coding 的专业件，没有 PTY 的哑管道；agent 跑的命令在对话流里看 | 界面减法子波先删入口；W6d 再删引擎侧与 xterm 依赖 |
| 任务面板（上下文水位、降级/压缩/卸载卡、上轮结束原因） | OpenMinis 方向 | 替换：换成输入卡上的上下文占用环（AionUi 形态），重复的三张卡去掉 | W5b，与真实水位同一子波交付 |
| 右栏三个 tab | 自创 | 收成「文件 / 改动」两个（AionUi 同款）；先确认「等你批准」提示已由 W2b-2 迁到左栏与对话流 | 与任务面板替换同一提交 |
| 右栏默认展开，注释却写默认收起 | 自创 | 0.3.0 先把注释改成与实现一致；「默认收起、有产出物时自动展开」要先把工作区绑定入口挪出「文件」tab | 注释随 W2b-11；行为排 W8a |
| 历史回合里没有结果的工具显示成「成功」 | 核验中新发现的界面撒谎 | 修：不在运行中的回合里，没有结果的工具显示「已中断 · 结果未知」 | 并入 W2b-11（见 §4 第 2 条） |
| 工具步骤组整组折叠 | AionUi | 保留；组头加「写了 N 个文件 / 跑了 N 条命令」摘要 | W7c |
| 权限确认卡 | OpenMinis 改内联 | 保留；W7b 停靠到输入区，补拒绝级联与重评 | W7b |
| 改动清单 | 自创 | 保留；不学 OpenCode 的 git 差分审阅 | W8b 增强 |
| 输入卡的斜杠菜单、@ 文件、输入历史 | OpenMinis、AionUi | 保留；交互逻辑抽成纯函数状态机（借 OpenCode 输入框 V2 的做法） | W7a |
| 三栏外壳、左栏、欢迎页、会话舞台、预览主舞台、事件条、助手、定时、市场、设备、设置 | AionUi / cowork 形态 | 保留 | — |

**为什么 0.3.0 期间一件都不裁**：TopBar、任务面板、右栏、输入卡、会话舞台都在 W2b 的改动清单里，
没有一件既是纯删除、又有守卫保护、又不与止血冲突。终端刚在 W1b-1 加了进程树回收，发版前删掉等于推翻刚合入的止血成果。
界面减法放在 W4b 之后，是为了先有 SSR 渲染测试，给「入口没丢」加守卫，避开 T 波「换壳丢入口」的老路。

## §3 底层功能设计基准表

逐项的参照文件、借鉴要点、许可与零依赖落地方式见附录 `baseline-and-cuts.md`。

| 子系统 | 主基准 | 次基准 | 对路线的影响 |
|---|---|---|---|
| 会话模型与事件持久化 | OpenCode V2 事件表 | ZCode V4 快照 | 新建带 seq 的会话事件表，时机见 §4 第 3 条 |
| 引擎与渲染端协议 | ZCode V4（已在产品运行） | OpenCode V2 | W6b/W6c 增补：增量不推进游标、有限 history 分页、会话钉定的 RPC |
| 运行器循环 | OpenCode V2 边界法则 | ZCode | W5a：到达回合上限改为发一轮不带工具的收尾回合（提示用 user 角色）；W7a：悬空工具在下次运行时判为「执行被中断」 |
| 工具协议与副作用元数据 | ZCode 调度屏障 | OpenCode V2 注册表 | W7a 增补 stale 守卫与结果三分类；W5b 的截断改在注册表出口统一做 |
| 权限与交互通道 | ZCode 交互登记 | OpenCode PermissionV2 | W7b 增补拒绝级联、同会话重评、附言写进工具结果 |
| 上下文压缩 | ZCode 熔断 | OpenCode V2 检查点 | W5a/W5c 原计划已覆盖；补一条：压缩失败保留上一个 marker |
| provider 与模型规则 | ZCode 规则数据 | OpenCode llm 包 | W4c 增补：错误报文先脱敏再上屏；换模时思考块降为普通文本 |
| 配置与指令文件 | OpenCode V2 System Context | ZCode | W5c 补具体数据模型：基线冻结 + 带 key 的源 + 变化追加 |
| todo / 计划 | AionUi 计划条 | ZCode | W7c 不变；OpenCode 不作基准 |
| 多会话与运行态可见性 | AionUi 等待态 | OpenCode app 冒泡 | W7b 增补：通知接线不依赖外壳组件 |
| 界面状态投影 | AionUi 运行态投影 | OpenCode 消息联合 | W6c 纯 reducer 以 AionUi 为形；W7c 对话流内分隔行 |
| cowork 能力（助手、定时） | AionUi | ZCode 无人值守应答 | 不变；OpenCode 没有这块 |
| 改动追踪与回退 | ZCode rewind | OpenCode 三段式回退 | W8b 增补可撤回的三段式回退；回合结束事件带改动文件 |

## §4 需要拍板的事（括号内为默认建议）

> **2026-09-25 用户拍板：七条全部按默认。** 第 2 条已在 W2b-11a（`4e20153`）落地；第 4 条里 NOTICES 补登 OpenCode 已在 W2b-11c（`7d7e71f`）落地；
> 其余按下面的默认写进路线详案（`docs/research/2026-09-24-resurvey/roadmap.md` 的「2026-09-25 拍板」一节与各波范围）。

1. **底部终端抽屉砍不砍**（砍，分两步：W4b 之后的界面减法子波先删入口，W6d 再删引擎侧）。
   另建议 0.3.0 的 CHANGELOG 不再把终端写成亮点。
2. **历史回合里没有结果的工具显示成「成功」，0.3.0 修不修**（修，并入 W2b-11 的界面同类假话，只改渲染端一处）。
   这属于已定的「界面不说假话」一类，主会话按默认先纳入 W2b-11，用户可否决。
3. **会话事件表放哪次迁移**（W6c，与 W7a 要用的收件箱表合成 0.5.0 唯一一次追加迁移）。
4. **是否采纳基准分工表并据此改写路线各波的「借鉴」行**（采纳；0.3.0 之后先补一份逐条标明落地状态的 OpenCode V2 研读稿，
   再改路线；THIRD-PARTY-NOTICES 的「仅借思路」一节补登 OpenCode，标题栏形制借的是它的思路）。
5. **上下文占用环从 W9c 提前到 W5b，同一子波删任务面板、右栏收成两个 tab**（是）。
6. **右栏默认展开还是收起**（0.3.0 保持展开，只改注释；收起留到 W8a 设计稿再议）。
7. **工具步骤组要不要改成 OpenCode 那样只折叠只读类工具**（不改，保持 AionUi 的整组折叠，组头加摘要）。

## §5 方法与局限

- 三路阅读（OpenCode V2 底层、OpenCode V2 界面、DeskMinis 界面溯源）→ 一位对抗式核验者 → 综合。
- 主会话亲自复核了三条关于 DeskMinis 的关键说法：代码与测试里 grep 不到 opencode；标题栏 ☰ 只切换明暗且不保存（`AppShell.vue:64-67`）；
  历史工具缺结果时默认显示成功（`StageChat.vue:112`）。
- 参考仓库是浅克隆，没法逐版 diff；「变了什么」是拿上次研究的每条说法逐条核对现在的源码得出的。
