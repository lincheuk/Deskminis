# 参考项目重读与方向评估（2026-09-24）

> 用户原话：「我們之前的參考項目有了較大程度的修改，我想要你先把我們之前的參考項目重新閱讀一下，再進行重新革新優化還是繼續怎麼樣」。
> 参考项目按用户补充共五个：OpenMinis、AionUi、deepseek-harness、ZCode、pi。
> 状态：**调研与建议，等用户拍板**。本报告不改代码；路线里的每一波开工前照例先出设计稿。
> 附录：`docs/research/2026-09-24-resurvey/` 目录。其中 `matrix.md` 是 117 行完整能力矩阵，`roadmap.md` 是分波详案与验收标准，
> 另有五个项目核验后的发现、DeskMinis 现状画像，以及评审共用的背景材料 `context.md`。

## §0 结论

**建议「定向革新」，并且先止血、先发版。** 不推倒重来，也不照老路只补功能。

1. **先止血。** 用两轮小修（W1、W2，共四个子波）修掉会伤数据、会越权、会说假话、会卡死的问题。§4 列了 24 条核实过的缺陷，其中 9 条会损坏用户数据或绕过权限。
2. **再发版。** 然后在 Windows 真机上发出第一个正式版 0.3.0（W3）。前两次重做已经让 0.2.0 没能发出去，这次发版排在任何大改之前。
3. **只成批重写两块。** 发版后成批重写的只有两处：长对话时引擎怎么整理上下文（W5），以及界面和后台怎么保持连接（W6）。其余在现有骨架上逐项补齐。
4. **cowork 内容提前。** 办公技能包是纯内容，不依赖引擎重写，提前到 0.3.1 送到用户手里。

**为什么不推倒重来。** 能力矩阵共 117 项，只有两项碰到零依赖红线：OS 级沙箱和 Mermaid 图表排版。OS 级沙箱的参考实现依赖 FFI 库，自建成本高；Mermaid 排版则离不开 mermaid 库。其余都能在现有骨架上零依赖补齐，没有一项需要换引擎架构或换 UI 框架。五个参考项目这段时间也没有一家在换界面或换框架，AionUi 的设计令牌自上次阅读以来零变更。界面树保留，不做第三次换壳。这也回应了用户「不要在原有基础搞出四不像」：该重做的子系统一次重做到位，刚重建完的界面不再整体换皮。

**为什么不只做增量。** 缺陷是两条互相咬合的链，零散点修会互相掩盖。
- **上下文链**：溢出被当成可降级错误；压缩输入无上界；空摘要也写标记；失败被静默吞掉；水位只按字符估算；系统提示每一步都重建。
- **连接链**：断线无人处理；引擎崩溃无人接管；全量广播；非当前会话的事件被丢弃。

五个参考项目这段时间的共同走向，恰好都落在这两条链上。

**需要用户先定的三件事**（完整清单见 §7）：
- 0.3.0 是否在止血后立即发。
- 自动更新源怎么解决。私仓下更新检查一律 404，这决定 0.3.0 用户以后能不能自动升级。
- agent 写应用配置的权限收窄到什么程度。

## §2 五个项目这段时间变了什么

**总的印象**：参考项目这五周的进展主要在**引擎深度与运行时韧性**，界面形态基本稳定。AionUi 的设计令牌零变更，S/T 波照抄的色值、圆角、阴影仍然有效。多家同时在做的是这几件事：会话协议可续传、引擎崩溃可恢复、上下文压缩有上界且可恢复、provider 参数数据驱动、工具按副作用调度、状态可见（等待你、系统通知）。

### OpenMinis（v1.10 → v1.13）

- **最大一块是备份恢复**：iOS 端 29 个文件、约 9000 行，包格式 `minisbak/1`，带口令加密与流式 zip64 写包。
- **Thinking Rules 数据体系**：把一年来各家 provider 报过的 400 沉淀成规则表，约 1400 行，配黄金快照测试和用户规则编辑器。Anthropic 的思考参数按模型代际分叉；DeepSeek V4 这类默认开思考的模型，关闭时必须显式发 disabled，并回传 reasoning_content。
- **压缩链路加固**：分段重试放宽，两半摘要直接拼接；Android 加了调用次数与墙钟上限，429/5xx/鉴权失败不拆分。
- **其它**：逐条消息记录实际出答的模型；视觉组让文本模型借视觉模型「代看」图片；被截断的写文件参数直接拒绝执行；打开数据库前做降级守卫。
- **对我们的意义**：provider 兼容与压缩是 DeskMinis 的真短板（§4 第 10、16 条）。GPLv3 只能借思路，规则表要自己按官方文档建。

### AionUi（v2.1.59 → v2.2.2）

- **形态不变**：仍是 Electron 瘦壳 + React 渲染层 + 独立 Rust 引擎 aioncore，变化几乎全在渲染层。
- **五条功能线**：
  - 侧栏「等待你」状态，配原生系统通知；
  - 计划条钉在输入框上方；
  - 删除改为归档优先，另有已归档管理页；
  - @@ 跨会话提及；
  - 一批壳层体验：空输入开会话并显示助手空态、分区字体、侧栏可拖宽、预览最大化。
- **上次没覆盖的进程生命周期加固**：单实例、崩溃重启与重连、启动失败分类、退出清理。这部分基线前就有。
- **对我们的意义**：「空会话助手空态」能从结构上修掉交接文档 §6 一档里「欢迎页选助手的既有撒谎」。「等待你」和系统通知对定时任务的权限询问最有用。这些都能用 Electron 内置能力零依赖实现。

### deepseek-harness（DSH，0.1.0-rc.8 → 0.1.7-rc.1）

- **新增 Electron 桌面端**：以 RunAsNode 拉起 Host，有单实例锁、导航守卫、原生致命错误恢复与崩溃报告、带准入锁的更新。
- **会话存储**：删除 SQLite 后端，只留 JSONL，另建 v0→v4 相邻迁移链。起因是一份 116MB 的旧日志整块迁移时 OOM。
- **上下文**：压缩复用前缀缓存；溢出单独分类，压缩后重试一次；系统提示分稳定段与动态段，动态上下文作为 user 快照追加。
- **客户端**：过程分组、整回合折叠、回合导航、用量面板、会话分叉、上下文占用环。
- **反面**：`session-log-deepseek` 默认开启，会把完整会话日志附在官方 API 请求里上传。遥测默认值也从关闭改成了只收反馈。
- **对我们的意义**：它的上下文策略直接对应 DeskMinis 的三处缺陷（§4 第 10、11、12 条）。Cordis 插件框架和全量事件溯源不值得照搬。

### ZCode（v3.14.3，首次阅读）

- **架构**：一套 services 挂在三种宿主上，分别是桌面 utilityProcess、Web、远端 SSH/WSL/Docker。agent 在独立 CLI 子进程里，约 29 万行 TS。
- **V4 会话协议**：「快照 + 7 种封闭增量 + seq/revision」，渲染端刷新后能从快照完整恢复。
- **运行时**：连接断开时拒绝全部挂起调用；崩溃预算按 1/2/4/8/16 秒退避；工具按「只读 / 并发安全」元数据调度，不安全的调用作为屏障单独执行；Edit 多级匹配并检查 mtime 是否过期；压缩熔断。
- **反面**：全仓只有 4 个测试文件；Goal 验证器失败时 fail-open；`--web` 在回环地址上默认不启令牌。
- **对我们的意义**：运行时韧性的样板。§4 第 1、9、13 条缺陷都是对照它发现的。

### pi（pi-mono，0.84 → 0.87.1）

- **两层**：
  - **稳定面**：CLI、SDK、stdio JSONL RPC、模型层，持续打磨。
  - **实验面**：架构重心整体迁移一次，新增 chord、durable、pico 内核；协议缩到只剩纯路由信封。只在 `PI_EXPERIMENTAL` 下使用，规范自述仍是 WIP。
- **稳定面值得吸收的小机制**：
  - 上下文溢出识别后压缩并重试一次，不走降级；
  - OpenAI 兼容端点的 compat 矩阵；
  - 编辑工具切片拼接，保持 CRLF 与 BOM；
  - 迭代式结构化压缩，截断的摘要一律拒收；
  - 按真实 usage 算水位；
  - RPC 断连时结算挂起调用；
  - 运行中插话的 steer 队列；
  - Windows 按进程树终止；
  - AGENTS.md 注入前先经信任确认。
- **反面**：`session-backends/sqlite-node` 原地改写初始迁移。它能这样做是因为包还没发布，DeskMinis 的迁移只追加纪律不能松。
- **对我们的意义**：实验面不跟。稳定面的机制多数是 S–M 规模的零依赖移植。

## §3 跨项目趋势与 DeskMinis 的差距

完整矩阵见附录 `matrix.md`，分四簇：引擎与上下文 30 项、运行时与协议 28 项、桌面体验 29 项、cowork 广度 30 项。这里只列结论。

**六条共同走向**：

1. **请求前缀只追加。** 这已经从缓存优化变成硬约束。DSH 把系统提示做成会话节点 0，动态上下文作为追加消息；pi 加了转录内系统消息和追加式上下文编辑。API 侧也在收紧：Anthropic 对新账号强制校验思考块的前缀（§4 第 15 条）。
2. **溢出先压缩再重试，不降级。** pi、DSH、ZCode 三家做法相同，而且都把溢出和限流、配额耗尽分开分类。压缩都具备四要素：增量、输入有界、结构化模板、截断或空摘要拒收。DeskMinis 四项全缺。
3. **引擎外置进程的韧性地基。** AionUi、DSH、ZCode 三个桌面端都有这几样：单实例锁、崩溃预算与受控重启、断线结算挂起调用、快照加序号续传、有序退出。DSH 在五周内从零补齐了这整套，说明它是「能发布」的前提。DeskMinis 只做了启动期那一半。
4. **人在回路的结构化通道。** 运行中插话五家都有，DeskMinis 是唯一在运行中锁住输入框的。「等待你」徽标与系统通知多家都有，DeskMinis 有定时任务和 90 秒自动拒绝，却一条通知都没有。
5. **provider 兼容数据驱动，并用请求体快照钉住。** OpenMinis 的思考规则表、ZCode 的规则级联、pi 的兼容矩阵都是这个思路。DeskMinis 仍在各 provider 里写分支，思考参数停在旧的 budget_tokens 写法。
6. **cowork 广度靠内容包，不靠代码。** AionUi 有 21 个助手和内置办公技能，DSH 与 ZCode 也都随包提供技能。DeskMinis 的零依赖 Office 引擎比它们都轻，缺的是随包的办公技能和配套助手。

**价值最高的差距**（用户价值 5，或价值 4 且至少三家具备，DeskMinis 缺失或有缺陷；完整 65 行见附录）：

|---|---|---|---|
| 运行中插话：排到下一回合，或在工具边界插入 | 5 | 缺 | M |
| 会话「等待你 / 运行中」徽标与系统通知 | 5 | 缺 | M |
| 发布工程：资产校验、依赖冻结、仓库外冒烟 | 5 | 部分 | S |

**参考项目里要避开的做法**：
- **默认外发数据**：DSH 默认把完整会话日志附在官方 API 请求里上传；ZCode 把 Coding Plan 端点静默改发到自家网关。
- **放宽宿主安全**：AionUi 为了一个字体 API 放行全部 Electron 权限请求；ZCode 的 `--web` 在回环地址上默认不发令牌。
- **失败即放行**：ZCode 的 Goal 验证器遇错判为通过。
- **静默改字符**：pi 的编辑模糊匹配第一步做 NFKC，会把中文全角标点改成半角。
- **改写已有迁移**：pi 原地改写初始迁移。

借鉴任何机制之前，都要先 grep 确认参考项目里真有调用方，再写 DeskMinis 自己的不变量红测。ZCode 注释里引用的「黄金测试」就不在它的仓库里。

## §4 顺带核实的 DeskMinis 真缺陷

核验者对照参考项目时报出了一批 DeskMinis 缺陷。下表每一条都由主会话回到源码核对过，其中两条做了实验。按严重度分三组。

### A 组：会损坏用户数据或绕过权限（建议全部在 0.3.0 前修掉）

| # | 位置 | 问题 | 后果 | 核实 |
|---|---|---|---|---|
| 1 | `src/minisd/tools/files.ts:123` | file_edit 用 `String.replace` 写盘，替换文本里的 `$$`、`$&`、`$'` 被当成特殊序列 | 静默改坏用户文件：`"$$5"` 落盘成 `"$5"`，`$&` 插入原文 | Node 复现 |
| 2 | `tools/files.ts:27-32` | 写权限检查对整个数据根放行，而数据根里放着 `providers.json`、`mcp-servers/servers.json`、`skills/`、`memory/`、`minis.db` | agent 不经任何权限卡就能改应用配置。例如往 servers.json 写一个带任意命令的 MCP 服务，下次加载 MCP 时就会执行 | 读码 |
| 3 | `ui/settings/SecMcp.vue:31,44` + `mcp/config.ts:186-210` | 编辑 MCP 条目时，界面提交的数据只有七个字段，并强制启用；后端整条替换；参数按空白重新切分 | 在设置里编辑一次，哪怕只改备注，也会抹掉环境变量（含市场装入的密钥）、请求头、工作目录，带空格的参数被拆坏 | 读码 |
| 4 | `mcp/config.ts:127,174` | servers.json 解析失败只记错误，之后任一次保存用空列表覆盖原文件 | 用户手写的 MCP 配置被清空 | 读码 |
| 5 | `agent/compact.ts:97` | 摘要为空时照样写压缩标记，内容是「[摘要为空]」；也不检查摘要是否被截断 | 锚点之前的全部历史被替换成空摘要。新一代 Claude 的思考计入输出上限，而摘要上限只有 1024，可能触发这条路径（按代码推断） | 读码 |
| 6 | `store/db.ts:196` | 迁移只处理版本号更低的库，旧版应用打开新版库不拦截 | 回退安装后写坏新结构。这道守卫只有装在旧版里才起作用，所以必须随 0.3.0 出去 | 读码 |

## §5 建议路线

- **保留**：

## §6 不做什么

- **不做第三次整体换皮，也不换 UI 框架。** 渲染侧测试几乎全是源码文本守卫，没有测试网能兜住一次整体重写。T 波换壳时，1890 例全绿也没拦住权限卡从来没渲染过。
- **不用外部 agent 运行时替换 minisd。** 候选包括 aioncore、pi harness、zcode-cli、嵌入 ACP。约 95 个引擎行为测试会一起作废，也打破零新依赖。
- **不把存储改成 JSONL 事件溯源。** DSH 弃用 SQLite 的起因是按 delta 存储导致迁移时 OOM，DeskMinis 按消息落库，没有这个问题。
- **不在一波里同时重写循环、压缩、provider、连接层和 store。** 每波只动一个耦合簇。
- **不引入新 npm 依赖。** 数学公式和 Mermaid 如实降级为等宽原文，除非用户破例。
- **不学默认外发、放宽宿主安全、失败即放行、重连后自动重放写操作。**
- **近期不做多 agent 团队、工作流编排、SSH、LSP、IM 机器人、多 BrowserWindow 对话墙。**
- **0.3.0 前不加新功能，也不加数据库迁移。**
