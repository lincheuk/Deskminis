# zcode:verify
总述：ZCode（/home/user/refs/zcode，v3.14.3，Apache-2.0）是智谱系 AI 编程工作台的开源快照。git 只有 3 个提交（77432b6 → 872ad96 open source → 29628c9 v3.14.3），所以本次按首次阅读处理，下面所有结论都以源码为证。

架构上是 pnpm monorepo，核心是「一套 services 多处托管」：packages/services 的 ServiceCollection 通过 @zcode/rpc（移植自 VS Code IPC，二进制帧，ProxyChannel 默认把服务的全部方法暴露出去）挂到三种宿主上：
- 桌面端：每个窗口一个 utilityProcess Host，renderer 用 MessagePort 直连；
- `zcode --web`：Hono HTTP/WS；
- 远端：SSH/WSL/Docker，走 stdio。

Agent 在独立的 zcode-cli 子进程里（约 29 万行 TS），讲 ZCode Protocol。V4 协议约 1.09 万行，把会话建模为「快照 + 7 种封闭增量 + seq/revision」，旧 v1 协议（3720 行）并存。运行时有这些特点：
- 回合循环不设上限，靠多级压缩、熔断和重复调用提醒兜底；
- 工具按副作用元数据调度；
- Edit 做多级匹配并带 mtime 过期检测；
- Goal 由独立 verifier 续跑，但 verifier 失败时 fail-open；
- hooks、插件兼容 Claude Code/Codex 的包格式；
- IAB 内置浏览器通过 webview + CDP 实现；
- 模型参数由受限 CEL 生成 JSON merge patch。

UI 为 React，DESIGN.md 约束写得很严，但没有守卫。

工程面的问题：全仓只有 4 个测试文件；architecture-policy 只管 storage 一个模块；206 个文件豁免了 max-lines。出网面也大：Coding Plan 网关静默转发、ARMS/OTel 遥测、CDN 同步。凭据存储不是系统钥匙串。

对 DeskMinis 最有价值的是运行态韧性与 Agent 循环的若干机制：快照恢复、断线拒绝挂起调用、崩溃预算、工具调度屏障、压缩熔断、迁移 checksum。核验中还顺带确认了 DeskMinis 的三处真实缺陷：
- file_edit 的 `$` 替换缺陷，已复现；
- 同批工具一律并发；
- 技能 zip 解压没有上限。

要点变化：
- 首次阅读基线：ZCode v3.14.3 monorepo 只有 3 个提交；全仓只有 4 个 *.test.ts(x)（services 3 个、ui 1 个），源码注释里多次引用的「黄金测试」（formal-proof-consistency、两个 profile 终态逐字节一致）都不在仓库里
- V4 会话协议：conversationSnapshot 带 seq、revision、logEpoch 以及 control/queue/pendingInteractions 等状态，增量是 7 种封闭 op，表达不了的就整份 resync；renderer 刷新时 Main 给还活着的 Host 补挂 MessagePort，不重建 Host（desktopWindowLifecycle.ts:136-165）
- @zcode/rpc 的 ChannelClient 在 dispose 时拒绝全部挂起调用，并支持 PromiseCancel；PersistentProtocol（ACK/重放）在产品代码和 examples 里都没人用，Web 客户端的 onClose 是空函数
- zcode-cli 回合循环是 while(true)，AGENTS.md 明确不用工具调用次数做硬停止，靠 microcompact、自动压缩、超窗反应式压缩、rapid-refill 与连续失败熔断、重复签名提醒来收住
- ToolScheduler 让 readOnly/concurrentSafe 的调用并行，不安全的调用作为屏障单独执行；对照发现 DeskMinis agent/loop.ts:548-553 对同批所有工具一律 runWithConcurrency(10)
- Edit 用函数式 replacer 避开 String.replace 的 $ 特殊 token（edit.ts:631-634）；对照复现了 DeskMinis tools/files.ts:123 的缺陷：new_string 里的 "$$5" 写盘后变成 "$5"，"$&" 会插入原文
- Goal 验证器在坏 JSON、请求失败、模型试图调工具这几种情况下都返回 passed:true（fail-open），请求失败那一支的事件 status 却标成 "failed_closed"；token 预算可以为 null
- `zcode --web` 在回环 host 上默认不启 token（runner.mjs shouldProtectHost），token 中间件只在配置了 authToken 时挂载，/ws 不校验 Origin；/ws/host 用 30s 一次性 capability 提权（正面做法）
- zcode-server-cli 的 CrashBudget：5 分钟窗口内按 1/2/4/8/16s 退避，耗尽后进入 crash-loop-stopped；core 监听父进程 IPC disconnect 自行收口；Main 强杀 Host 前至少等 3.5s
- 插件、hook、技能生态兼容 .claude-plugin/.codex-plugin；hook 7 个事件，stdin 带 snake_case 别名，退出码 2 表示阻断；工作区 hook 按声明 sha256 做信任，执行前实时复核
- 插件 zip 源有 200MB/500MB/20000 条/50MB 四道上限，并强制 sha256；对照发现 DeskMinis skills/importer.ts 的 unzipToMemory 没有条目数、解压总量、单文件上限（office/zip.ts 反而有）
- model-option-map：受限 CEL 表达式生成请求体 JSON merge patch，两个 option 写同一路径直接报冲突，请求体不是 JSON 文本时 fail-closed；内置规则 modelRules 84 / modelApiRules 72 / providerSiteRules 52 / templateModelRules 244 / builtinProviderModelRules 26
