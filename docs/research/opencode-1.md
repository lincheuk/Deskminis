# 服务端与客户端协议 (OpenCode server / protocol / client / sdk / httpapi-codegen)

## Key findings
- Wire protocol is plain HTTP+JSON (REST-ish), NOT JSON-RPC and NOT a general WebSocket channel. The whole surface is declared with Effect's `HttpApi` DSL in C:/Users/24739/Downloads/opencode-ref/packages/protocol/src/api.ts (`makeApi`/`makeDefaultApi` compose 18 `HttpApiGroup`s: server.health, server.location, server.agent, server.session, server.message, server.model, server.provider, server.integration, server.credential, server.permission, server.fs, server.command, server.skill, server.event, server.pty, server.question, server.reference, server.projectCopy). Grep for `jsonrpc` across packages only hits MCP / LSP / ACP / websearch code — never the core<->client channel.
- Server assembly is C:/Users/24739/Downloads/opencode-ref/packages/server/src/routes.ts: `HttpApiBuilder.layer(Api, { openapiPath: "/openapi.json" })` — the running server self-serves its own OpenAPI document at GET /openapi.json. `createRoutes(password?)` (network) vs `createEmbeddedRoutes()` (no password, in-process) are the only two variants.
- Streaming = Server-Sent Events over the same HTTP port, two endpoints. (1) Global firehose GET /api/event (protocol/src/groups/event.ts, `HttpApiSchema.StreamSse({ data: EventSchema })`); handler C:/Users/24739/Downloads/opencode-ref/packages/server/src/handlers/event.ts emits SSE frames with `event: message` + `data: <json>`, prepends a synthetic `server.connected` event, and merges a `: heartbeat\n\n` comment every 15 seconds with headers Cache-Control: no-cache,no-transform / X-Accel-Buffering: no / X-Content-Type-Options: nosniff. (2) Per-session GET /api/session/:sessionID/event?after=<seq> (protocol/src/groups/session.ts line ~327) which REPLAYS durable events after an aggregate sequence then continues live.
- Event envelope (v2) is uniform: `{ id: "evt_...", type: string, data: {...}, durable?: { aggregateID, seq, version }, location?: { directory, workspaceID? }, metadata?: Record<string,unknown> }` — defined by `Event.define(...)` in C:/Users/24739/Downloads/opencode-ref/packages/schema/src/event.ts. Event IDs are monotonic `evt_` + ascending id. The legacy v1 stream at GET /event uses a DIFFERENT shape `{ id, type, properties }` with a `server.heartbeat` event every 10s (packages/opencode/src/server/routes/instance/httpapi/handlers/event.ts).
- Event names are dot-namespaced, lifecycle-suffixed strings (schema/src/session-event.ts): session.next.prompted, session.next.prompt.admitted, session.next.step.started/ended/failed, session.next.text.started/delta/ended, session.next.reasoning.started/delta/ended, session.next.tool.input.started/delta/ended, session.next.tool.called/progress/success/failed, session.next.shell.started/ended, session.next.compaction.started/delta/ended, session.next.revert.staged/cleared/committed, session.next.retried, session.next.agent.switched, session.next.model.switched, session.next.moved, session.next.context.updated, session.next.synthetic. Other domains: permission.v2.asked/replied, question.v2.asked/replied/rejected, pty.created/updated/exited/deleted, file.edited, server.connected, global.disposed.
- Critical split: *.delta events (text/reasoning/tool-input/compaction) are LIVE-ONLY, everything else is also DURABLE. schema/src/session-event.ts exports two inventories — `DurableDefinitions` (no deltas) and `Definitions` (with deltas); `Durable = Schema.Union(DurableDefinitions, {mode:"oneOf"}).pipe(Schema.toTaggedUnion("type"))`. Durable events carry `durable: { aggregate: "sessionID", version: 1|2 }` and are persisted with a per-aggregate monotonic `seq`, so a reconnecting client can resume losslessly with ?after=seq while deltas are best-effort cosmetics.
- Durable stream implementation (packages/core/src/event.ts, `durable({aggregateID, after})`) = read rows from SQLite after `seq`, then a `PubSub.sliding<void>(1)` wake channel that re-reads from the DB on every notification. Slow consumers can never lose events; they just coalesce. Contrast the global firehose `allBounded(events, 256)` which uses `Queue.dropping` and FAILS the stream with `SubscriberOverflowError` on overflow — the global stream is intentionally lossy-and-fail-fast, the per-session one is gap-free.
- Schema is defined once with Effect Schema (v4 `effect/Schema`, not zod) in @opencode-ai/schema, wrapped into endpoints in @opencode-ai/protocol, and everything else is GENERATED. Dependency direction is enforced and documented: `@opencode-ai/schema <- @opencode-ai/protocol <- @opencode-ai/server` (packages/schema/AGENTS.md).
- Two-stage codegen in C:/Users/24739/Downloads/opencode-ref/packages/httpapi-codegen/src/index.ts (1185 lines): `compile(Api, {groupNames, endpointNames, omitEndpoints})` reflects an HttpApi into a transport-neutral `Contract`, then `emitPromise(contract)` / `emitEffect(contract)` / `emitEffectImported(contract)` produce two independent clients, then `write(output, dir)`. Generated files are COMMITTED and CI fails on drift (`bun run check:generated` = regenerate + `git diff --exit-code`). A `.httpapi-codegen.json` manifest tracks generated files so regeneration deletes only files it previously owned.
- Generated Promise client (packages/client/src/generated/client.ts, 1029 lines, zero Effect/zod at runtime) is a flat `RequestDescriptor` interpreter: `{ method, path, query, headers, body, successStatus, declaredStatuses, empty }` -> fetch. It unwraps `{data: A}` envelopes (`.then(v => v.data)`), maps 204 to void, throws the declared tagged error object when `declaredStatuses.includes(status)`, otherwise throws `ClientError("Transport"|"UnexpectedStatus"|"MalformedResponse"|"UnsupportedContentType")`. SSE endpoints return a lazy `AsyncIterable<A>` from a hand-rolled parser (1 MiB frame cap, CRLF normalization, `data:` line joining). Explicitly: neither generated runtime auto-reconnects.
- Codegen renames transport identifiers into a domain surface via an explicit map in packages/client/src/contract.ts: group "server.session" -> `sessions`, "server.fs" -> `files`, "server.pty" -> `ptys`, endpoint "session.messages" -> `list`, "permission.request.list" -> `listRequests`, etc. `omitEndpoints = new Set(["fs.read", "pty.connect", "pty.connectToken"])` keeps binary/WebSocket routes out of the generic HTTP client.
- There is a SECOND, older SDK: packages/sdk/js generated by Hey API (@hey-api/openapi-ts) from a 1.1 MB committed packages/sdk/openapi.json, built by `bun dev generate > openapi.json` (packages/sdk/js/script/build.ts). It has v1 (`src/gen`) and v2 (`src/v2/gen`) trees. So OpenCode currently ships THREE client generations (hey-api v1, hey-api v2, httpapi-codegen promise/effect) plus a protocol-sniffing shim.
- Clients probe which protocol a server speaks: packages/app/src/utils/server-protocol.ts `detectServerProtocol` GETs /global/health (v1 marker: `{healthy:true}`) then /api/health, treating a `pid` field as v2 and `healthy:true` as v1, defaulting to v2. This is the versioning strategy — capability probing on health endpoints, not a handshake or version header.
- Server discovery for CLI-style clients = a state-directory registration file, not env vars: C:/Users/24739/Downloads/opencode-ref/packages/cli/src/services/daemon.ts writes `$XDG_STATE_HOME/opencode/server.json` = `{ id: uuid, version, url, pid }` (written to `<file>.<uuid>.tmp` then renamed, mode 0600) and `$XDG_STATE_HOME/opencode/password` (32 random bytes base64url, mode 0600, tmp+rename). `daemon.start()` reads server.json, health-checks it WITH auth, compares `version` against `InstallationVersion`, kills a stale/mismatched one (SIGTERM, poll 100x50ms, then SIGKILL), else spawns `serve --register` detached+unref. The registering process re-reads server.json every 10s and SIGTERMs itself if another server took over the file; a scope finalizer deletes the file if it still owns it.
- Auth on the channel is HTTP Basic, single shared password, username default "opencode": packages/server/src/auth.ts + packages/server/src/middleware/authorization.ts. Config comes from OPENCODE_SERVER_PASSWORD / OPENCODE_SERVER_USERNAME (or an explicit `createRoutes(password)`). If no password is configured the middleware becomes the identity function — i.e. NO auth at all (legacy `opencode serve` prints "Warning: OPENCODE_SERVER_PASSWORD is not set; server is unsecured."). On failure it appends `www-authenticate: Basic realm="Secure Area"` and returns UnauthorizedError (401). There is no per-client identity, no token expiry, no scopes, no rotation beyond `opencode service password <value>` (which stops the daemon first).
- Credentials can also travel as `?auth_token=<base64(user:pass)>` because browsers cannot set headers on WebSocket upgrades (middleware/authorization.ts, AUTH_TOKEN_QUERY). The web app strips it from the URL immediately after reading (`clearAuthToken()` + history.replaceState in packages/app/src/entry.tsx).
- The only WebSocket in the product is PTY: GET /api/pty/:ptyID/connect (protocol/src/groups/pty.ts, annotated `x-websocket: true` in OpenAPI). Because header auth is impossible there, it uses a single-use ticket: POST /api/pty/:ptyID/connect-token requires header `x-opencode-ticket: 1` (forces a CORS preflight so a cross-origin page cannot mint one) plus an origin check, returns `{ ticket: uuid, expires_in: 60 }` from an in-memory TTL cache (packages/core/src/pty/ticket.ts, 60 s, capacity 10 000, consumed via `Cache.invalidateWhen` so it is atomically single-use). `hasPtyConnectTicketURL(url)` makes the global Authorization middleware skip credential checks for exactly that path when `?ticket=` is present, and the handler validates the ticket itself.
- PTY wire format (packages/core/src/pty/protocol.ts): outbound frames are raw UTF-8 terminal text; ONE control frame = 0x00 byte followed by UTF-8 JSON `{"cursor": n}` sent after replay so a client can reconnect with `?cursor=`. Replay is chunked at 64 KiB. Inbound frames are text or binary UTF-8, invalid UTF-8 is dropped. Close codes: 1000 normal, 4404 "session not found"/"session exited".
- Multi-project/multi-workspace scoping is per-REQUEST middleware, not per-connection: packages/server/src/location.ts resolves a `Location.Ref` from query `location[directory]` / `location[workspace]` (OpenAPI deepObject style) or headers `x-opencode-directory` / `x-opencode-workspace`, falling back to process.cwd(), then provides a whole per-location service layer via `LocationServiceMap.get(ref)`. Session-scoped routes instead use packages/server/src/middleware/session-location.ts, which SELECTs directory/workspace_id from the session row in SQLite and derives the location from the session itself (404 SessionNotFoundError if absent). Location-scoped responses are wrapped as `{ location: Location.Info, data: T }` (schema/src/location.ts `response()`).
- Concurrency model: the server is stateless per request; each SSE subscriber gets its own bounded queue (256) via `EventV2.allBounded`; each PTY WebSocket gets its own unbounded outbox queue drained by a single writer to preserve ordering. Concurrent clients on the same session are reconciled by the durable log, not by locking: POST /api/session/:id/prompt takes an optional client-supplied `id` (idempotency), a `delivery: "steer" | "queue"` field, and `resume?: boolean`, and returns `SessionInput.Admitted = { admittedSeq, id, sessionID, prompt, delivery, timeCreated, promotedSeq? }` — the client learns exactly where its input landed in the sequence. GET /api/session/active returns `{ data: Record<SessionID, {type:"running"}> }` for foreground drains owned by THIS process; POST /api/session/:id/interrupt is a no-op if idle.
- Errors are declared per-endpoint as Effect tagged error classes with an httpApiStatus annotation (packages/protocol/src/errors.ts): InvalidRequestError(400, +kind/field), UnauthorizedError(401), ForbiddenError(403), SessionNotFoundError(404, +sessionID), MessageNotFoundError(404), PermissionNotFoundError(404), QuestionNotFoundError(404), PtyNotFoundError(404), ProviderNotFoundError(404), InvalidCursorError(400), ConflictError(409, +resource), ServiceUnavailableError(503, +service), UnknownError(500, +ref). They serialize as `{_tag, message, ...}` and the generated client rethrows them verbatim when the status is declared.
- Pagination is opaque cursors that embed the original query: `SessionsCursor` = base64url(JSON of the query struct + an `anchor` {id, time, direction}) with `make`/`parse` statics (protocol/src/groups/session.ts lines 49-104). Responses return `{ data, cursor: { previous?, next? } }`. Same pattern for /api/session/:id/message.
- Electron desktop mirrors DeskMinis almost exactly and is worth copying: packages/desktop/src/main/index.ts picks a free port by listening on 0 then closing, generates `password = randomUUID()`, and packages/desktop/src/main/server.ts forks `sidecar.js` as an Electron `utilityProcess` (serviceName "opencode server", stdio piped into the app log) and hands it `{type:"start", hostname, port, password, userDataPath}` over `postMessage`; sidecar.ts sets OPENCODE_SERVER_PASSWORD/USERNAME + XDG_STATE_HOME=userData, forces loopback into NO_PROXY, loads system CAs, and calls `Server.listen({..., cors:["oc://renderer"]})`. Readiness is a `{type:"ready"}` message with a 60 s stall timeout, then an independent health poll every 100 ms against /api/health with Basic auth. Shutdown: postMessage stop -> 6 s -> child.kill(). The renderer receives `{url, username, password}` over IPC (`awaitInitialization`).
- CORS is an allowlist function (packages/server/src/cors.ts `isAllowedCorsOrigin`): any http://localhost:*, http://127.0.0.1:*, `oc://renderer` (the Electron custom scheme), tauri origins, `*.opencode.ai`, plus explicit extras.
- Embedded/in-process mode reuses the identical HTTP stack with zero sockets: packages/sdk-next/src/opencode.ts builds `createEmbeddedRoutes()` into a `HttpRouter.toWebHandler`, wraps it as a fake `fetch`, and feeds it to the SAME generated Effect client (`OpenCode.make({baseUrl: "http://opencode.local"})`). One protocol, two transports — no second in-process API surface to keep in sync.
- A generic OpenAPI-driven CLI client exists: `opencode api <operationId|METHOD /path>` (packages/cli/src/commands/handlers/api.ts) fetches /openapi.json from the running daemon, resolves `operationId` -> method+path, interpolates `{param}` path params and puts leftovers in the query string, and reuses the daemon's discovered url+Basic headers. ~85 lines total.
- mDNS/LAN publishing exists but is minimal and legacy-side only: packages/opencode/src/server/mdns.ts uses `bonjour-service` to publish `{ name: "opencode-<port>", type: "http", host: "opencode.local", port, txt: { path: "/" } }`, and packages/opencode/src/server/server.ts refuses to publish when hostname is loopback. There is no discovery/browse side and no pairing in the repo.
- Cross-host session sync is modelled as durable-event replay over HTTP (packages/opencode/src/server/routes/instance/httpapi/groups/sync.ts): POST /sync/start, POST /sync/replay with `{ directory, events: [{id, aggregateID, seq, type, data}] }` -> `{sessionID}`, POST /sync/steal `{sessionID}` (transfer ownership into this workspace), POST /sync/history `Record<aggregateID, seq>`. Backed by `EventV2.replay/replayAll/claim` in packages/core/src/event.ts, which validates that a replayed seq is exactly latest+1, dies on divergence (`Replay diverged at aggregate X sequence N`), verifies byte-equality of already-stored events for idempotent re-replay, and enforces an `owner_id` on the aggregate sequence row (strictOwner).

## Formats
- Endpoint declaration (packages/protocol/src/groups/session.ts): `HttpApiEndpoint.post("session.prompt", "/api/session/:sessionID/prompt", { params: { sessionID: Session.ID }, payload: Schema.Struct({ id: SessionMessage.ID.pipe(Schema.optional), prompt: PromptInput.Prompt, delivery: SessionInput.Delivery.pipe(Schema.optional), resume: Schema.Boolean.pipe(Schema.optional) }), success: Schema.Struct({ data: SessionInput.Admitted }), error: [ConflictError, SessionNotFoundError] }).middleware(sessionLocationMiddleware).annotateMerge(OpenApi.annotations({ identifier: "v2.session.prompt", summary: "Send message" }))
- SSE declaration + frame: `success: HttpApiSchema.StreamSse({ data: EventSchema })` produces `Content-Type: text/event-stream` and frames written by effect/unstable/encoding/Sse as `event: message\ndata: {"id":"evt_...","type":"session.next.text.delta","data":{...}}\n\n`; keepalive is the bare comment line `: heartbeat\n\n` every 15 s (packages/server/src/handlers/event.ts).
- Event envelope schema (packages/schema/src/event.ts `define`): `{ id: Event.ID /* "evt_"+ascending */, type: Schema.Literal(<name>), data: Schema.Struct(fields), durable?: { aggregateID: string, seq: int, version: int }, location?: { directory: AbsolutePath, workspaceID?: string }, metadata?: Record<string, unknown> }`; durable definitions declare `durable: { aggregate: "sessionID", version: 1 }` at definition time.
- Legacy v1 event frame (packages/opencode/.../handlers/event.ts): `{ id, type, properties }` — note `properties` instead of `data`, plus periodic `{type:"server.heartbeat", properties:{}}` and a terminal `server.instance.disposed`.
- Admitted-input response (packages/schema/src/session-input.ts): `{ admittedSeq: NonNegativeInt, id: SessionMessage.ID, sessionID, prompt, delivery: "steer"|"queue", timeCreated: DateTimeUtcFromMillis, promotedSeq?: NonNegativeInt }`
- Location-scoped response wrapper (packages/schema/src/location.ts): `Schema.Struct({ location: Location.Info /* {directory, workspaceID?, project:{id,directory}} */, data: T })`; non-located routes use the plain `{ data: T }` envelope which codegen unwraps.
- Tagged error wire shape (packages/protocol/src/errors.ts): `Schema.TaggedErrorClass("SessionNotFoundError", { sessionID: Schema.String, message: Schema.String }, { httpApiStatus: 404 })` -> body `{"_tag":"SessionNotFoundError","sessionID":"ses_...","message":"Session not found: ses_..."}`
- Generated Promise call descriptor (packages/client/src/generated/client.ts): `request<{readonly data: SessionsCreateOutput}>({ method: "POST", path: `/api/session`, body: {...}, successStatus: 200, declaredStatuses: [401,400], empty: false }).then(v => v.data)`; SSE: `sse<EventsSubscribeOutput>({ method:"GET", path:`/api/event`, successStatus:200, ... })` returning `AsyncIterable`.
- Daemon registration file `$XDG_STATE_HOME/opencode/server.json` (mode 0600): `{ "id": "<uuid>", "version": "1.18.5", "url": "http://127.0.0.1:4096", "pid": 12345 }`; sibling `password` file holds `randomBytes(32).toString("base64url")`.
- Auth header: `Authorization: Basic base64("opencode:<password>")`, or query `?auth_token=base64("opencode:<password>")` for WebSocket/EventSource contexts; failure response carries `www-authenticate: Basic realm="Secure Area"`.
- PTY ticket: `POST /api/pty/:ptyID/connect-token` with header `x-opencode-ticket: 1` -> `{ location: {...}, data: { ticket: "<uuid>", expires_in: 60 } }`; then `ws://host/api/pty/<id>/connect?location[directory]=/abs&cursor=123&ticket=<uuid>`.
- PTY binary framing: server->client either a UTF-8 text frame (terminal output) or a binary frame whose byte 0 is 0x00 followed by UTF-8 JSON `{"cursor":<int>}`; client->server raw UTF-8 keystrokes; replay chunked at 65536 chars.
- Location addressing on any request: query `?location[directory]=/abs/path&location[workspace]=<id>` (OpenAPI style deepObject/explode) or headers `x-opencode-directory: <urlencoded abs path>` / `x-opencode-workspace: <id>`; the v2 SDK's request interceptor rewrites the headers into query params for GET/HEAD (packages/sdk/js/src/v2/client.ts).
- Opaque list cursor: `base64url(JSON.stringify({ ...originalQuery, anchor: { id, time: epochMillis, direction: "next"|"previous" } }))`, branded `SessionsCursor`, returned as `{ data, cursor: { previous?, next? } }`.
- Sync replay payload (packages/opencode/.../groups/sync.ts): `POST /sync/replay { directory: string, events: [{ id, aggregateID, seq, type, data }] }` -> `{ sessionID }`; `POST /sync/steal { sessionID }`; `POST /sync/history` takes `Record<aggregateID, seq>`.

## Lessons for DeskMinis
- ADOPT: split the event vocabulary into durable vs live. DeskMinis currently pushes everything over one JSON-RPC notification channel; OpenCode persists every semantically meaningful event with a per-session monotonic `seq` and treats only `*.delta` text/tool-input chunks as droppable. This single decision is what makes reconnect, history, LAN sync (M3) and multi-window all fall out for free. Add `durable: { aggregateID, seq, version }` to your event envelope now, before M2, because retrofitting sequence numbers after skills/memory events exist is painful.
- ADOPT: a resumable per-session subscription. `GET /api/session/:id/event?after=<seq>` replays from SQLite then continues live, implemented as read-after-seq + a sliding(1) wake channel that re-reads the DB (packages/core/src/event.ts `durable`). Give minisd a `session.subscribe({sessionID, afterSeq})` that does exactly this; then a dropped WebSocket, an Electron window reload, or a laptop sleep costs nothing. Keep the global firehose lossy on purpose (OpenCode uses a 256-slot dropping queue that fails the stream and lets the client reconnect) rather than growing unbounded buffers.
- ADOPT: one schema source, generated clients, committed output, CI drift check. `compile(Api) -> emitPromise/emitEffect -> write` with `check:generated` = regenerate + `git diff --exit-code` (packages/client/package.json). For DeskMinis: declare each JSON-RPC method's params/result once (zod or TypeBox), generate the Vue-side typed client, commit it, and fail CI on drift. Do NOT hand-write a parallel `api.ts` in the renderer — OpenCode explicitly forbids a second schema identity (packages/schema/AGENTS.md).
- ADOPT: name events `domain.subject.verb-ed` with started/delta/ended triples, and version durable ones. `session.next.tool.input.started|delta|ended`, `session.next.step.started|ended|failed`. The started/ended pairing is what lets a UI render collapsible tool cards without inventing client-side state machines, and `version` on the durable definition lets you evolve payloads while old rows stay replayable (`versionedType(type, version)` = `"type.2"`).
- ADOPT: the Electron sidecar pattern verbatim — it is the closest match to minisd. packages/desktop/src/main/{index,server,sidecar}.ts: bind port 0 to grab a free port, `randomUUID()` as the per-run secret, fork the daemon as a child with the secret over an IPC message (never argv, never a file), wait for an explicit `{type:"ready"}` with a stall timeout, THEN poll a /health endpoint before showing UI, and stop with graceful-message -> timeout -> kill. Also copy `ensureLoopbackNoProxy()` (127.0.0.1/localhost/::1 into NO_PROXY): corporate proxy env vars silently break localhost transports on Windows and this is a real bug you will otherwise hit.
- ADOPT: a state-directory registration file so a second client (CLI, second window, future minis-cli) can attach to an already-running daemon: `{ id, version, url, pid }` written tmp+rename at mode 0600, plus a sibling secret file. Crucially, OpenCode never trusts the file alone — it health-checks WITH auth before signalling the pid, precisely because a stale pid may have been reused (comment at daemon.ts line ~157). Also compare a `version` field and restart the daemon on mismatch instead of speaking a stale protocol.
- ADOPT (with upgrade): OpenCode's auth is one shared Basic password and nothing else — no per-client identity, no expiry, no scopes, and it degrades to fully open when unset. DeskMinis's per-run bearer token is already stronger. Keep it, but add the two things OpenCode got right: (a) an escape hatch for contexts that cannot set headers (they use `?auth_token=<base64>` and the web client strips it from the URL immediately), and (b) an explicit origin allowlist for the Electron custom scheme (`oc://renderer`) rather than `*`.
- ADOPT: the single-use ticket pattern for any privileged upgrade/stream you can't put a header on. `POST .../connect-token` requires a custom request header (forcing a CORS preflight so a hostile page can't mint one) + origin check, returns a uuid with `expires_in: 60` from a TTL cache consumed atomically via invalidateWhen. If DeskMinis ever exposes a terminal or file-download URL to the webview, this is the pattern — not a long-lived query token.
- ADOPT: idempotent, sequenced writes. `session.prompt` accepts a client-supplied message `id` and returns `Admitted { admittedSeq, promotedSeq? }`, plus `delivery: "steer" | "queue"` to say what should happen if the agent is already running, and a `409 ConflictError`. DeskMinis's agent loop should return the admitted sequence from its send RPC so the UI can correlate optimistic bubbles with durable events instead of guessing.
- ADOPT: per-request scoping instead of per-connection sessions. Every OpenCode route resolves its workspace/directory from `location[directory]`/`x-opencode-directory`, and session routes derive it from the session row in SQLite. The server holds no per-connection state, so N Electron windows and a CLI can hammer it concurrently with no affinity logic. If DeskMinis's WebSocket connection currently carries implicit 'current project' state, move it into the request params.
- ADOPT: serve your own machine-readable contract from the daemon and build the debug CLI on top of it. OpenCode exposes /openapi.json and gets a whole generic client in 85 lines (`opencode api <operationId>`). minisd should expose an `rpc.discover`-style method (or a static schema doc) — it costs almost nothing and gives you a scriptable debugging surface plus a drift-detection anchor.
- ADOPT: run embedded and networked over the SAME protocol. packages/sdk-next/src/opencode.ts turns the router into an in-memory `fetch` and feeds the identical generated client. If DeskMinis ever wants an in-process mode (tests, a headless CLI, or an embedded minisd inside Electron main), implement it as an in-memory JSON-RPC transport behind the same client interface — never as a second direct-call API, which inevitably diverges.
- ADAPT for M3: OpenCode's LAN story is event-sourced replay over the normal HTTP API (`POST /sync/replay` with `[{id, aggregateID, seq, type, data}]`, `POST /sync/steal` for ownership transfer, `POST /sync/history` for a per-aggregate watermark vector), backed by strict validation — seq must be exactly latest+1, byte-equality on re-replayed events makes retries idempotent, and an `owner_id` column on the aggregate sequence row prevents two hosts writing the same session. This is a better fit for your PortableRecord plan than ad-hoc record diffing: make the durable event log the sync unit and the watermark map the sync protocol.
- AVOID / be warned: mDNS in OpenCode is publish-only, ~47 lines, wrapped in silent try/catch, uses `bonjour-service`, and refuses to publish on loopback (packages/opencode/src/server/mdns.ts). There is NO browse side, no pairing, no TXT-record capability negotiation, no TLS. Do not treat it as a reference for M3 — you will need to design discovery + pairing + peer auth yourself, and note that OpenCode's single-shared-password model does not survive a LAN threat model at all.
- AVOID: shipping multiple client generations at once. OpenCode currently maintains a hey-api v1 SDK, a hey-api v2 SDK, and the httpapi-codegen promise/effect clients, plus a runtime `detectServerProtocol()` probe that GETs /global/health then /api/health and sniffs for a `pid` field. That is the cost of changing the wire shape (`{id,type,properties}` -> `{id,type,data,durable,location}`) after clients shipped. For DeskMinis: freeze the envelope shape and add a version field/capability list to the handshake NOW, so M2/M3 additions are additive.
- AVOID: putting anything except a genuine byte stream on WebSocket. In the whole OpenCode repo the only `request.upgrade` is the PTY route; all request/response and all event fan-out ride HTTP + SSE. DeskMinis already has a WebSocket, which is fine, but the lesson is that the request/response half should stay strictly request-shaped (id-correlated, per-request scoping params, declared error set) and the streaming half should be a separately-resumable, sequence-numbered subscription — not an undifferentiated notification firehose.
- ADOPT: declare the error set per method with a stable tag + numeric status and let the generated client rethrow it verbatim (packages/protocol/src/errors.ts). Anything undeclared collapses into one `ClientError` with kinds Transport / UnexpectedStatus / MalformedResponse / UnsupportedContentType. For DeskMinis JSON-RPC this maps to: a documented error-code table per method (permission denied, session not found, provider unavailable, conflict) plus one catch-all transport error — and a UI that can branch on `_tag`/code rather than parsing message strings.
