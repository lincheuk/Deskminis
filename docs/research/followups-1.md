# OpenMinis iOS Sync V2 (SyncCore + Syncable registry + iCloud/LAN transports) — C:/Users/24739/Downloads/openminis1/OpenMinis/src/ios/Agent/Sync/V2/

## Key findings
- THE PER-TYPE `transports` ALLOWLIST DOES NOT EXIST IN CODE. SyncTransport.swift lines 56-57 say a transport's `name` is 'used in logs and to filter per-record `transports` allowlists declared in SyncTypeMetadata', but SyncTypeMetadata (Syncable.swift lines 192-241) has no transports field, and SyncCore.sendNow (SyncCore.swift lines 471-511) fans EVERY batch out to EVERY registered transport with zero per-type filtering. Secrets (ProviderConfigV2/ProviderInstanceV3/EnvVarV2/EnvVarItem/MCPServersV2/MCPServerItem) would go over LAN unfiltered if a LAN transport were ever registered.
- The only guard keeping secrets off LAN today is that LAN doesn't run at all: LANTransport.isImplemented = false (LANTransport.swift line 37) and SyncCore.register refuses it ('refusing to register LANTransport (skeleton only)', SyncCore.swift lines 184-190). Every LANTransport method is preconditionFailure; SyncV2Bootstrap.startIfEnabled (SyncV2Bootstrap.swift line 172-174) registers only ICloudSharedZoneTransport.
- Effective type→zone routing lives ONLY inside the iCloud transport: ICloudSharedZoneTransport.zoneByRecordType (ICloudSharedZoneTransport.swift lines 39-75). minis-shared: SessionV2, MessageV2, CompactMarkerV2, SessionFileV2, SkillV2, SoulV2, MemoryGlobalV2, MemoryDailyV2. minis-devices: SyncDeviceV2. minis-secrets: ProviderConfigV2, EnvVarV2, EnvVarItem, ProviderInstanceV3, ProviderModelEntryV3, ProviderModelGroupV3, MCPServersV2, MCPServerItem. Types missing from this map are SILENTLY DROPPED at the push loop's zone guard — comments document two real incidents (V3 provider types and MCPServersV2 never reached CloudKit).
- Scope metadata per type (SyncedTypes.swift): .perObject → SessionV2 only. .perParent(SessionV2) → MessageV2, CompactMarkerV2, SessionFileV2. .global → everything else (SkillV2, ProviderConfigV2, MCPServersV2, MCPServerItem, ProviderInstanceV3, ProviderModelEntryV3, ProviderModelGroupV3, EnvVarV2, EnvVarItem, SyncDeviceV2, SoulV2, MemoryGlobalV2, MemoryDailyV2). Conflict policies: LWW-by-updatedAt for most; .alwaysAccept for CompactMarkerV2 + SyncDeviceV2; .lastWriteWinsByServerEtag for SessionFileV2.
- Capability vectors: iCloud = [.deltaFetch, .assets, .persistence, .conflictDetect] (ICloudSharedZoneTransport.swift line 24); LAN = [.pushObserve, .conflictDetect] — 'Notably absent: .persistence (no central store) and .deltaFetch (peer state is opaque)' (LANTransport.swift line 33).
- SyncCore does NOT compensate for a transport lacking persistence/deltaFetch/fullFetch. fetchNow (SyncCore.swift line 717-729) iterates only `transports where t.capabilities.contains(.deltaFetch)` — a LAN transport is never polled. fullFetchAndReconcile (lines 744-755) calls fullFetch on all transports, but LAN's documented contract is 'peers don't store history; LAN cannot satisfy fullFetch in general. Return an empty batch and document that callers must rely on iCloud for history' (LANTransport.swift lines 20-22). There is no cross-transport backfill or gap-repair logic anywhere in SyncCore.
- Consequence: a late-joining or wiped device on LAN-only receives ONLY live pushObserve frames sent while it is online. All history backfill (fresh install, forceFullSync, per-session force-pull) is iCloud-only — fetchSessionPortables (SyncCore.swift lines 769-786) even hard-casts to ICloudSharedZoneTransport and returns empty if none is registered. Additionally, tombstone reconcile after fullFetch is disabled entirely (audit C2, SyncCore.swift lines 731-750), so even iCloud full-fetch never deletes local-only ghosts.
- Multi-transport merge model: broadcast-to-all, 'first one to deliver a record wins (others see it as a no-op because the record id already merged locally)' (SyncCore.swift lines 38-40). Duplicate/echo protection: recentlyPushedIds map with echoTTL=30s stamped BEFORE the network call (lines 177-179, 461-467); inbound applies in 25-record chunks with 50ms yields; records of unregistered types are skipped, and minimumCompatibleVersion > local version blocks apply (lines 628-631).
- UploadPolicy (UploadPolicy.swift) is iCloud-push gating only, filtered at ChatStore.markDirty so disabled types never enter the dirty queue: 6 per-category UserDefaults toggles (chatSessions, sessionFiles, skills, providers, envVars, memory; keys cloudSync.v2.upload.<cat>), default permissive=true; SyncDevice/SyncDeviceV2 always allowed; unknown types pass through (forward-compat); turning a category off does NOT retract records already on iCloud. Size cap: maxFileSizeBytes default 1 MB (key cloudSync.v2.upload.maxFileSize) for SessionFile assets, enforced at markDirty. No per-type push windows exist in UploadPolicy.
- Throttling/windows actually live in SyncCore (SyncCore.swift): 3s debounce (defaultSendDelay line 156); chained-send delay = 5s base × 1x (user on sync sheet) / 3x (foreground) / 4x (background) × 2x if cellular (currentSendDelay lines 87-95); CloudKit 429 retry-after gate nextEarliestSendAt (lines 119-123, 343-347, 499-508); user pause persisted in UserDefaults cloudSync.v2.pausedUntil (lines 129-153); sendDeferred flag suppresses sends while an agent loop streams (lines 158-161); per-cycle batch cap = LIMIT 100 dirty rows (ChatStore.swift line 4814); MemoryDailyV2 pushes only the most recent 30 days (SyncedTypes.swift line 700).
- A second gating layer exists in ChatStore: v2SyncRecordTypes whitelist (ChatStore.swift lines 4730-4753) feeds loadDirtyRecords(v2Only:true)'s WHERE-IN. Types absent from this list have dirty rows written but never loaded — this silently blackholed MemoryGlobalV2/MemoryDailyV2 and MCPServersV2 in past incidents (comments T-soulv2-memory-whitelist, T-mcp-per-server-sync). Any new record type must be added in THREE places: Syncable registration, this whitelist, and zoneByRecordType.
- ANSWER TO THE CORE QUESTION: P2P mDNS/LAN sync CANNOT fully replicate state peer-to-peer under this architecture. (a) LAN is a never-registered skeleton. (b) Even the designed LAN transport has no persistence/deltaFetch and an empty fullFetch — a late joiner or wiped device gets nothing historical; the durable hub (iCloud here; the 'optional hub' in a DeskMinis port) is REQUIRED for history backfill, making it effectively non-optional unless peers add a queryable local history store + peer-to-peer catch-up protocol. (c) Secrets distribution over LAN is currently unrestricted by design gap — the per-type transports allowlist is mentioned in a comment but unimplemented, and the secret payloads are base64-encoded (env vars explicitly NOT encrypted), so a DeskMinis LAN transport must either implement the allowlist (secrets → hub/E2E channel only) or add real transport-layer encryption before letting secrets ride mDNS.
- Sync history/versioning per type: SyncedTypes.swift shows a consistent evolution pattern away from whole-file LWW records toward per-entry records because whole-file LWW silently drops the losing side's additions: EnvVarV2 (whole-file, legacy inbound-only) → EnvVarItem (per-variable); MCPServersV2 (whole-file, legacy) → MCPServerItem (per-server, recordName = server name); ProviderConfigV2 (whole-file, dual-write outbound during transition) → ProviderInstanceV3/ProviderModelEntryV3/ProviderModelGroupV3 (per-record, with extrasJson forward-compat envelope and removedMembersJson member-tombstones).

## Data formats
- PortableRecord (C:/Users/24739/Downloads/openminis1/OpenMinis/src/ios/Agent/Sync/V2/PortableRecord.swift): Codable/JSON-able envelope {id:{type,id}, fields:{cloudKey:PortableFieldValue}, assets:{key:PortableAsset}, schemaVersion:Int, minimumCompatibleVersion:Int?, unknownFields:{...}, updatedAt:Date}. unknownFields MUST round-trip on write-back so older clients never strip newer clients' fields.
- PortableFieldValue tagged JSON encoding: {"t": "null|string|int|double|bool|date|data|json", "v": <value>} — designed so both CKRecord setters (iCloud) and JSON frames (LAN) consume the same enum.
- SyncRecordID wire/dirty-queue string format: "Type:id" (e.g. "MessageV2:AB12CDEF-..."); ChatStore.clearDirtyRecord parses on the first ':'. SessionFileV2 uses a composite id "sessionId:relativePath".
- Dirty queue: SQLite table sync_dirty_records(record_type, record_id, zone_name, operation['upsert'|'delete'], priority[0=user,1=migration], created_at) in ChatStore.swift; loadDirtyRecords(v2Only:) uses a WHERE record_type IN (v2 whitelist) plus ORDER BY priority ASC, Session-before-Message CASE, created_at DESC, LIMIT 100 (line 4814).
- CloudKit: CKRecord per PortableRecord in 3 fixed private-DB zones (container iCloud.com.openminis.app); payloads >750,000 bytes become CKAsset instead of inline string (assetInlineThreshold, ICloudSharedZoneTransport.swift line 80); etag/systemFields cache persisted to Library/MinisChat/cloud-sync-v2/etag-cache.plist (cap 5000 records).
- Planned LAN wire format (comment-only, LANTransport.swift lines 9-26): Bonjour service "_minis-sync._tcp" via NWListener/NWBrowser, JSON-encoded SyncOutboundBatch over WebSocket per peer, assets multiplexed as length-prefixed binary frames, deletes broadcast as tombstone-marked PortableRecords.
- Secrets encodings (SyncedTypes.swift): SyncedProviderConfig.secretsJsonBase64 = base64-wrapped secrets blob (field 'secretsJson'); SyncedProviderInstanceV3.secretBlob = base64-wrapped Keychain secret + secretKind ('apiKey'|'manual-oauth-token'|'oauth-token'); SyncedEnvVar.valueB64 = base64(utf8(value)) with explicit comment 'base64 is encoding, not encryption'; SyncedMCPServer.entryJson = verbatim ServerEntry JSON whose headers/env can hold literal tokens.
- Config-file singletons synced as whole-text records: MCPServersV2 = /var/minis/mcp-servers/servers.json verbatim; SoulV2 = SOUL.md full text; MemoryGlobalV2 = GLOBAL.md full text; MemoryDailyV2 = one record per day (id 'YYYY-MM-DD') holding JSON [MemoryEntry], only last 30 days pushed, merged by set-union on timestamp.

## Reusable for desktop
- PortableRecord envelope design: transport-neutral tagged-value record ({t,v} field encoding) with unknownFields round-trip preservation, per-type schemaVersion, and minimumCompatibleVersion skip-gate — directly portable to JSON over WebSocket/mDNS between Electron peers and lets old/new app versions coexist without stripping each other's fields.
- TransportCapabilities OptionSet (pushObserve / deltaFetch / assets / persistence / conflictDetect) + a broadcast SyncCore that routes fetch operations by capability — clean seam for a DeskMinis architecture with one LAN transport and one hub transport; but ALSO implement the per-type transports allowlist OpenMinis only documented, so secret-bearing types can be pinned to the hub/E2E channel.
- Crash-safe dirty queue in SQLite (markDirty writes the row first, debounced send later; operation upsert/delete; priority 0=user vs 1=backfill; parent-type-before-child ordering; LIMIT-per-cycle chained sends) — the whole outbound pipeline is transport-agnostic and maps 1:1 onto an Electron main-process SQLite store.
- Echo suppression pattern: stamp pushed record ids into a TTL map (30s) BEFORE the network call so a racing poll doesn't re-apply your own write and thrash the renderer — same race exists with any polling hub + push LAN combo.
- Conflict policy declared per type at registration (LWW-by-date keypath / server-etag / always-accept / custom closure) plus per-record rather than whole-file sync for anything users edit on two machines (EnvVarItem, MCPServerItem, ProviderInstanceV3 lessons — whole-file LWW silently loses concurrent additions).
- Zone-per-sensitivity partitioning (minis-shared / minis-devices / minis-secrets): keeps 'wipe my synced secrets' a one-zone operation and lets the secrets category toggle off without breaking chat sync — for DeskMinis, partition hub storage the same way and make the secrets partition hub-only or E2E-encrypted.
- Device presence via an always-allowed SyncDevice heartbeat record carrying uploadTypes CSV (peers can see what each device syncs) — useful as-is for a DeskMinis peer roster over mDNS.
- Adaptive throttling model: base delay × context multipliers (visible-sync-UI / foreground / background / metered network) + server retry-after gate + user pause-until — translates directly to an Electron app (window focus, power state, metered connection).
- Operational lesson worth designing around: OpenMinis needed a type registered in THREE separate lists (registry, dirty-queue whitelist, zone map) and shipped multiple silent-drop bugs from missing one — a desktop port should derive all routing from single-source-of-truth type metadata (i.e., actually put zone + transports in SyncTypeMetadata).
- Explicit backfill architecture decision: peers-without-history + empty fullFetch means a hub is mandatory for late joiners. For DeskMinis, either (a) accept hub-required-for-backfill and label it so, or (b) give each desktop peer a durable outbox/history store + a 'fetch since vector/lastSeen' peer protocol — the LANTransport skeleton's fetchChanges('anything since lastSeen') sketch is the starting point.
