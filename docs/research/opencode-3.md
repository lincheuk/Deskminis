# Agent loop, provider abstraction, and session storage in sst/opencode (packages/core, packages/llm, packages/opencode)

## Key findings
- TWO GENERATIONS COEXIST. `packages/opencode` is v1 (legacy, still the shipping CLI, version 1.18.5) and drives the loop through the Vercel AI SDK (`streamText` from `ai`, plus ~18 `@ai-sdk/*` provider packages listed in C:/Users/24739/Downloads/opencode-ref/packages/opencode/package.json). `packages/core` is v2 and drives the loop through opencode's own `@opencode-ai/llm` package with zero AI SDK involvement. Both are live in the same binary; v1 picks per-call between them (see next finding).
- V1 RUNTIME SELECTION (AI SDK vs native): C:/Users/24739/Downloads/opencode-ref/packages/opencode/src/session/llm/native-runtime.ts `statusWithFetch()` only returns `supported` when providerID is `openai`/`anthropic`/`opencode*` AND `model.api.npm` is one of `@ai-sdk/openai`, `@ai-sdk/openai-compatible`, `@ai-sdk/anthropic` AND an API key exists; otherwise it returns `{type:"unsupported", reason}` and C:/Users/24739/Downloads/opencode-ref/packages/opencode/src/session/llm.ts falls back to `streamText(...)` with `maxRetries: input.retries ?? 0`.
- V2 AGENT LOOP is in C:/Users/24739/Downloads/opencode-ref/packages/core/src/session/runner/llm.ts. Structure: outer `run({sessionID, force})` -> `while(shouldRun)` over queued prompts -> inner `while(needsContinuation)` over steps -> `runTurn` -> `runTurnAttempt`. Exactly ONE `llm.stream(request)` per turn; the runner (not the SDK) owns tool dispatch, persistence and continuation. `needsContinuation` is set true the moment any non-provider-executed `tool-call` event arrives.
- TURN/STEP LIMIT: there is no hard default cap in v2. `const isLastStep = agent.info?.steps !== undefined && currentStep >= agent.info.steps` — only if the agent config sets `steps`. On the last step the runner passes `tools: []`, `toolChoice: "none"`, and appends `Message.assistant(MAX_STEPS_PROMPT)` (C:/Users/24739/Downloads/opencode-ref/packages/core/src/session/runner/max-steps.ts — a hard-worded 'MAXIMUM STEPS REACHED / respond with text ONLY' instruction). V1 does the same with `const maxSteps = agent.steps ?? Infinity` (prompt.ts:1178). The 'max turns = 20' default appears only in the *proposal* doc C:/Users/24739/Downloads/opencode-ref/packages/llm/DESIGN.md, not in shipped code.
- TOOL EXECUTION CONCURRENCY (v2): unbounded and eager. Each tool call is forked into an Effect `FiberSet` (`FiberSet.run(toolFibers)`) as its event arrives mid-stream, wrapped in `Effect.uninterruptibleMask`. After the stream ends the runner does `Effect.raceFirst(FiberSet.join(fibers), FiberSet.awaitEmpty(fibers))` before starting the next turn. Publication of results is serialized by a 1-permit semaphore (`Semaphore.makeUnsafe(1).withPermit`) so DB writes are ordered. No per-tool timeout, no concurrency cap.
- COMPACTION (v2) C:/Users/24739/Downloads/opencode-ref/packages/core/src/session/compaction.ts. Two triggers: (1) proactive `compactIfNeeded` before sending — estimates tokens of `{system, messages, tools}` via `Token.estimate(JSON.stringify(...))` and fires if `> context - max(maxTokens, buffer)`; defaults `DEFAULT_BUFFER = 20_000`, `DEFAULT_KEEP_TOKENS = 8_000`, `SUMMARY_OUTPUT_TOKENS = 4_096`, `TOOL_OUTPUT_MAX_CHARS = 2_000`. (2) reactive `compactAfterOverflow` when the provider returns a context-overflow error and no assistant text has streamed yet.
- COMPACTION MECHANICS: history is flattened to plain text lines (`[User]: …`, `[Assistant tool call]: name(input)`, `[Tool result]: …` truncated to 2000 chars), split into `head` (to summarize) + `recent` (kept verbatim, ~8k tokens, split mid-message if needed). A second LLM call renders a fixed Markdown template (`## Objective / ## Important Details / ## Work State {Completed,Active,Blocked} / ## Next Move / ## Relevant Files`). Result is persisted as a `compaction` message; on rebuild it becomes ONE user message wrapped in `<conversation-checkpoint><summary>…</summary><recent-context>…</recent-context></conversation-checkpoint>` (C:/Users/24739/Downloads/opencode-ref/packages/core/src/session/runner/to-llm-message.ts).
- COMPACTION CONTROL FLOW uses a defect-as-signal trick: `Effect.die(new TurnTransitionError({_tag: "ContinueAfterCompaction"|"ContinueAfterOverflowCompaction", step}))`, caught by `Effect.catchDefect` in `runTurn`, which restarts the turn from compacted history. Post-overflow-compaction retry runs through `runAfterOverflowCompaction`, which explicitly refuses to recover a *second* overflow.
- RETRY (v2) lives entirely at the HTTP layer, NOT in the agent loop: C:/Users/24739/Downloads/opencode-ref/packages/llm/src/route/executor.ts — `MAX_RETRIES = 2`, `BASE_DELAY_MS = 500`, `MAX_DELAY_MS = 10_000`, jittered exponential (`Random.nextBetween(base*2^n*0.8, base*2^n*1.2)`), honors `retry-after-ms` / `retry-after` (seconds or HTTP-date). Retryable statuses: 429, 503, 504, 529 and >=500. Errors are classified into tagged reasons: AuthenticationReason(401/403), RateLimitReason(429), QuotaExceededReason, ContentPolicyReason, InvalidRequestReason(400/404/409/413/422, with `classification: "context-overflow"`), ProviderInternalReason, TransportReason, UnknownProviderReason.
- SECRET REDACTION in the executor is unusually thorough and worth copying: header/query/body redaction driven by one regex source (`authorization|api[-_]?key|access[-_]?token|refresh[-_]?token|id[-_]?token|token|secret|credential|signature|x-amz-signature`), plus a second pass that literally string-replaces any secret VALUE the request sent in case the response echoes it back. Response bodies capped at `BODY_LIMIT = 16_384`.
- RETRY (v1) is richer and user-facing: C:/Users/24739/Downloads/opencode-ref/packages/opencode/src/session/retry.ts — `RETRY_INITIAL_DELAY=2000`, factor 2, `RETRY_MAX_DELAY_NO_HEADERS=30_000`; never retries ContextOverflowError; special-cases `FreeUsageLimitError`/`GoUsageLimitError` bodies into an actionable `{reason, title, message, label, link}` payload shown in the UI; also pattern-matches plain-text 'rate limit'/'too many requests'/'exhausted'/'unavailable'. No model FALLBACK chain exists anywhere — a failed model is an error, not a switch.
- NO MODEL FALLBACK: I found no provider/model failover in either generation. `SessionRunnerModel.resolve` (C:/Users/24739/Downloads/opencode-ref/packages/core/src/session/runner/model.ts) picks exactly one model and fails with `ModelUnavailableError`/`ModelNotSelectedError`/`UnsupportedApiError`/`VariantUnavailableError`.
- PROVIDER ABSTRACTION (v2) is a custom 4-axis composition in `@opencode-ai/llm`, documented in C:/Users/24739/Downloads/opencode-ref/packages/llm/src/route/protocol.ts and implemented in route/client.ts: `Route = Protocol × Endpoint × Auth × Framing` (+ optional headers/defaults). `Protocol` owns `body.schema` + `body.from(LLMRequest)` and a streaming state machine `{event, initial(request), step(state,event)->[state, LLMEvent[]], terminal?, onHalt?}`. Protocols shipped: anthropic-messages, openai-chat, openai-compatible-chat, openai-responses, gemini, bedrock-converse (C:/Users/24739/Downloads/opencode-ref/packages/llm/src/protocols/index.ts). The stated design goal: 'lets DeepSeek, TogetherAI, Cerebras, etc. all reuse OpenAIChat.protocol without forking 300 lines per provider.'
- MODELS.DEV is the model catalog source, fetched at RUNTIME not build time (v2 shipping code): C:/Users/24739/Downloads/opencode-ref/packages/core/src/models-dev.ts fetches `https://models.dev/api.json`, caches to `Global.Path.cache/models.json` with a 5-minute freshness TTL, refreshes on a 60-minute schedule, uses a cross-process `Flock` so concurrent CLIs don't race, falls back to a compiled-in `OPENCODE_MODELS_DEV` snapshot, and can be disabled via `OPENCODE_DISABLE_MODELS_FETCH`. Schema includes cost tiers, `limit.{context,input,output}`, modalities, `reasoning_options` (effort/toggle/budget_tokens), and `status: alpha|beta|deprecated`.
- CATALOG -> ROUTE BRIDGE: C:/Users/24739/Downloads/opencode-ref/packages/core/src/session/runner/model.ts `fromCatalogModel()` maps the models.dev field `api.package` to a native protocol — `@ai-sdk/openai` -> OpenAIResponses.route + `Auth.bearer`; `@ai-sdk/anthropic` -> AnthropicMessages.route + `Auth.header("x-api-key", …)`; `@ai-sdk/openai-compatible` (+url) -> OpenAICompatibleChat.route + `Auth.bearer`. Everything else fails `UnsupportedApiError`. So the AI-SDK package name survives purely as a routing key. Model 'variants' (e.g. reasoning effort) are applied by merging `variant.headers`/`variant.body` via immer `produce`.
- PROVIDER PLUGINS: 33 provider plugins in C:/Users/24739/Downloads/opencode-ref/packages/core/src/plugin/provider.ts. Each is tiny and declarative — e.g. anthropic.ts (27 lines) only does `ctx.catalog.transform(...)` to inject `anthropic-beta: interleaved-thinking-2025-05-14,fine-grained-tool-streaming-2025-05-14` and `ctx.aisdk.sdk(...)` to lazily import the SDK. Provider-specific behavior is a *catalog patch*, not a code fork.
- PROMPT CACHING is on by default: C:/Users/24739/Downloads/opencode-ref/packages/llm/src/cache-policy.ts — default `"auto"` places 3 breakpoints (last tool definition, last system part, latest user message). Applied only for protocols in `RESPECTS_INLINE_HINTS = {"anthropic-messages", "bedrock-converse"}`; skipped for OpenAI/Gemini which cache implicitly. The runner also passes `providerOptions: { openai: { promptCacheKey } }` derived from the session id.
- PERSISTENCE IS SQLITE + DRIZZLE, EVENT-SOURCED. Single DB file at `Global.Path.data/opencode.db` (channel-suffixed on non-release channels); PRAGMAs set in C:/Users/24739/Downloads/opencode-ref/packages/core/src/database/database.ts: `journal_mode=WAL`, `synchronous=NORMAL`, `busy_timeout=5000`, `cache_size=-64000`, `foreign_keys=ON`, `wal_checkpoint(PASSIVE)`.
- EVENT LOG SCHEMA (C:/Users/24739/Downloads/opencode-ref/packages/core/src/event/sql.ts): `event_sequence(aggregate_id PK, seq, owner_id)` + `event(id PK, aggregate_id FK, seq, type, data JSON)` with `uniqueIndex(aggregate_id, seq)`. The aggregate id for sessions IS the sessionID. Total ordering via a monotonically incremented integer per aggregate — explicitly chosen because only one writer is allowed (see C:/Users/24739/Downloads/opencode-ref/packages/opencode/src/sync/README.md: 'Because only one device is allowed to write, we don't need any kind of sophisticated distributed system clocks or causal ordering').
- EVENT COMMIT is fully transactional and idempotent (C:/Users/24739/Downloads/opencode-ref/packages/core/src/event.ts `commitDurableEvent`): inside one `db.transaction`, it reads latest seq, runs all registered PROJECTORS, runs the caller's local `commit(seq)` hook, then inserts into `event_sequence` (upsert) and `event`. Replay of an already-stored seq is accepted only if `{id, versionedType, data}` deep-equal the stored row, else it dies with 'Replay diverged at aggregate X sequence N'. Duplicate event ids are rejected.
- PROJECTED READ MODEL: `session_message(id PK, session_id, type, seq, time_created, data JSON)` with `uniqueIndex(session_id, seq)` plus indexes on (session_id,type,seq) and (session_id,time_created,id) — C:/Users/24739/Downloads/opencode-ref/packages/core/src/session/sql.ts. Also `session`, `session_input`, `session_context_epoch`, `todo`, `session_share`, and legacy v1 `message`/`part` tables. Everything read by the agent loop goes through `session_message`, never through the raw event log.
- HISTORY WINDOWING (C:/Users/24739/Downloads/opencode-ref/packages/core/src/session/history.ts): a single SQL query selects rows with `seq >= latestCompaction.seq` OR (`type='system'` AND `seq > baselineSeq`). The 'context epoch' (`session_context_epoch{session_id PK, baseline TEXT, snapshot JSON, baseline_seq}`) stores the rendered system prompt so system-context churn doesn't invalidate the whole history.

- STEERING / QUEUEING: `session_input(id PK, session_id, prompt JSON, delivery, admitted_seq, promoted_seq NULL)` — two delivery modes `steer` (injected mid-run, resets step counter to 1) and `queue` (drained after the current run finishes). `SessionInput.promoteSteers(db, events, sessionID, cutoff)` only promotes inputs admitted BEFORE the cutoff sequence, so a prompt typed during a turn lands deterministically.

## Formats
- Route composition (packages/llm/src/route/client.ts): `Route.make({ id, provider?, protocol, endpoint, auth, framing, headers?, defaults? })` -> `Route`. `route.with(patch)` returns a NEW immutable route (merging headers/limits/generation/providerOptions/http); `route.model({id})` binds it into a `Model`. Compile pipeline is `compile(request) = applyCachePolicy(resolveRequestOptions(request))` -> `route.body.from(resolved)` -> validate against `route.body.schema` -> `route.prepareTransport(body, resolved)` -> `route.streamPrepared(prepared, request, runtime)`.
- Protocol interface (packages/llm/src/route/protocol.ts): `{ id: ProtocolID, body: { schema: Schema.Codec<Body, unknown>, from: (LLMRequest) => Effect<Body, LLMError> }, stream: { event: Schema.Codec<Event, Frame>, initial: (LLMRequest) => State, step: (State, Event) => Effect<[State, LLMEvent[]], LLMError>, terminal?: (Event)=>boolean, onHalt?: (State)=>LLMEvent[] } }`.
- Canonical LLMEvent union (packages/llm/src/schema/events.ts, 618 lines): `step-start | text-start | text-delta | text-end | reasoning-start | reasoning-delta | reasoning-end | tool-input-start | tool-input-delta | tool-call | tool-result | provider-error | finish` (+ usage). Every event carries optional `providerMetadata` as the escape hatch.
- Usage normalization (packages/llm/src/schema/events.ts): `{ inputTokens, outputTokens, nonCachedInputTokens, cacheReadInputTokens, cacheWriteInputTokens, reasoningTokens, totalTokens, providerMetadata }`. Documented invariant: `nonCachedInputTokens + cacheReadInputTokens + cacheWriteInputTokens === inputTokens` and `reasoningTokens <= outputTokens`. inputTokens/outputTokens are INCLUSIVE totals (AI-SDK convention); the breakdown fields are non-overlapping so consumers never subtract. `visibleOutputTokens` getter is the only subtraction, clamped at 0.
- ToolResultValue (packages/llm/src/schema/messages.ts): `{type:'json'|'text'|'error'|'content', value}`. `ToolOutput = {structured: unknown, content: ToolContent[]}` with round-trip helpers `ToolOutput.fromResultValue` / `ToolOutput.toResultValue` (0 content parts -> json; 1 text part -> text; else -> content).
- Tool declaration to model (packages/llm/src/tool.ts): `ToolDefinition { name, description, inputSchema: JsonSchema, outputSchema?: JsonSchema, cache? }`. `Tool.toDefinitions(record)` takes the tool NAME from the record key. Per-model JSON-Schema dialect fixups live in packages/llm/src/protocols/utils/tool-schema.ts: `ToolSchemaProjection.{gemini, moonshot, openAI, modelCompatibility}` — e.g. openAI flattens `anyOf` into one object and strips `type:'null'` branches; moonshot rewrites `prefixItems`/tuple `items` and drops `unevaluatedItems`.
- Sync wire format (packages/opencode/src/server/routes/instance/httpapi/groups/sync.ts): ReplayEvent `{id: 'evt…', aggregateID: string, seq: NonNegativeInt, type: string, data: Record<string,unknown>}`; ReplayPayload `{directory, events: NonEmptyArray<ReplayEvent>}`; HistoryPayload `Record<aggregateID, lastKnownSeq>`; HistoryEvent uses snake_case `aggregate_id`. Event `type` on the wire is version-stamped by `EventV2.versionedType(type, version)`.
- Session persisted message union (packages/schema/src/session-message.ts): `agent-switched | model-switched | user | synthetic | system | shell | assistant | compaction`, all sharing `{id: 'msg_…', metadata?, time:{created}}`. Assistant: `{agent, model: Model.Ref, content: (text|reasoning|tool)[], snapshot?:{start,end,files}, finish?, cost?, tokens?:{input,output,reasoning,cache:{read,write}}, error?, time:{created,completed?}}`.
- Compaction rendered back into context as a single user message: `<conversation-checkpoint>` … `<summary>{markdown}</summary>` … `<recent-context>{verbatim tail}</recent-context>` … `</conversation-checkpoint>`.
- Skill injection format (packages/core/src/tool/skill.ts): the `skill` tool returns `<skill_content name="X">` + `# Skill: X` + SKILL.md body + `Base directory for this skill: <dir>` + `<skill_files><file>…</file>…</skill_files>` + `</skill_content>`, with the file list sampled to `FILE_LIMIT = 10`.

Server auth = HTTP Basic `opencode:<password>`; renderer origin allowlist `['oc://renderer']`.

## Lessons for DeskMinis
- ADOPT — the two-loop shape. OpenCode's v2 runner is `while(pending queue) { while(needsContinuation) { one provider turn } }`, where `needsContinuation` is set by the arrival of any local tool call, NOT by a finish_reason check. This is more robust than branching on `stop_reason === 'tool_use'` because it works identically across Anthropic and OpenAI-compatible wire formats. DeskMinis's counted agent loop should treat the step counter as a safety valve, not the control flow.
- ADOPT — start tools eagerly, mid-stream. `runTurnAttempt` forks each tool into a FiberSet the instant the `tool-call` event lands, then awaits all of them after the stream closes. On a 3-tool turn this overlaps tool latency with the tail of token streaming. Wrap each in an uninterruptible mask so a cancel can't leave a half-executed side effect, and serialize the *persistence* of results behind a 1-permit mutex so DB ordering stays deterministic even though execution is parallel.
- ADOPT — the max-steps prompt trick over a silent stop. When the step budget is exhausted, opencode does not just stop: it sends one more turn with `tools: []`, `toolChoice: 'none'`, and an appended assistant message (max-steps.ts) demanding a text summary of work done + remaining tasks + recommendations. The user gets a useful wrap-up instead of a truncated transcript. Cheap to copy verbatim.
- ADOPT — three-channel tool output (`output` / `structured` / `content`). DeskMinis's shell and file tools should separate what the model sees from what the UI renders from what is persisted. opencode's bash tool is the template: model sees raw stdout + 'exited with code N'; DB stores only `{exit, truncated, timeout}`; UI can render either.
- ADOPT — bounded tool output with spill-to-disk. `MAX_LINES=2000`, `MAX_BYTES=50KB`, head+tail preview (half the line budget from each end), full artifact written to a managed dir with 7-day retention and `outputPaths` handed back. This is exactly the failure mode a shell tool hits first, and DeskMinis already has a `/var/minis` path contract to hang it on.
- ADOPT — stale-tool-call rejection. Registry entries carry an `identity` object; a tool call whose identity doesn't match what was advertised for that turn returns `Stale tool call: <name>` rather than executing. Matters the moment MCP servers (M2) can appear/disappear between turns.
- ADOPT — permission decline halts the loop. opencode checks the failure Cause for `DeclinedError`/`RejectedError` and interrupts the whole run instead of feeding 'permission denied' back as tool output. Feeding it back makes models retry the same forbidden action in a loop. Also adopt the three-outcome reply (allow / decline / CORRECT-with-feedback) — the correction path is more useful than a binary gate.
- ADOPT — permission as wildcard rules with `findLast` precedence, plus an explicit `save` field on the request naming the pattern to remember. `evaluate(action, resource, ...rulesets)` defaulting to `ask` gives you deny-by-default without hardcoding a tool list.
- ADOPT — HTTP-layer retry with jitter and Retry-After honoring, kept OUT of the agent loop. `MAX_RETRIES=2`, base 500ms, cap 10s, ±20% jitter, honoring `retry-after-ms` / `retry-after` (numeric seconds or HTTP-date), retryable on 429/503/504/529/5xx. Classify errors into a tagged union (auth / rate-limit / quota / content-policy / invalid-request-with-context-overflow / transport) — the loop then only needs to special-case context-overflow.
- ADOPT — the executor's two-pass secret redaction before anything is logged or persisted: (1) structural regex on sensitive header/query/body FIELD NAMES, (2) literal replacement of the actual secret VALUES the request sent, in case the provider echoes one back. DeskMinis persists provider errors to SQLite and ships them over the WebSocket to the renderer; this is where API keys leak.
- ADOPT — the compaction design, which is simpler than it looks: flatten history to plain text lines, keep the last ~8k tokens verbatim, summarize the rest into a FIXED Markdown template (Objective / Important Details / Work State{Completed,Active,Blocked} / Next Move / Relevant Files), re-inject as one `<conversation-checkpoint>` user message. Two triggers — proactive (estimated tokens > context − max(maxTokens, 20k buffer)) and reactive (provider returned context-overflow AND no assistant text has streamed yet). Rules worth copying: truncate tool results to 2000 chars before summarizing, refuse to recover a second overflow, and bail out if the summary prompt itself wouldn't fit.
- ADOPT (M3, this is the headline) — model LAN sync as SINGLE-WRITER EVENT-LOG SHIPPING, not record merge. opencode's `sync/README.md` states the rationale plainly: one writer means no vector clocks, no CRDTs, just a per-aggregate integer `seq`. The concrete pieces to copy: `event_sequence(aggregate_id, seq, owner_id)` + `event(id, aggregate_id, seq, type, data)`; a `/sync/history` endpoint whose REQUEST body is a `{aggregateID: lastKnownSeq}` map (so the client declares what it has and the server sends only the delta, full history for unknown aggregates); a `/sync/replay` that validates contiguity and owner; and a `/sync/steal` that transfers write ownership of one session. This maps onto DeskMinis's PortableRecord plan far better than diffing records — records become a projection, the log is the truth.
- ADOPT — replay idempotency + divergence detection. Re-replaying a stored seq is accepted only if `{id, versionedType, data}` deep-equal what's already there; otherwise it hard-fails with 'Replay diverged at aggregate X sequence N'. Without this, a flaky LAN link silently forks two desktops' histories.
- ADOPT — version-stamp event types on the wire (`versionedType(type, version)`). DeskMinis M3 will sync between desktops on different app versions; putting the schema version in the event `type` string (rather than a sibling field) means an old peer simply doesn't recognize the type instead of mis-decoding it.
- ADOPT — the Electron sidecar pattern, which is nearly identical to DeskMinis's minisd design and validates it. packages/desktop forks a `utilityProcess` (not a raw child_process), hands it `{hostname, port, password, userDataPath}`, waits for a `{type:'ready'}` message with a 60s stall timeout and a 6s stop timeout, and locks the renderer origin to a custom scheme. Two details DeskMinis should steal outright: force loopback into `NO_PROXY` (corporate proxy configs otherwise intercept localhost) and merge system CA certificates into Node's trust store (corporate TLS interception otherwise breaks every provider call). Both are one-liners that turn into unreproducible support tickets.
- ADAPT — a models.dev-backed catalog is the right call for M2's 'more providers', but opencode fetches it at RUNTIME (5-min TTL, 60-min refresh, cross-process file lock, compiled-in snapshot fallback, `OPENCODE_DISABLE_MODELS_FETCH` kill switch). For a desktop app that must work offline on first run, invert the priority: ship the snapshot, refresh in background, and keep the kill switch. The catalog buys you context/output limits and pricing for free — which is exactly what compaction and cost display need.
- ADAPT — the Protocol × Endpoint × Auth × Framing decomposition. DeskMinis already has Anthropic + OpenAI-compatible providers; before adding a third, factor the wire protocol (body builder + streaming state machine) apart from deployment (baseURL, auth scheme, headers). opencode's stated payoff is that DeepSeek/Together/Cerebras/Groq all reuse one OpenAI-chat protocol with zero new code. Note their streaming contract is a pure reducer — `step(state, providerEvent) -> [state, canonicalEvent[]]` — which is trivially unit-testable against recorded fixtures.
- ADAPT — record real provider streams as JSON fixtures. packages/llm/test/fixtures/recordings/ holds per-protocol captures (streams-text, streams-tool-call, drives-a-tool-loop, cache read/write, malformed-tool-order) plus an `http-recorder` package. For a desktop agent this is the only sane way to regression-test provider quirks without burning tokens in CI.
- ADAPT — normalize usage into inclusive totals PLUS a non-overlapping breakdown, and write down the invariant. opencode documents that Anthropic reports `input_tokens` as non-cached-only while OpenAI reports it inclusive, and that Anthropic does not separate thinking tokens out of `output_tokens`. Storing all fields independently (never a clamped subtraction) is what prevents the underflow bug class. DeskMinis will hit this the first time it shows a cost number.
- ADAPT — steer vs queue as two distinct delivery modes with a sequence cutoff. A prompt typed mid-run is 'steer' (injected into the current run, resets the step counter); a prompt typed after is 'queue' (drained when the run ends). Promotion only picks up inputs admitted before a recorded cutoff seq, which makes the race deterministic. This is a UX problem every desktop agent has and most get wrong.
- AVOID — do NOT build DeskMinis's loop on top of the AI SDK's `streamText` tool loop. opencode's own trajectory is the evidence: v1 delegated to `streamText` and is being replaced by a v2 that owns the turn boundary explicitly, and their design doc states 'OpenCode should migrate to generateTurn/streamTurn … It should not use the automatic run API for Session orchestration.' A durable agent must own persistence, permission prompts, tool settlement and continuation between turns — an SDK that hides the loop takes those seams away.
- AVOID — do NOT copy opencode's Effect-TS-everything style. `Context.Service` + `Layer` + `FiberSet` + `Effect.catchDefect` on a `TurnTransitionError` used as control flow is powerful but is a large conceptual tax on a Node service. Take the ALGORITHMS (eager tool fibers, coordinator, event commit transaction) and implement them with plain async/AbortController/Promise.allSettled.
- AVOID — do NOT copy the compaction-via-thrown-defect pattern (`Effect.die(new TurnTransitionError(...))` caught by `catchDefect` to restart the turn). Express 'recompact and retry this turn' as an explicit return value from the turn function. Same behavior, no exception-as-goto.
- AVOID — do NOT ship unbounded tool concurrency with no per-tool timeout. opencode has zero cap and zero per-tool timeout in the v2 runner; their own design doc lists 'bounded tool concurrency number' as an unresolved question and 'Bound provider retries and repeated identical tool calls' as an unchecked TODO in runner/llm.ts. DeskMinis should add a concurrency cap and per-tool timeout from day one — a model emitting 20 shell calls in one turn is a real failure mode.
- AVOID — do NOT let cloud 'share' bleed into the P2P design. opencode's share (packages/opencode/src/share/share-next.ts) is a hosted-API upload of denormalized session/message/part records and is completely separate from the /sync event-log path. Keep DeskMinis's M3 LAN sync on the event log; if a share/export feature is ever wanted, make it a projection of the log, not a second write path.
- NOTE — mDNS in opencode is only 47 lines and only advertises the HTTP server (`_http._tcp`, name `opencode-<port>`, host `opencode.local`, TXT `{path:'/'}`); there is NO peer discovery, no pairing, no auth handshake over mDNS. DeskMinis M3 gets no reference implementation here for the discovery+trust half — that has to be designed from scratch, and it is the harder half. Budget for it.
- NOTE — packages/llm/DESIGN.md is aspirational. If DeskMinis lifts ideas from it (StopWhen combinators, run-vs-turn split, tagged error unions, build-time model snapshot, staged hooks), treat them as a well-argued design proposal, not as battle-tested code. The genuinely shipped-and-proven parts are: Route/Protocol composition, the executor retry+redaction, the cache policy, the event-sourced store, and the v2 runner.

## Open questions
- Does the v2 runner enforce any provider-retry ceiling per SESSION? runner/llm.ts line ~55 lists '[ ] Bound provider retries and repeated identical tool calls' as unchecked, and the only retry is the 2-attempt HTTP one — so a model stuck emitting the same failing tool call appears unbounded. Worth confirming before copying the loop verbatim.
- Where are MCP tools registered in v2 core? Only `config/mcp.ts` (config parsing) exists there; the live MCP client is v1-only (packages/opencode/src/mcp/{index,catalog,auth,oauth-provider}.ts) and tools/builtins.ts explicitly says 'Dynamic MCP and plugin tools later use separate scoped canonical registrations'. The v2 MCP tool-registration path may not exist yet — relevant to DeskMinis M2 scheduling.
- Is the /sync SSE + replay path used for desktop-to-desktop over LAN, or only desktop-to-hosted-workspace? `syncWorkspaceLoop` early-returns when `target.type === 'local'` and resolves the peer through a `WorkspaceAdapterRuntime`, which suggests a cloud/remote workspace is the intended peer. I did not read the adapter to confirm whether a LAN peer is representable.
- How is the sidecar's Basic-auth password generated and delivered to the renderer? I read sidecar.ts (consumer) but not the generator in src/main/index.ts or initialization.ts — worth reading before mirroring the scheme for minisd's per-run bearer token.
- What exactly does `snapshots.capture()` / `snapshots.files({from,to})` do (git stash? content-addressed tree?) — the runner records a start/end snapshot per step and emits changed files in `Step.Ended`. This is the mechanism behind session revert and would be the reference for DeskMinis's M4 workspace file sync, but I did not read packages/core/src/snapshot.ts.
- Are `session_message` rows ever rewritten in place during streaming (per-delta UPDATE), or only appended at block end? message-updater.ts (16KB) and projector.ts (19KB) hold the answer; this determines write amplification for a long streaming turn on SQLite/WAL and is directly relevant to DeskMinis's persistence design.
