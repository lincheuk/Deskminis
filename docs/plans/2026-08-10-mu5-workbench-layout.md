## §2 决策点（逐条结论 + 理由）

### 2-1. 可拖的是哪一栏 → **对话列**

布局 B 里工作台承担弹性，因此**可拖边界移到对话列右缘**，`clampPaneWidth` 语义随之从「右栏宽度」变为「对话列宽度」，区间改 `[280, 520]`，默认 `336`。

理由：工作台装网页与截图，越宽越有用，不该由用户手动挤；对话列反而有明确的舒适阅读区间。

**连带两处必改（执行时极易漏）**：
1. `nextWidth` 现为 `clampPaneWidth(startW - (moveX - startX))`（drag.ts:14）——右栏在右侧，右拖变窄。边界移到对话列**右缘**后方向相反，须改为 `startW + (moveX - startX)`。**只改区间不改符号 = 拖拽反向**，且现有 6 例若只重锚数值不重锚方向，会放这个 bug 过去。
2. 见 2-6 的持久化键。

### 2-6. 存量 localStorage 值怎么办 → **换键名，不迁移**

`App.vue`:45 写、:86 读 `deskminis.rightW`，存的是右栏宽。语义换成「对话列宽」后，**存量值 360 落在新区间 `[280,520]` 内不会被 clamp 拦住**，会被静默当成对话列宽复原——用户看到的是一个自己从没设过的对话列宽度。

**处置：改键名为 `deskminis.chatW`**。旧键不读不删（无害残留，删它要额外代码且无收益）。新键缺省即取默认 336。这比写迁移逻辑简单，且避免「把一个语义不同的旧值算作用户偏好」。

### 2-2. 会话列表的两态 → **默认图标轨，可展开**

工作态默认 52px 纯图标（激活项左侧 2px 竖条）；点顶部按钮展开为 212px 完整列表（状态点 + 标题 + 右对齐相对时间）。展开态覆盖在对话列之上还是挤压对话列？→ **挤压**，避免浮层遮挡正在读的内容。

### 2-3. 四个旧标签怎么进工作台 → **进度并入任务条，其余进标签**

- `进度` 的核心信息（当前动作 / 步数 / 耗时 / 水位）升进**顶部任务条**常驻；剩余步骤清单挂在工作台底部。
- `产物` / `文件` 合并为**可多开的文件标签**（点产物卡 → 在工作台开一个该文件的标签）。
- `终端` 保持独立标签。
- 浏览器 / 屏幕两个标签**本轮只出壳与空态**，内容留给后端里程碑。

### 2-4. 「界面本体去彩」怎么落 → **只保留三处彩色**

状态点（绿/灰）、待批准（琥珀）、激活态强调（蓝）。其余一律走中性阶。现状里会话选中态标题用 `--action` 蓝，保留（属激活态）。

### 2-5. 字体切换范围 → **只改 `--font-ui`，等宽不动**

`--font-ui` 插入 `"Noto Sans SC"` 于 `Segoe UI Variable` 之后、`Microsoft YaHei` 之前（保留雅黑兜底）。`--font-mono` 维持 Cascadia。属 tokens.css **C 区**改动，不触 A 区，`tokens-mu3-appica` 例 2 不受影响。

## §3 命门处理

### 3-1. 命门 1：右栏契约反转打破 MU2b 已验收断言

`renderer-rightpane.test.ts` **6 例**与 `e2e:mu2b` 例 1 锚的是「右栏 360 默宽 / [320,480] 可拖 / 四 tab」。本轮全部失效。

**处置**：**重锚而非删除**——守卫价值是「分栏宽度受控且可拖」，换栏后该价值不变。改法：
- `lib/pane/drag.ts`：`clampPaneWidth` 区间改 `[280,520]`、默认 `336`；`nextWidth` 改 `startW + (moveX - startX)`（2-1）。测试同步重锚（**6 例，例数不变**），**其中必须有一例锚拖拽方向**，否则符号错会漏网；
- `e2e:mu2b` 例 1 断言改为「对话列默宽 336 / 拖拽 clamp 520 / 工作台标签≥3」——**计划内修正，单独申报**；
- 例 2-8 一字不动，必须继续绿。

### 3-2. 命门 2：去气泡会打到 ChatView 的既有源文本断言

MU2a/MU2b 立过若干 ChatView 渲染锚（字号令牌、事件条、工具行）。去气泡改的是容器与背景，不应动这些锚。

**处置**：执行前先跑一遍 ChatView 相关测试记录基线；改完逐条比对，**任何一条变红都必须先判明是「锚失效」还是「真回归」**，前者申报重锚，后者立即回退。不得为了让测试绿而改断言。

### 3-3. 命门 3：图标轨与 SessionList 现有断言

`renderer-sessioncard.test.ts` 锚 `var(--state-ok/-warn/-err)` 等状态色。图标轨是新增形态，**SessionList 展开态必须保留**，这些断言才继续成立。

**处置**：图标轨作为 SessionList 的**折叠视图**实现，不是替换组件。展开态 DOM 与断言锚保持。

## §11 真机目视逮到的两个缺陷（源码守卫与 e2e 全绿也看不见）

执行期 1048 例源码守卫全绿、`e2e:mu2a` 7/7、`e2e:mu2b` 8/8，但打开真机截图后逮到两个真缺陷。
两条都**只有看图才会发现**，记在这里作为「源码文本守卫能力边界」的实证。

**缺陷 1 · 输入卡 chip 逐字换行。** 对话列由弹性收成 336 定宽后，底部「＋ / 工作区 / 权限档 /
模型 / 发送」一排约需 244px，而可用宽只有约 194px，于是 chip 开始逐字换行——「工作区」竖成三行。
处置：禁止换行 + 在输入卡这一处收紧到 11px 字号与 8px 内边距（约省 54px），并加回归锚。

**缺陷 2 · Vue scoped CSS 类名撞车，收起工作台后右边一大片死白。**
`App.vue` 的对话列外壳与 `ChatView` 的根元素**同名 `.pane-c`**，而 Vue 的子组件根元素会
**同时带上父组件的 scope id**，于是 `App.vue` 的 `.pane-c { width: 336px }` 泄漏进 ChatView 根，
把它钉死在 336px。收起工作台时外壳铺满 1228px 而内容仍是 336px，右边 892px 全是白的。

MU2b 时这条规则只有 `flex: 1`，泄漏无害且不可见；MU5 给它加了 `width` 才让潜伏的撞车显形。
两层同宽时任何断言都分辨不出来——`main.pane-c` 量出来是对的，错的是内层。
处置：外壳改名 `.pane-chat` 根治，测试与 e2e 同步重锚。

**教训**：`.vue` 不在 `npm run typecheck`（`tsc --noEmit`）覆盖内，源码文本守卫又只能证明
「该出现的出现了」。这两层之外的东西——布局是否真的成立、字有没有挤成一坨——**只能靠看**。

## §12 多尺寸与拖拽极值走查（用户 2026-08-10 追加要求）

问题：拖动两边比例到一大一小、以及不同屏幕尺寸下，布局会不会错乱或不美观。

**先说结论：不会「错乱」，但会「把工作台饿死」。** 逐尺寸实测（应用 `minWidth: 900`）：
三区之和恒等于视口、无元素重叠、无页面横向滚动——布局结构是稳的。
但上限写死 520 不看视口，于是：

| 场景（900，即最小窗口） | 修复前工作台 | 后果 |
|---|---|---|
| 折叠 52 + 对话列拖到 520 | 328px | 标签条要横向滚动才够得到 |
| 展开 212 + 对话列拖到 520 | **168px** | 基本不可用 |
| 大屏拖宽后缩小窗口 | 一直 520 | **完全没有重钳逻辑** |

**处置（两条）**

1. **上限随可用宽收缩**：新增 `maxChatWidth(available) = clamp(available − WORKBENCH_MIN, PANE_MIN, PANE_MAX)`，
   `clampPaneWidth` / `nextWidth` 增可选 `available` 参数（省略即旧行为，既有调用点与测试一字不改）。
2. **可用宽变化即重钳**：`App.vue` 监听 `resize` 并 `watch(availableW)`——窗口缩放与**展开侧栏**
   （多吃 160px）都会触发，不只是 resize。

**`WORKBENCH_MIN = 360` 是量出来的，不是拍的。** 第一次按「标签宽合计 311 + 内边距 20 = 331」
估成 344，装上去仍然溢出——**漏算了标签之间的 5 个 3px gap**。真实构成 311 + 15 + 20 = 346，
取 360 留 14px 余量（兼容字体渲染差异与标签收起时多出的「＋N」恢复钮）。
这条本身就是「别凭算术推 UI 尺寸，去运行态量」的又一个实例。

**修复后复验**（900 / 1280 / 1920，折叠×展开 × 最窄×最宽 共 12 种组合）：
标签条、任务条、输入卡三处零溢出；页面零横向滚动；三区之和恒等于视口；
工作台下限守住 360。端到端最恶劣路径（1920 拖到 520 → 展开侧栏 → 缩到 900）
自动收敛为「对话列 328 / 工作台 360」，修复前是「520 / 168」。

npm test 1048 → **1052/1052**；`e2e:mu2a` 7/7、`e2e:mu2b` 8/8 复跑通过。
